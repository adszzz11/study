# Projects: 적용 실험

아래는 dossier의 활용 흐름에 기반한 제안이다. 실측 운영 성과가 제공된 사례는 아니다.

## 대학 프로젝트 배포 서버

- **목표:** Coolify를 활용해 프로젝트 앱을 배포한다.
- **최소 범위:** 앱 하나를 배포하고 외부 접속을 확인한다.
- **완료 기준:** 배포 상태, 실행 상태, 외부 접속 결과를 각각 기록한다.
- **검증 과제:** 실제 확보한 자원이 무료 범위 안에 있는지 확인한다. 수용 가능한 사용자 규모는 측정한다.

## 문의 자동 응답 실험

- **목표:** n8n으로 문의를 받아 응답하는 Workflow를 구성한다.
- **최소 범위:** 테스트 문의 한 건의 처리와 응답을 확인한다.
- **완료 기준:** 정상 처리와 실패 시 동작을 구분해 기록한다.
- **검증 과제:** 문의 증가 시 처리 성능과 외부 연동 조건·비용을 별도로 확인한다.

## 고객 관리 도구 운영 실험

- **목표:** Twenty로 테스트 고객 정보를 관리한다.
- **최소 범위:** 테스트 데이터 입력·조회와 앱 접근을 확인한다.
- **완료 기준:** 기능 동작과 서버 자원 사용을 함께 기록한다.
- **검증 과제:** 실제 고객 데이터 사용 전 접근 제어·데이터 보존·복구 방안을 검토한다. 해당 조건은 자료에 없다.

## 통합 실험의 진입 조건

- [ ] 각 앱을 개별 실행한 자원 사용 기록이 있다.
- [ ] 실패 시 관찰·복구 방법을 정했다.
- [ ] 동시 실행 전후 같은 부하 조건으로 비교한다.

세 프로젝트를 한 서버에 올리는 것은 후속 실험이다. 12GB·2코어라는 수치만으로 동시 운영 안정성을 전제할 수 없다.
