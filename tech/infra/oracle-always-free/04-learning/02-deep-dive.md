# Deep Dive: 자원과 운영 검증

## 12GB·2코어를 해석하는 방법

12GB는 메모리 규모, 2코어는 CPU 자원 규모를 설명한다. 해당 수치의 shape, CPU architecture, 전체 할당량과의 관계는 자료로 확인되지 않는다. 이를 성능 보장으로 변환하지 않는다.

| 관찰 축 | 확인할 내용 | 판단에 필요한 이유 |
|---|---|---|
| CPU·메모리 | 평시·순간 부하, 앱별 사용량 | 자원 경쟁과 한계 파악 |
| Database | 사용 여부, 데이터 크기 | 메모리·저장 공간 요구 파악 |
| Disk I/O | 읽기·쓰기 부하와 지연 | CPU 외 병목 확인 |
| Network | 응답 지연, 전송량 | 접근성과 트래픽 조건 확인 |
| 이미지 호환성 | CPU architecture 지원 | 실행 가능한 구성 확인 |

## 단계적 실험

1. 단일 앱에서 동일한 테스트 요청의 응답·오류·자원 사용을 기록한다.
2. 업무 도구 하나를 추가한 뒤 같은 조건에서 반복한다.
3. 요청량을 단계적으로 바꾸며 실패가 나타나는 조건을 기록한다.
4. 개별 실행 결과를 확보한 뒤 여러 도구의 통합 실험을 진행한다.

측정 간격·요청량·판정 기준은 자신의 목적에 맞게 먼저 정한다. 제공 자료에는 권장 처리량이나 안전한 동시 실행 개수가 없다.

## 외부 접속 실패 조사

- 앱 실행 상태와 로그를 확인한다.
- 내부 요청과 외부 요청의 결과를 분리해 기록한다.
- 실제 Network 경로, 포트 설정, 앱의 수신 설정과 TLS 상태를 확인한다.
- 변경 전후 결과를 비교해 원인을 좁힌다.

이는 조사 항목이며 영상의 실제 실패 원인을 뜻하지 않는다. 앱 실행 성공과 HTTP·HTTPS 외부 접근 성공을 독립적으로 판정한다.

## 운영 전 추가 검증

가동률, 장애 복구, 자원 회수 조건과 SLA는 별도 확인 대상이다. 실제 고객 데이터를 쓰기 전 접근 제어·보존·백업·복구 방법을 검토한다. 서버의 무료 조건은 연결된 외부 서비스 비용까지 보장하지 않는다.
