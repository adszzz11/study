# 시작하기: 단일 앱부터 검증

## 사전 기록

- [ ] 무료 조건과 영상 사양을 별도 항목으로 기록한다.
- [ ] 실제 환경에서 전체 무료 한도와 개별 서버 구성을 확인한다.
- [ ] CPU architecture와 사용할 이미지의 호환성을 확인한다.
- [ ] Storage·Network·초과 처리 조건을 확인한다.

자료에는 설치 명령이나 구체 설정값이 없다. 아래는 실행 순서에 대한 실습 제안이며 복사 실행용 설치 가이드가 아니다.

## 실습 순서

1. **Docker 실습:** 작은 앱 하나의 시작·종료·로그를 관찰한다. 사용 자원과 실패 시 증상을 기록한다.
2. **Coolify 배포:** 단일 앱의 배포 결과를 확인한다. 배포 완료와 앱 실행 상태를 분리한다.
3. **외부 접속:** 외부에서 요청해 결과를 기록한다. 80·443과 ports 항목은 점검 단서이며 원인 판정 근거 자체는 아니다.
4. **업무 도구 추가:** Twenty 또는 n8n 하나를 선택한다. 추가 전후 자원 사용과 응답을 비교한다.

## 완료 기록 양식

```text
확인 일시 / 환경:
무료 조건의 출처와 확인일:
개별 사양 / 계정 전체 한도:
앱 / 이미지 architecture:
배포 결과:
실행 상태와 로그:
외부 접속 위치 / 요청 결과:
CPU / 메모리 / Disk / Network 관찰:
문제 / 관찰 근거 / 다음 확인:
```

## 완료 기준

- [ ] 배포 상태, 실행 상태, 외부 접속 결과가 각각 기록되어 있다.
- [ ] 실패 원인은 증거가 있을 때만 결론 내린다.
- [ ] 비용과 가용성의 미확인 조건을 남긴다.
