# Projects: 검색 인프라 적용

> 이 노트는 제공된 dossier와 기존 지식에 기반한 초안이다. 제품 기능·구현·지원 범위는 **확인 필요**이며, 최신 버전·운영 상태·성능 수치를 주장하지 않는다.

## 1. 개인·팀 검색 Gateway

- **목표:** Private Instance에서 자주 쓰는 검색 소스를 통합한다.
- **작업:** 접근 제어, 엔진 선택, 최소 로그 정책, 장애 안내를 설계한다.
- **산출물:** 구성 근거, 질의 평가표, 데이터 흐름도, 운영 절차.
- **완료 기준:** 대표 질의에서 필요한 결과를 얻고, 일부 소스 실패에도 사용 가능한 응답을 제공하며, 민감한 질의 저장 경로를 설명한다.

## 2. AI Research Assistant의 검색 계층

구조화된 결과 연동이 가능한지 검증한 다음 파이프라인을 만든다.

```text
질문 → 검색 → URL 선별 → 원문 수집 → 근거 추출 → 답변
```

- **작업:** 출력 지원·활성화 조건·필드, 외부 엔진 자동화 이용 조건, 원문 수집 조건을 확인한다.
- **산출물:** 검색 결과와 원문 근거를 구분하는 응답 예시 및 실패 처리 기록.
- **완료 기준:** 답변의 핵심 주장에 원문 근거를 연결하고 검색·수집 실패를 드러낸다.
- **주의:** snippet은 원문 검증을 대체하지 않는다. 구조화 출력의 실제 지원 범위는 **확인 필요**다.

## 3. 검색 품질·운영 평가 도구

- **목표:** 엔진 추가가 품질을 개선하는지 지연·실패 부담만 늘리는지 판단한다.
- **작업:** 고정 질의 집합에서 엔진 조합을 비교한다. 개인화·시점·지역·언어를 기록한다.

| 지표 | 실험용 정의 |
|---|---|
| 유용한 상위 결과 비율 | 상위 k개 중 평가자가 유용하다고 판정한 결과 수 / 실제 평가한 결과 수 |
| 중복률 | 중복으로 판정한 결과 수 / 전체 결과 수 |
| 응답 시간 | 클라이언트에서 요청 시작부터 응답 완료까지 |
| 실패율 | 실패한 엔진 호출 수 / 시도한 엔진 호출 수 |

분모가 0이면 해당 지표는 N/A로 기록한다. k와 중복 판정 규칙을 고정한다. 이는 제안한 평가 지표이며 제품 내장 지표가 아니다.

**완료 기준:** 품질·지연·실패의 변화를 함께 제시하고 엔진 조합 선택을 데이터로 설명한다. 수치 목표는 실험 전에 사용 목적에 맞게 정한다.
