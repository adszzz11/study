# Overview: What / Why / 특징

> 이 노트는 제공된 dossier와 기존 지식에 기반한 초안이다. 제품 기능·구현·지원 범위는 **확인 필요**이며, 최신 버전·운영 상태·성능 수치를 주장하지 않는다.

## What

SearXNG는 자체 호스팅 가능한 오픈소스 Metasearch 시스템으로 알려져 있다. **확인 필요**. 검색용 웹 인덱스를 직접 구축하기보다 외부 검색 소스를 중계하고 결과를 통합하는 접근이다.

## Why

웹 수집·인덱스 유지에는 비용이 들고, 외부 서비스를 직접 쓰면 접근 경로와 결과 처리 통제가 제한된다. Metasearch는 검색 창구 통합과 운영 정책 통제를 제공하는 후보지만 외부 의존 자체를 제거하지 않는다.

## 개념적 처리 흐름

정확한 모듈 구성·호출 순서는 **확인 필요**다.

```text
사용자 / 애플리케이션
  → SearXNG Instance
    → 질의·검색 옵션 해석
    → Engine Adapter별 요청 생성 및 외부 요청
    → 응답 파싱·공통 형식 변환
    → 결과 통합·정렬
  → 검색 결과 응답
```

| 경계 | 설계상 의미 | 확인할 내용 |
|---|---|---|
| Engine Adapter | 서로 다른 요청·응답을 연결 | 지원 엔진, 파싱 방식, 외부 변경 대응 |
| 결과 통합 | 중복·누락 필드·순위 차이를 다룸 | 실제 중복 제거·가중치·정렬 알고리즘 |
| 외부 요청 | timeout과 실패가 품질에 영향 | 동시성·timeout·부분 실패 처리 |
| 운영 계층 | 질의와 접근 정책을 취급 | Proxy·앱 로그, 인증, Rate Limiting |

## Privacy와 신뢰

중계 계층은 외부 검색 엔진과 사용자 사이의 연결 경계를 바꿀 수 있다. 다만 외부 엔진에 전달되는 질의 자체에 개인정보가 포함될 수 있고, Instance 운영자와 Proxy·모니터링 시스템도 신뢰 주체가 된다. 기본 쿠키·헤더·로깅 정책과 익명성 보장은 **확인 필요**다.

## Public / Private Instance

- **Public:** 불특정 다수와 자동화 트래픽을 고려한 abuse 대응·용량 계획이 필요하다.
- **Private:** 사용자 범위를 제한하기 쉽지만 인증과 내부 접근 정책을 설계해야 한다.
- 관련 기능의 내장 여부를 가정하지 말고 애플리케이션과 외부 운영 계층의 책임을 확인한다.
