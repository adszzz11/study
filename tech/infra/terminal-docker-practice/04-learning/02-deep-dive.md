# 심화 학습: 배포·외부 접속·업무 운영

## 1. 배포로 확장

작은 앱이나 대학 프로젝트 하나를 대상으로 정한다. Coolify 작업과 터미널 작업을 별도로 기록하고, 두 도구의 연결은 실제 설정에서 확인한 범위만 설명한다.

| 기록 항목 | 남길 내용 |
|---|---|
| 터미널 작업 | 입력, 출력, 실행 결과 |
| Coolify 작업 | 배포 설정, 작업 결과 |
| 실제 연결 관계 | 확인한 설정과 근거 |
| 외부 접속 | 시도 위치, 주소, 시각, 관찰 결과 |

## 2. 외부 접속을 별도 검증

1. 앱 실행 결과를 기록한다.
2. 외부에서 웹앱 접근을 시도하고 결과를 따로 기록한다.
3. 실패하면 표시된 오류와 당시 설정을 보존한다.
4. 80·443과 가이드의 `ports` 항목을 점검 단서로 삼아 실제 구성과 대조한다.
5. 설정을 변경했다면 변경 내용과 변경 후 결과를 연결해 기록한다.

영상은 실패 원인을 명시하지 않는다. 따라서 80·443을 열면 해결된다는 절차나 `ports` 수정이 정답이라는 설명을 만들지 않는다. 실제 공개 범위와 필요한 설정은 선택한 앱의 공식 문서에서 확인한다.

## 3. Docker 개념 추가 학습

다음은 dossier에 설명이 없어 별도 근거가 필요한 학습 질문이다.

| 개념 | 직접 확인할 질문 |
|---|---|
| image / container | 실행 대상과 실행 상태는 어떻게 구분하는가? |
| volume | 앱 데이터가 어디에 남는지 어떻게 확인하는가? |
| network | 앱 통신과 외부 접근 구성을 어떻게 확인하는가? |
| Dockerfile | 선택한 앱의 빌드 정의를 어떻게 확인하는가? |
| Compose | 여러 서비스의 설정을 어떻게 표현하고 검증하는가? |

이 표는 자료에서 확인한 내부 아키텍처 설명이나 권장 설정이 아니다.

## 4. 업무 목적 하나 선택

- Twenty: 고객 관리 작업 하나의 입력과 결과를 검증한다.
- n8n: 문의 입력 → 처리 → 응답 결과를 가진 흐름 하나를 검증한다.

처음부터 모든 도구를 운영하지 않고 목적 하나를 정한다. 두 도구의 상호 연동과 동일 서버 설치는 전제하지 않는다.
