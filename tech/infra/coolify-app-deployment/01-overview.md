# Overview: What / Why / 특징

> **한 줄 정의**: Oracle Always Free 서버를 실행 환경으로 삼아 Coolify로 앱을 배포하는 활용 경로를 공부한다.

## What

제공 자료는 “밤새 켜 둘 서버”의 활용 예시로 앱·대학 프로젝트 배포를 소개한다. 서버 제공과 배포 도구는 서로 대체하는 관계가 아니다.

| 구성 요소 | 확인된 역할 | 미확인 사항 |
|---|---|---|
| Oracle Always Free | 앱과 도구를 위한 서버 자원 | 할당 조건, 가용성, 상세 과금 범위 |
| 터미널·Docker | 서버에서 Docker 실습 | Coolify 내부 연동, 앱별 container 구성 |
| Coolify | 앱·대학 프로젝트 배포 | 설치, build, 자동 배포, rollback |
| 접속 설정 | 웹앱 실패 화면, 80·443 및 `ports` 표시 | 실제 원인과 필요한 설정 전체 |
| Twenty·n8n | 고객 관리·문의 자동 응답 예시 | 동일 서버 운영 여부, Coolify 배포 여부 |

## Why

- **지속 실행 환경:** 개인 작업 시간과 관계없이 앱이나 자동화 도구를 운영한다.
- **개발 결과물 공개:** 개발 완료 후 다른 사람이 접근할 배포 환경이 필요하다.
- **외부 접근 확인:** 배포 작업 수행과 접속 성공은 별도의 완료 조건이다.

## 특징과 검증 관점

```text
서버 사용 가능 여부 → 앱 배포 결과 → 외부 접속 결과
```

위 흐름은 실습을 위한 검증 관점이며 Coolify 내부 아키텍처를 나타내지 않는다. 영상의 접속 실패가 어느 단계에서 발생했는지도 판정할 수 없다.

1. **포트는 단서다.** 80·443이나 `ports` 표시만으로 방화벽 원인을 확정하거나 HTTPS 완료를 주장할 수 없다.
2. **사양은 처리량이 아니다.** 메모리 12GB·코어 2개만으로 앱 수, 동시 사용자 수, 자동화 처리량을 계산할 수 없다.
3. **무료에는 범위가 있다.** 화면의 문서 발췌는 계정 유지 기간 동안 정해진 범위의 무료 자원을 설명한다. 전체 운영 비용이 항상 0이라는 의미는 아니다.
