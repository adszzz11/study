# Projects: 배포와 운영 적용

## 프로젝트 A. 대학 프로젝트 배포 및 시연

자료에 직접 등장하는 활용처를 실습한다.

- **목표:** 다른 사람이 접근해 작은 프로젝트를 확인할 수 있게 만든다.
- **작업:** 앱 선정 → 사용 버전의 공식 절차 확인 → 설정·배포 결과 기록 → 외부 접속 검증.
- **결과물:** 배포 대상과 revision, 설정 요약, 배포 결과, 외부 접속 결과.
- **완료 기준:** 배포 성공과 외부에서의 기대 응답을 각각 확인한다.
- **핵심 학습:** 개발 완료, 배포 완료, 접근 가능 상태의 차이.

## 프로젝트 B. 배포 후 접속 실패 진단 기록

영상 후반의 접속 문제에서 확장한 학습 과제다. 실제 실패가 발생했을 때 적용한다.

- **목표:** 추측에 의존하지 않고 문제 해결 과정을 재현 가능하게 만든다.
- **작업:** 증상 수집 → 배포·접속 상태 분리 → 80·443 및 `ports` 조사 → 변경·재검증 기록.
- **결과물:** 변경 전후 결과, 해결 여부, 원인 확정 근거 또는 남은 가설.
- **완료 기준:** 해결 여부와 판단 근거를 설명할 수 있다. 미해결이면 미해결로 표시한다.
- **핵심 학습:** 포트 정보를 단서로 활용하되 실제 원인은 검증으로 확정한다.

## 프로젝트 C. 앱과 업무 도구의 운영 구성 검토

앱 배포, Twenty 고객 관리, n8n 문의 자동 응답 사례를 바탕으로 한 **확장 제안**이다. 동일 서버에서 함께 운영되거나 모두 Coolify로 배포되었다는 사실은 확인되지 않았다.

- **목표:** 필요한 서비스와 각 서비스의 역할을 설계한다.
- **작업:** 서비스별 필요성 → 배포 경로 확인 계획 → 외부 접근 검증 계획 → 자원 관찰 계획 작성.
- **결과물:** 아래 운영 검토표.
- **완료 기준:** 각 서비스의 배포 경로·접속 검증·자원 관찰 계획과 미확인 조건을 작성한다.
- **핵심 학습:** 여러 활용 예시와 동시 운영 검증을 구별한다.

| 서비스 | 역할 | 배포 경로 확인 계획 | 접속 검증 계획 | 자원 관찰 계획 |
|---|---|---|---|---|
| 내 앱 | 프로젝트 공개 | 사용 버전의 Coolify 문서 확인 | 기대 화면·응답 확인 | 실제 부하 조건과 사용량 기록 |
| Twenty | 고객 관리 | 지원 환경·절차 추가 조사 | 사용할 기능의 접근 확인 계획 | 측정 항목·주기 설계 |
| n8n | 문의 자동 응답 | 지원 환경·절차 추가 조사 | 자동화 흐름의 검증 계획 | 작업 실행 시 사용량 관찰 계획 |
