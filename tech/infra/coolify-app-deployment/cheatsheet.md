# Cheatsheet: 배포·접속·자원 점검

## 역할 빠르게 구분

| 키워드 | 기억할 내용 |
|---|---|
| Oracle Always Free | 실행할 서버 자원의 맥락 |
| Coolify | 앱·대학 프로젝트 배포의 맥락 |
| Docker | 별도로 소개된 서버 실습 예시 |
| Twenty / n8n | 고객 관리 / 문의 자동 응답 활용 예시 |
| 80·443 / `ports` | 접속 실패를 조사할 단서, 원인 확정 아님 |
| 12GB / 코어 2개 | 영상 제시 사양, 할당·성능 보장 아님 |

## 실습 전

- [ ] 실제 제공 자원과 현재 무료 범위를 확인한다.
- [ ] 사용 버전과 공식 절차의 URL을 확보한다.
- [ ] 작은 앱과 기대 화면·응답을 정한다.

## 배포 후

- [ ] 서버 사용 가능 여부를 확인한다.
- [ ] 배포 결과와 관찰 근거를 기록한다.
- [ ] 외부 접속 결과를 따로 확인한다.
- [ ] 공개 기록에서 비밀번호·token·private key를 제외한다.

## 접속 실패 시

```text
증상 → 배포 상태 확인 → 접속 설정 조사 → 변경 기록 → 외부 재검증
```

- 80·443 개방만으로 해결을 보장하지 않는다.
- 특정 방화벽이나 HTTPS 상태를 증거 없이 단정하지 않는다.
- 변경 전후 결과와 해결 여부를 함께 남긴다.

## 운영 판단 전

- [ ] 제공 자원과 앱의 실제 사용량을 구분한다.
- [ ] 무료 범위와 전체 운영 비용을 구분한다.
- [ ] 여러 도구의 소개와 동일 서버 동시 운영 검증을 구분한다.
- [ ] 앱 수·동시 사용자 수·처리량은 별도 관찰 없이 추정하지 않는다.

이 자료에는 실행 가능한 설치 명령과 Coolify 조작 순서가 없다. 명령 대신 점검 기준을 제공한다.
