# 시작하기: 작은 앱 배포 기록

## 학습 목표

실행 환경과 배포 도구의 역할을 구분하고, 작은 앱 하나의 배포 결과와 외부 접속 결과를 각각 기록한다. 아래는 실습 계획이며 자료에 없는 Coolify 설치·조작 순서를 재구성한 것이 아니다.

## 1. 역할 구분

| 항목 | 우선 설명할 역할 | 실습에서 추가 확인 |
|---|---|---|
| Oracle Always Free | 서버 자원 | 실제 제공 자원과 무료 범위 |
| Docker | 서버 활용·학습 예시 | 실습 환경에서의 사용 여부와 구성 |
| Coolify | 앱 배포 | 사용 버전, 공식 절차와 설정 |

**결과물:** 확인된 역할과 미확인 연결 관계를 구분한 구성표.

## 2. 실습 대상 정하기

- 실행 여부를 쉽게 판별할 수 있는 작은 앱을 고른다.
- 배포할 revision과 예상 화면 또는 응답을 기록한다.
- 현재 정책과 사용 버전의 공식 문서를 확보한 뒤 실제 절차를 진행한다.
- 공개 vault에는 비밀번호, API key, SSH private key, 민감한 환경변수 값을 넣지 않는다.

## 3. 배포와 접근을 각각 확인

```text
실습 날짜:
앱 / revision:
서버에서 확인한 자원:
Coolify 버전 / 참조한 공식 문서 URL:
적용 설정(민감한 값 제외):
배포 결과 / 관찰 근거:
외부 접속 시각 / 접속 환경:
기대 화면·응답 / 실제 결과:
미확인 항목 / 다음 조치:
```

실패하면 배포 결과와 접속 결과를 한 항목으로 합치지 않고 각각 남긴다. 접속 실패 화면만으로 배포 자체가 실패했다고 단정하지 않는다.

## 완료 기준

- [ ] Oracle과 Coolify의 역할을 구분해 설명했다.
- [ ] 적용한 설정과 배포 결과를 기록했다.
- [ ] 외부 접속을 별도로 시도하고 결과를 기록했다.
- [ ] 실패 또는 미확인 항목에 후속 조치를 적었다.

배포 실습의 성공 기준은 기대한 앱 응답을 외부에서 확인하는 것이다. 실패 기록만으로 서비스 공개가 완료되었다고 표시하지 않는다.
