# 심화 학습: 접속 진단과 무료 자원 운영

## 1. 배포 상태와 외부 접근 분리

| 검증 질문 | 기록할 증거 | 피해야 할 결론 |
|---|---|---|
| 서버를 사용할 수 있는가? | 실제 자원과 관찰 시각 | 영상과 같은 자원이 항상 할당됨 |
| 앱 배포가 완료되었는가? | 배포 결과와 앱 상태의 관찰 근거 | 배포 작업 수행만으로 성공 확정 |
| 외부에서 접근 가능한가? | 접속 환경, 기대 응답, 실제 결과 | 배포 완료가 곧 외부 접속 성공 |

## 2. 접속 실패 진단

영상에 등장한 80·443과 `ports` 항목을 조사 단서로 사용한다. 구체적 설정값과 변경 결과가 없으므로 특정 포트 개방 명령이나 해결책을 이 자료에서 도출할 수는 없다.

1. 실패한 주소·시각·증상을 민감한 정보를 제외해 기록한다.
2. 앱 배포 상태와 확인 가능한 접속 설정을 수집한다.
3. 가설, 확인 항목, 실제 관찰을 나누어 적는다.
4. 문서로 확인한 설정을 변경했다면 변경 전후를 기록한다.
5. 외부에서 다시 접속하고 기대 결과와 비교한다.

```text
증상:
배포 상태의 관찰 근거:
가설 / 확인 항목(80·443, ports 등):
설정의 기존 값 / 변경 값(민감한 값 제외):
변경 근거 문서:
재검증 환경 / 시각 / 결과:
해결 여부 / 원인 확정 근거 / 남은 가설:
```

“80·443을 열면 반드시 해결”, “방화벽이 원인”, “HTTPS 완료”는 각각 별도 검증이 필요한 주장이다. 위 양식은 영상 장애의 실제 원인을 확정한 기록이 아니다.

## 3. 무료 범위와 실제 사용량

| 항목 | 영상 요약 | 내 환경에서 기록할 내용 |
|---|---|---|
| 자원 | 메모리 12GB·코어 2개 | 실제 할당 자원 |
| 무료 범위 | 계정 유지 기간 동안 정해진 범위 | 현재 정책, 적용 조건, 비용 항목 |
| 사용량 | 측정 자료 없음 | 앱별 메모리·CPU 관찰값과 측정 조건 |
| 운영 규모 | 검증 자료 없음 | 실제 부하에서의 관찰과 한계 |

무료 정책 확인과 부하 관찰을 분리한다. 사양만으로 처리량을 계산하거나 여러 도구의 동시 운영을 검증된 것으로 간주하지 않는다.

## 완료 기준

- [ ] 증상 → 확인 → 변경 → 재검증 기록을 작성했다.
- [ ] 해결 여부와 원인 확정 여부를 구분했다.
- [ ] 제공 자원·무료 범위·사용량·미확인 조건을 구분했다.
