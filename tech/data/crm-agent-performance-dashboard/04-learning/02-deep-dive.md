# 심화 학습: 집계·기여·근거 추적

## 지표 계약을 데이터와 함께 관리

지표마다 이름, 목적, 계산식, 데이터 원천, 시간대, 집계 단위, 중복 키, 실패 처리, 확정 시점, 버전을 기록한다. 실행 성공률과 업무 성공률은 별도의 분모를 쓴다.

```text
실행 완료율 = 완료 Run 수 / 종료된 Run 수
유효 응답률 = 유효 응답 고객 수 / 실제 접촉 고객 수
고객당 비용 = 해당 cohort에 배분한 실행 비용 / 접촉 고객 수
```

진행 중 실행은 첫 식에서 제외했다고 표시한다. 업무 지표는 접촉 cohort와 응답 관측 창을 고정해야 기간 간 비교가 가능하다. 모든 식은 설계 예시다.

## 활동량과 품질을 분리

| 가상 에이전트 | 접촉 고객 | 유효 응답 고객 | 유효 응답률 |
|---|---:|---:|---:|
| A | 100 | 10 | 10% |
| B | 20 | 6 | 30% |

A는 응답 절대량이 많고 B는 비율이 높다. 동일한 고객 난이도·관측 창인지 확인하지 않으면 우열을 단정할 수 없다. 처리 시간, 검토 시간, 비용도 나란히 보여주고 단일 점수가 숨기는 차이를 설명한다.

## 공동 기여와 조직도

- 팀 결과는 outcome_id로 한 번만 센다.
- 개인 기여는 별도 관계 테이블 `Contribution(outcome_id, agent_id, weight)`로 기록한다.
- 분할 배분을 택했다면 결과별 weight 합이 1인지 검증한다. 이는 설계 선택이며 실제 제품 규칙이 아니다.
- Lead Finder와 Outreach Agent에 각 0.5를 배분해도 팀 결과는 1건이다. 개인 관여 건수 2건을 팀 결과로 합산하지 않는다.
- 부서 이동은 소속 유효기간을 기록하고 ‘활동 시점 소속’ 또는 ‘현재 소속’ 중 집계 기준을 명시한다.

조직도의 소속 관계와 작업의 기여 관계를 분리한다. 조직도만으로 권한·승인 체계를 추정하지 않는다.

## 근거 조회와 검산

```text
대시보드 수치 → 포함된 고유 고객·결과 목록
             → Activity → Run → Agent
             → 원본 발송·응답 이벤트 또는 산출물
```

| 점검 사례 | 기대 동작 |
|---|---|
| 같은 이벤트 두 번 수집 | 활동·집계값 불변 |
| 같은 고객 여러 번 접촉 | 발송 건수 증가, 고유 고객 수 불변 |
| 실패 후 재시도 성공 | 실패 이력 보존, 성공 발송만 활동 집계 |
| 늦은 응답 | 정해진 응답 창으로 포함 여부 결정 |
| 공동 결과 | 팀은 한 번, 개인은 배분 규칙 적용 |
| 연결되지 않은 ID | 임의 귀속하지 않고 검토 대상으로 분리 |

Knowledge Graph의 노드·관계에는 출처 ID와 생성 시점을 기록한다. 그래프에 선이 있다는 사실 자체가 인과관계나 CRM 동기화의 증거는 아니다.
