# Projects: 검산 가능한 운영 화면 만들기

아래 프로젝트는 합성 데이터를 사용하는 설계 실습이다. Orbit Agents의 실제 API나 실행 기능을 전제로 하지 않는다.

## 프로젝트 1: Lead-to-Outreach CRM 대시보드

- **목표:** 고객 발굴 → 접촉 → 응답 흐름을 표현한다.
- **작업:** 고객별 Activity와 에이전트별 Run을 ID로 연결하고 생성 메시지·발송·접촉 고객·응답 고객 수를 따로 표시한다.
- **산출물:** 가상 데이터, 지표 계약, 고객별 이력 화면, 집계값에서 원본 목록으로 이동하는 화면.
- **완료 기준:** 화면 수치를 원본으로 재계산할 수 있고, 재시도·중복 이벤트가 고유 고객 수를 늘리지 않는다.

## 프로젝트 2: 에이전트 성과 평가 모델

- **목표:** 활동량·품질·운영 부담을 함께 비교한다.
- **작업:** 실행 성공과 업무 성공을 구분하고 팀 성과와 개인 기여를 분리한다. 동일 데이터에서 기간·분모·응답 창을 바꾸어 결과 차이를 확인한다.
- **산출물:** 지표 정의표, 비교표, 공동 기여 배분표, 민감도 분석 메모.
- **완료 기준:** 모든 평가값의 계산식과 근거를 설명하고 단일 점수의 한계를 제시할 수 있다.

## 프로젝트 3: Knowledge Graph와 CRM의 근거 연결

- **목표:** 고객·파일·출력물·활동을 출처와 함께 탐색한다.
- **작업:** 노드·관계에 원본 ID를 기록하고 `discovered`, `generated`, `contacted`의 의미를 정의한다. 조직 소속과 작업 기여 관계를 구별한다.
- **산출물:** 관계 사전, 합성 그래프 데이터, 원본 조회 화면.
- **완료 기준:** 모든 연결의 근거를 확인할 수 있고, 근거 없는 연결과 소속·기여 혼동을 탐지할 수 있다.

## 공통 리뷰

- [ ] 데이터와 화면의 수치가 일치한다.
- [ ] 미완료 관측 창과 0인 분모를 명시한다.
- [ ] 중복·실패·공동 기여 사례를 검산했다.
- [ ] 제품의 확인된 사실과 실습의 설계 결정을 구분했다.
