# 심화 학습: 접속·통합·운영 검증

## 서버 실행과 웹앱 접근

서버가 실행 중이어도 사용자가 웹앱에 접근할 수 있다는 뜻은 아니다. 영상 마지막의 접속 실패 화면과 80·443 및 ports 설정을 접속 계층 학습의 출발점으로 삼는다. 구체적인 설정값이나 장애 원인은 자료로 확정할 수 없다.

| 점검 계층 | 확인할 증거 |
|---|---|
| 서버 | 실행 상태와 자원 상태 |
| 애플리케이션 | 실행 로그, 응답 상태 |
| 네트워크·포트 | 실제 listener, port mapping, 허용 규칙 |
| 도메인·TLS | 이름 해석, 인증서와 요청 결과 |

한 번에 한 조건을 바꾸고 시각·증상·변경·결과를 기록한다. 80·443 표시만으로 방화벽 문제라고 결론 내리지 않는다.

## Twenty와 n8n 통합 후보 검증

1. 문의 입력과 필요한 고객 정보 출력을 정의한다.
2. 고객 식별 기준과 중복·누락 처리 방식을 정한다.
3. API 또는 connector의 존재·지원 범위·인증 방식을 공식 자료에서 확인한다.
4. 연결 수단이 확인되면 가상 데이터로 오연결·누락·실패를 시험한다.

직접 연동은 영상에서 확인되지 않았다. 연결 수단이 없다면 가능성 검토서로 결과를 남긴다.

## 운영 준비

- 도구별 메모리·CPU 사용량과 응답 상태를 유휴·작업 중에 측정한다.
- 영상의 12GB·2코어를 권장 사양이나 동시 운영 보장으로 사용하지 않는다.
- 열람·수정 권한을 시험하고 백업의 실제 복원 결과를 확인한다.
- 재시작·업데이트·장애 이후 데이터와 업무 상태를 확인한다.

권한·복구 검증 전에는 실제 고객 데이터 운영 준비가 끝났다고 판단하지 않는다.
