# 시작하기: 최소 문의 자동 응답

## 목표와 전제

제한된 문의 하나에 의도한 응답이 전달되는지 확인한다. 다음은 dossier 기반 학습 제안이며 영상의 설치·구현 절차가 아니다. 입력 채널과 n8n 설정은 별도 공식 문서에서 확인해야 한다.

## 1. 입력과 성공 기준 정하기

실제 고객 정보 대신 가상 데이터를 쓴다.

```text
문의 유형: 운영 시간 안내
입력 예시: "운영 시간이 궁금합니다"
예상 응답: "운영 시간은 평일 09:00~18:00입니다."
성공 기준: 선택한 테스트 채널에서 예상 응답을 확인
범위 밖 입력: 자동 답변 대신 검토 대상으로 기록
```

문구와 운영 시간은 실습용 예시다.

## 2. 흐름을 네 부분으로 설명하기

| 단계 | 정할 내용 | 남길 기록 |
|---|---|---|
| 입력 | 어떤 채널로 받는가 | 샘플 문의 |
| 실행 | 어떤 Trigger인가 | 시작 조건 |
| 결정 | 고정 문구·조건 분기 중 무엇인가 | 규칙과 예상 출력 |
| 전달 | 어디에 답하는가 | 전달 결과 |

처음에는 AI나 CRM 연동을 전제하지 않는다. n8n의 현재 공식 문서를 확인하고 선택한 채널의 입력·전달 방법을 정한 뒤 구현한다.

## 3. 최소 검증

- [ ] 정상 문의가 의도한 응답으로 이어진다.
- [ ] 범위 밖 문의를 정상 처리로 오인하지 않는다.
- [ ] 실행 기록과 수신 측 결과를 각각 확인한다.
- [ ] 웹앱 접속 여부와 Workflow 실행 여부를 따로 기록한다.

실패하면 `입력 수신 → 실행 시작 → 응답 결정 → 전달` 중 마지막으로 성공한 지점을 찾는다. 접속 실패만으로 Workflow 오류라고 결론내리지 않는다.
