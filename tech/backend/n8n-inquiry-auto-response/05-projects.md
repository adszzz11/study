# Projects: 적용 실습

아래는 자료에서 도출한 프로젝트 제안이다. 영상에서 완성된 사례가 아니다.

| 순서 | 프로젝트 | 구현 범위 | 완료 기준 |
|---|---|---|---|
| 1 | 최소 문의 자동 응답 | 제한된 문의 유형 하나 | 정해진 입력에 예상 응답이 전달됨 |
| 2 | 상시 운영 검증 | 선택한 서버에서 흐름 운영 | 정한 관찰 구간에 작업자 조작 없이 실행됨 |
| 3 | 배포·접속 점검 | 앱 접속과 실제 ports 설정 조사 | 접속 문제와 자동화 문제를 증거로 구분함 |
| 4 | 고객 관리 연계 검토 | Twenty 연계 필요성 분석 | 필요한 정보·연결 가능 여부·미확인 사항 기록 |

## 권장 첫 프로젝트

운영 시간 문의처럼 입력과 출력이 명확한 유형을 고른다. 정상 입력, 범위 밖 입력, 전달 실패를 구분해 기록하면 기능 문제와 운영 문제를 분리하기 쉽다.

## 결과 기록 양식

```text
목표 / 처리 범위:
선택한 입력 채널 / Trigger / 전달 채널:
예상 응답 / 실제 응답:
실행 시간 / 전달 확인:
관찰 기간 / 작업자 개입:
실패 지점 / 증거 / 다음 확인:
확인된 도구 연결 / 미확인 연결:
```

고객 관리 연계는 첫 실습의 필수 조건이 아니다. 자료에 Twenty와 n8n의 연동 절차가 없으므로 구현 전에 정보 요구와 연결 가능성을 검증한다.
