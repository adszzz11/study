# Overview: What / Why / 특징

## What

n8n을 통한 문의 자동 응답은 수집 영상에서 상시 가동 서버의 활용 예시로 나온다. 응답 문구뿐 아니라 흐름을 지속해서 실행할 운영 환경이 학습 범위에 포함된다.

## Why

반복 문의의 초기 응대와 담당자 개입을 줄이는 것이 자동화의 기대 목적이다. 이는 분석이며, 자료에 성과 수치나 실제 운영 기록은 없다. 영상의 서버 사양인 메모리 12GB·코어 2개도 당시 소개 내용으로만 기록한다. 현재의 보편적 제공 조건이나 지속 확보 가능성을 의미하지 않는다.

## 확인된 구성과 미확인 연결

| 구성 | 확인된 역할 | 확인되지 않은 내용 |
|---|---|---|
| Oracle Always Free | 상시 서버 선택지 | 실제 환경·가용성·비용 내역 |
| Docker | 터미널 실습 | n8n의 Container 실행 여부 |
| Coolify | 앱·대학 프로젝트 배포 | n8n 배포·관리 여부 |
| Twenty | 고객 관리 | n8n과 데이터 교환 여부 |
| n8n | 문의 자동 응답 | 입력·처리 단계·전달 방식 |
| 80·443, ports | 접속 설정 단서 | 실패 원인·해결 결과 |

화면의 문서 발췌는 Always Free 자원이 계정 유지 기간 동안 정해진 범위에서 무료라고 설명한다. 자원 배정 조건과 실제 청구 내역은 제시되지 않았다.

## 분석용 최소 구조

```text
문의 발생 → 자동화 흐름 실행 → 응답 결정 → 응답 전달
```

위 구조는 학습용 기능 분해이며 영상의 상세 Workflow가 아니다.

- 문의 발생: 입력 채널은 무엇인가?
- 흐름 실행: 어떤 Trigger가 실행을 시작하는가?
- 응답 결정: 고정 문구인가, 조건 분기인가, 다른 처리인가?
- 응답 전달: 어느 채널로 전달하며 성공을 어떻게 확인하는가?

AI chatbot·LLM·RAG로 분류할 근거는 없다. 또한 같은 영상에 등장한다는 사실로 `Twenty → n8n` 또는 `Coolify → n8n 배포`를 아키텍처에 추가하지 않는다.

## 운영 관점

자동화가 실행돼도 필요한 접속 경로가 동작하지 않으면 활용이 어렵다. 그러나 영상 후반의 웹앱 접속 실패가 문의 자동 응답에 직접 영향을 주었는지는 미확인이다. 80·443 표시만으로 방화벽이나 앱 설정을 원인으로 단정하지 않는다.
