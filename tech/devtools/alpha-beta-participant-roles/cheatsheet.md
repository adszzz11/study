# Cheatsheet: 참여자와 QA 결과 구분

## 핵심 구분

| 질문 | 기록할 내용 |
|---|---|
| 누가 참여했는가? | Alpha: 내부 참여자 / Beta: 실제 사용자 |
| 무엇을 확인했는가? | 핵심 기능·기존 기능·응답 속도 등 실제 목적 |
| 어떤 관점인가? | 소속·실제 사용 경험을 별도 기록하는 방법 고려 |
| 무엇을 관찰했는가? | 수행 내용·조건·관찰 결과 |
| 기준을 충족했는가? | 명시된 기준과 결과의 대응 근거 |

소속·사용 경험의 별도 기록은 설계 제안이다. 자료는 집단 중복 여부를 정하지 않는다.

## 피해야 할 추론

- 내부 참여자가 확인함 → 모든 QA 범위 완료: 근거 부족.
- 실제 사용자 참여 → acceptance 기준 충족: 근거 부족.
- Alpha 완료 → Beta 진행 → 출시 승인: 자료에서 순서·승인 조건 미확인.
- 한 집단에서 더 많은 결함 발견 → 항상 우수한 집단: 일반화 불가.

## 최소 기록 템플릿 — 적용 제안

```text
참여자 구분 / 소속 / 사용 경험:
검증 목적 / 대상 빌드:
수행 내용 / 조건:
관찰 결과:
판단 기준 / 근거 / 미확인 사항:
```

## 빠른 점검

- [ ] 참여자와 검증 목적을 따로 썼는가?
- [ ] 결과를 추적할 수행 조건과 근거가 있는가?
- [ ] 자료에 없는 모집·환경·완료 기준을 확정하지 않았는가?
- [ ] 참여 사실과 출시 준비 판단을 구분했는가?
- [ ] 원본 URL이 없다는 근거 한계를 표시했는가?
