# 심화: 경계 사례와 출시 판단

## 실습 범위

다음은 제공 자료를 이해하기 위한 **추가 설계 실습**이다. 자료가 제시하지 않은 운영 규칙을 정답처럼 확정하지 않는다.

## 1. 내부 직원이 실제 사용자인 경우

내부 직원이 일상적으로 제품을 사용한다는 상황을 가정한다. 자료는 두 집단의 중복 여부를 설명하지 않는다.

- 소속과 사용 경험을 각각 기록한다.
- 이 실습의 운영 기준을 정하고 이유를 남긴다.
- 예: 소속은 내부, 사용 경험은 실제 사용으로 기록하고 두 관점을 함께 표시한다. 이는 영상의 규칙이 아니다.
- 중복 참여자를 집단 비교에 포함한다면 집계 방식과 중복 여부도 명시한다.

## 2. 발견 사항의 차이 해석

| 비교할 항목 | 기록 이유 |
|---|---|
| 대상 기능·빌드 | 서로 같은 대상을 보았는지 확인 |
| 수행 과제·환경 | 조건 차이에서 나온 발견인지 검토 |
| 소속·사용 경험 | 관점의 차이를 해석할 맥락 확보 |
| 관찰 내용·근거 | 집단 이름만으로 결론 내리는 것 방지 |

한 번의 관찰에서 내부 참여자가 더 많은 버그를 찾았더라도 집단의 일반적 우수성을 증명하지 않는다. 조건 차이와 참여자 관점의 영향을 분리할 수 없다면 해석 한계로 남긴다.

## 3. 참여 사실과 acceptance 판단 분리

```text
참여 사실: 실제 사용자가 기능을 확인했다.
관찰 결과: [수행 내용과 관찰 근거]
고객·기획 기준: [명시된 기준 또는 미확인]
충족 판단: [충족 / 미충족 / 판단 보류]
판단 근거: [기준과 연결되는 결과]
미확인 항목: [추가 확인 필요 사항]
```

Beta 참여는 첫 줄의 근거가 될 수 있지만 나머지 줄을 자동으로 채우지는 않는다. 자료만으로 Alpha→Beta 순서나 완료 후 출시 승인을 도출할 수도 없다.

## 완료 체크

- [ ] 집단 경계의 운영 기준과 자료의 정의를 구분했다.
- [ ] 관찰 차이를 참여자 우열로 일반화하지 않았다.
- [ ] 기준이 없으면 출시 준비 판단을 보류했다.
