# 시작하기: 참여자와 검증 목적 분리

## 목표와 준비

이 절차는 **학습용 제안**이다. 작은 기능 하나(예: 검색)를 고르고 설명 문장에서 참여 주체, 검증 목적, 수행 내용, 결과를 분리한다. 특정 도구 설치나 자동화 Framework는 필요하지 않다.

## 1. 분류 축 표시

| 연습 문장 | 표시할 정보 | 문장만으로 알 수 없는 정보 |
|---|---|---|
| 내부 참여자가 점검한다 | 참여 주체 | 무엇을 확인했는가 |
| 새 빌드의 핵심 기능을 빠르게 확인한다 | 검증 대상·방식 | 누가 참여했는가 |
| 실제 사용자가 참여했다 | 참여 주체 | 결과·기준 충족 여부 |

## 2. 기록 양식 채우기

아래는 복사해서 사용하는 제안 양식이다. 모르는 값은 미확인으로 남긴다.

```text
대상 기능 / 빌드:
참여자 구분: 내부 참여자 / 실제 사용자 / 경계 사례
소속:
실제 사용 경험:
검증 목적:
수행 내용:
수행 조건:
관찰 결과:
판단 기준과 근거:
미확인 항목:
```

## 3. 예시 검토

**가상 실습 데이터:** 실제 사용자 한 명이 검색을 수행했고, 결과 표시까지 2초를 관찰했다. 환경과 측정 방법은 미기록이다.

- 참여자: 실제 사용자.
- 검증 목적: 응답 속도 확인.
- 관찰 결과: 2초. 이 수치는 권장 성능 기준이 아니다.
- 판단: 기준과 측정 조건이 없으므로 성능 통과 또는 출시 가능으로 결론 내릴 수 없다.

## 완료 체크

- [ ] Alpha/Beta 명칭 없이도 누가 무엇을 했는지 설명할 수 있다.
- [ ] 관찰 사실과 통과 판단을 구분했다.
- [ ] 부족한 기준·조건을 미확인으로 남겼다.
