# 심화 학습 — 효과의 역할과 AI 결과 검토

## 1. 정적인 구성과 동적인 효과 분리

이 절차는 학습 제안이다. `Paper Crumple` 또는 3D 큐브 그리드를 대상으로 효과가 있는 prototype과 없는 prototype을 비교한다. 실제 설치법·API는 제공되지 않았으므로 실행 코드를 추정하지 않는다.

가능하면 콘텐츠·레이아웃·화면 크기는 같게 두고 효과만 바꾼다. 효과를 제거해도 목적이 전달되는지, 효과가 어떤 추가 역할을 하는지 기록한다.

| 검토 항목 | 효과 없음 | 효과 있음 | 판단 근거 |
|---|---|---|---|
| 정보 위계와 가독성 | 관찰 | 관찰 | 가림·강조 변화 |
| 핵심 입력·탐색 | 관찰 | 관찰 | 클릭·터치 방해 여부 |
| 시각적 매력 | 관찰 | 관찰 | 표현하고 싶은 분위기와의 관계 |
| 성능 | 환경·측정값 | 환경·측정값 | 실제 적용 환경에서 확인 |

키보드 조작·작은 화면·reduced motion도 실제 구현에서 점검할 수 있다. 이는 추가 실무 제안이며 해당 컴포넌트가 지원한다고 확인된 기능은 아니다.

## 2. Copy prompt 읽기와 brief 보완

메뉴에 Claude Code·Codex·ChatGPT가 보인다는 사실만 확인되었다. prompt 내용이나 자동 실행 여부는 알 수 없다. 실제 복사한 내용을 읽은 후 중복·충돌을 정리한다.

```text
[AI 전달용 디자인 brief — 실습 템플릿]
제품 목적과 핵심 사용자 행동:
레퍼런스에서 참고할 요소와 선택 이유:
적용 위치와 범위:
실제 콘텐츠와 배치 요구:
원하는 동작과 효과를 끌 조건:
현재 프로젝트의 기술 환경과 제약:
복사한 prompt에 이미 들어 있는 정보:
추가하거나 수정할 요구:
검토 기준: 정보 위계 / 가독성 / 입력 방해 / 성능
확인되지 않은 API·의존성은 추정하지 말고 확인 필요로 표시한다.
```

## 3. 시각적 유사성과 제품 적합성 분리

- **유사성:** 원본의 형태·색·동작을 어느 정도 재현했는가?
- **적합성:** 실제 콘텐츠를 읽고 핵심 행동을 수행하는 데 도움이 되는가?

원본을 닮았어도 콘텐츠를 가리거나 사용 흐름을 방해하면 수정 또는 제거를 검토한다. 결과를 유지·수정·제거로 나누고 근거를 적는다. 실험만으로 일반적인 판단력 향상이나 도구 간 우열을 입증했다고 보지 않는다.
