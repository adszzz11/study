# Projects — 판단 근거를 산출물로 남기기

아래 프로젝트는 dossier를 바탕으로 구성한 적용 제안이다. 특정 서비스에서 확인된 workflow나 교육 과정은 아니다.

## 1. UI 레퍼런스 비교 노트

- **목적:** 시각적 선호를 설명 가능한 판단 기준으로 바꾼다.
- **작업:** 화면 세 개를 정보 위계·여백·타이포그래피·색상 기준으로 비교하고 제품 화면에 적용할 요소를 선택한다.
- **산출물:** 동일 기준 비교표, 선택·제외 이유, 적용 위치.
- **완료 기준:** 각 선택을 정보 전달이나 사용자 행동과 연결해 설명한다. 화면에서 알 수 없는 user flow는 미확인으로 표시한다.
- **시작점:** [[tech/devtools/ui-design-reference-exploration/04-learning/01-getting-started|화면 비교 실습]]

## 2. 인터랙티브 컴포넌트 적용 실험

- **목적:** 개별 효과가 전체 UI에 주는 영향을 확인한다.
- **작업:** `Paper Crumple` 또는 3D 큐브 그리드의 효과 유무 두 prototype을 비교한다. 실제 구현 전 설치·지원 환경·라이선스를 별도 확인한다.
- **산출물:** 두 prototype, 적용 환경 기록, 비교표, 유지·수정·제거 판단.
- **완료 기준:** 시각적 매력과 화면 안에서의 역할을 각각 설명한다. 가독성·입력 방해·성능을 적용 환경에서 확인한다.
- **시작점:** [[tech/devtools/ui-design-reference-exploration/04-learning/02-deep-dive|효과 유무 비교]]

## 3. AI 도구 전달용 디자인 brief

- **목적:** 레퍼런스 선택과 구현 요청 사이의 모호함을 줄인다.
- **작업:** 실제 `Copy prompt` 내용을 읽은 뒤 목적·적용 위치·원하는 동작·검토 기준을 보완한다.
- **산출물:** 원래 prompt, 보완한 brief, 생성 결과와 요구의 차이 기록. 실제 prompt를 확보하지 못하면 자체 brief 연습으로 표시한다.
- **완료 기준:** AI 결과에서 유지할 부분과 수정할 부분을 구체적으로 지적한다. 어떤 AI 도구가 더 낫다는 일반화는 하지 않는다.

## 공통 결과 기록

| 판단 | 관찰 근거 | 다음 작업 |
|---|---|---|
| 유지 | 목적에 도움이 된 부분 | 다른 콘텐츠에서도 확인 |
| 수정 | 요구와 달라진 부분 | brief 또는 구현 보완 |
| 제거 | 목적을 방해한 부분 | 효과 없는 버전 재검토 |
