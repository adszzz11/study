# Overview — 무엇을 보고 왜 비교하는가

## What

UI 디자인 레퍼런스 탐색은 화면·효과를 관찰해 목적에 맞는 요소를 선택하고 구현 요청으로 연결하는 과정이다. 특정 단일 제품의 사용법이 아니라 여러 탐색 대상을 묶은 tool-study다.

## Why

자료는 AI를 잘 활용하지만 미적 판단이 부족한 신입 디자이너에 관한 질문에서 출발한다. 도구를 다루는 능력만으로 제품에 적절한 시각적 결과를 고르는 능력을 설명할 수는 없다.

| 역량 | 핵심 질문 | 실습에서 남길 근거 |
|---|---|---|
| 생성·구현 | 원하는 UI를 어떻게 만들 것인가? | prompt, 구현 결과, 수정 내역 |
| 선택·평가 | 이 결과가 목적에 왜 적절한가? | 비교 기준, 선택·제외 이유 |

레퍼런스 열람 자체의 학습 효과는 자료에서 검증되지 않았다. 관찰을 언어화하는 방법은 이 노트의 학습 제안이다.

## 특징과 작업 흐름

| 계층 | 확인된 구성 | 관찰 역할 | 미확인 사항 |
|---|---|---|---|
| 갤러리 | 앱·인터페이스 썸네일 모음 | 다양한 시각적 방향 비교 | 검색·필터·정렬·저장 |
| 모바일 화면 | 모바일 앱 화면 목록 | 화면 단위 구성 관찰 | navigation, 실제 user flow |
| 효과 미리보기 | React Bits `Paper Crumple` | 개별 효과 검토 | 코드·설정·성능 |
| 컴포넌트 설명 | 3D 큐브 그리드 설명 | 형태와 동작 이해 | 소속 라이브러리·의존성·지원 환경 |
| AI 전달 | Claude Code·Codex·ChatGPT 대상 `Copy prompt` | 구현 요청의 접점 | prompt 본문·전달 범위·실행 결과 |

이는 software architecture가 아니라 관찰된 작업 흐름이다. 3D 큐브 그리드의 React Bits 소속 여부는 확인되지 않았다.

## 관찰 단위를 분리하기

- **화면 수준:** 어떤 정보를 먼저 보게 하는가? 정보 위계·여백·타이포그래피·색상을 비교한다.
- **컴포넌트 수준:** 효과가 화면에서 어떤 역할을 맡는가? 효과를 제거해도 목적이 전달되는지 살핀다.

위 질문은 분석 방법의 제안이며 사이트의 제공 기능이 아니다. `Copy prompt` 메뉴의 존재도 도구별 최적화·동일 결과·자동 설치·품질을 보장하지 않는다.
