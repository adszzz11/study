# Ecosystem — 탐색 방식과 구현 접점 비교

## 비교 범위

자료만으로 시장 경쟁 구도나 서비스별 우열을 판단할 수 없다. 아래는 영상에 등장한 대상의 역할 비교다.

| 대상·방식 | 확인된 내용 | 적합한 탐색 목적 | 자료의 한계 |
|---|---|---|---|
| 앱·인터페이스 썸네일 갤러리 | 여러 썸네일이 모인 화면 | 시각적 방향을 넓게 비교 | 서비스명·URL 미제공 |
| 모바일 앱 화면 레퍼런스 | 모바일 화면 나열 | 화면 구성의 차이 관찰 | 사용 맥락·화면 연결 관계 불명 |
| React Bits `Paper Crumple` | 효과 미리보기 | 특정 시각 효과 검토 | 설치법·API·라이선스 미제공 |
| 3D 큐브 그리드 페이지 | 설명과 `Copy prompt` 메뉴 | 컴포넌트 검토 후 AI 요청 | React Bits 소속 여부 확인 불가 |
| Claude Code·Codex·ChatGPT | 메뉴의 대상 도구로 표시 | 복사한 prompt로 후속 작업 | 기능·구현 품질 비교 근거 없음 |

## 선택 순서 제안

1. 화면 목적과 핵심 사용자 행동을 먼저 적는다.
2. 갤러리에서 화면 구성을 비교한다.
3. 필요한 역할이 정해진 뒤 효과·컴포넌트를 검토한다.
4. 실제 prompt를 읽고 부족한 요구를 보완한다.
5. 생성 결과를 화면 목적과 대조한다.

갤러리와 컴포넌트 페이지는 탐색 해상도가 달라 상호 보완적이다. AI 도구 세 개는 이 자료에서 레퍼런스 서비스의 경쟁 제품으로 제시되지 않았다. 위 순서는 학습 제안이며 실제 서비스 간 자동 연동을 뜻하지 않는다.

## 탐색 범위 밖의 대안

기존 제품의 design system을 우선 검토하거나 정적인 prototype으로 구성부터 검증하는 것도 적용 전략이다. 이는 dossier에 나온 서비스 기능·비교 결과가 아니라 불필요한 효과 도입을 줄이기 위한 제안이다.
