# Projects: 발견과 출시 준비 검토

## 프로젝트 1: 한 기능의 발견·기준 연결표

- **입력**: 실제 기능, 고객·기획 기준과 출처.
- **활동**: 자유로운 사용으로 문제 탐색, 실제 기준별 확인, 발견 결과의 영향 연결.
- **산출물**: 발견 문제·사용 맥락·관련 기준·기준별 결과·증거·미확인 항목.
- **완료 조건**: 어떤 관찰과 기준으로 출시 준비 상태를 판단했는지 설명할 수 있다.

| 관찰 ID·문제 | 관련 기준·출처 | 기준별 결과·증거 | 영향·추가 확인 |
|---|---|---|---|
| 입력 | 입력 또는 연결 미확인 | 충족 / 미충족 / 미확인과 근거 | 입력 |

버그 개수만 집계하지 않고 출시 기준에 주는 영향을 드러낸다. 이 표는 학습용 제안이며 필수 산출물은 아니다.

## 프로젝트 2: 변경 후 QA 질문 분리

변경이 있는 기능과 새 빌드를 대상으로 결과를 구분한다.

| 활동 | 확인 질문 | 기록할 근거 |
|---|---|---|
| Smoke testing | 새 빌드 핵심 기능이 동작하는가? | 확인한 기능과 결과 |
| Regression testing | 변경 후 기존 기능은 어떤 상태인가? | 재점검 범위와 결과 |
| Exploratory testing | 시나리오 없이 어떤 문제가 발견되는가? | 사용 맥락과 관찰 |
| Acceptance testing | 고객·기획 기준으로 출시 준비가 되었는가? | 실제 기준과 확인 결과 |

- **산출물**: 활동별 결과와 최종 판단에서 사용한 근거 목록.
- **완료 조건**: 결과를 다른 유형의 증명으로 대체하지 않고 미확인 범위를 표시했다.
- 표의 순서는 설명용이다. 실행 순서·도구·승인 권한은 팀의 실제 맥락에서 정해야 하며 자료가 규정하지 않는다.
