# 시작하기: 한 기능에 두 질문 적용

## 목표와 준비

같은 기능에서 발견 근거와 기준 충족 근거가 어떻게 다른지 설명한다. 다음은 **학습용 제안**이며 자료에 제시된 표준 절차가 아니다.

- 테스트가 허용된 기능 하나를 선택한다.
- 실제 고객·기획 기준을 확보한다. 기준이 없으면 확인 필요로 기록하고 통과를 선언하지 않는다.
- 특정 프레임워크나 자동화 도구는 필수가 아니다.

## 실습

1. 정해진 시나리오 없이 기능을 사용하며 문제와 발생 맥락을 적는다.
2. 실제 기준을 각각 확인하고 결과와 증거를 적는다.
3. 발견한 문제가 어느 기준에 영향을 주는지 검토한다.
4. 확인한 범위와 미확인 항목을 포함해 출시 준비 검토 근거를 설명한다.

위 순서는 학습 편의를 위한 제안이며 두 테스트의 필수 순서가 아니다.

```text
기능 / 환경 / 확인 일시:
탐색 관찰 ID / 사용 맥락 / 관찰 사실:
기준 ID / 실제 기준 / 출처:
기준별 결과 / 확인 증거 / 미확인 사유:
관찰 ID → 관련 기준 ID / 영향 또는 연결 불명 사유:
판단 / 근거 / 남은 불확실성:
```

## 완료 확인

- [ ] 버그 개수 경쟁 대신 두 활동의 근거 차이를 설명했다.
- [ ] 관찰 사실과 기준 충족 판단을 구분했다.
- [ ] 수행자의 추측을 고객·기획 기준으로 바꾸어 적지 않았다.
- [ ] 버그 미발견을 출시 기준 통과로 해석하지 않았다.
