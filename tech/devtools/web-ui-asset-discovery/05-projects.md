# Projects · 적용 과제

아래는 실습 제안이다. 영상에서 실행된 프로젝트나 검증된 통합 사례가 아니다.

## 1. UI reference 검토표

**목표**: 디자인 후보와 구현 가능한 에셋을 구별한다.

버튼·책·꽃·타일 구체 예시를 대상으로 다음 표를 채운다. 확보하지 못한 예시는 미확인으로 둔다.

| 후보 | 시각적 목적·적용 위치 | 필요한 interaction | 전달 형식·사용 조건 | 미확인 사항 |
|---|---|---|---|---|
| 버튼 | 작성 | 작성 | 확인 필요 | 작성 |
| 책 | 작성 | 작성 | 확인 필요 | 작성 |
| 꽃 | 작성 | 작성 | 확인 필요 | 작성 |
| 타일 구체 | 작성 | 작성 | 확인 필요 | 작성 |

**완료 기준**: 후보마다 관찰과 추정을 나누고 다음 확인 작업을 적는다. 후보 발견을 구현물 확보로 기록하지 않는다.

## 2. 단일 에셋 통합 실험

**선행 조건**: 후보 하나의 전달 형식과 license·사용 조건을 확인한다.

1. 작은 화면에 버튼 또는 카드 하나를 적용한다.
2. 외형·동작 요구사항을 먼저 기록한다.
3. 실행 성공, console error, dependencies를 검토한다.
4. 결과와 미충족 조건을 남긴다.

**산출물**: 실험 화면, 실행 방법, 요구사항별 평가 기록.

**통과 기준**: 요구한 외형·동작 재현, 프로젝트 실행 성공, 오류 점검 완료. 제공 형식이나 사용 조건이 확인되지 않으면 통합을 보류하고 검토 기록을 남긴다.

## 3. 애니메이션 배경 평가

**선행 조건**: 실제 사용할 수 있는 배경과 사용 조건을 확보한다.

본문과 입력 요소가 있는 화면에서 가독성, 입력 반응, 화면 크기 변화, motion 감소 설정 대응을 평가한다. 이는 검토 항목이며 제품의 지원 기능이 아니다.

**산출물**: 조건별 평가표와 적용·수정·보류 판단.

**완료 기준**: 측정 환경과 관찰 결과를 기록하고, 문제가 생기는 조건에는 정적 배경 등 대안을 제시한다.
