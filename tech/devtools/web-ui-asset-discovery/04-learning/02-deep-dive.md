# 심화 실습 · 전달 계약과 구현 평가

## 1. 산출물의 계약 작성

아래 항목은 확인할 기준이며 threeui의 지원 기능 목록이 아니다.

| 확인 축 | 질문 | 남길 증거 |
|---|---|---|
| 입력 형식 | code·prompt·기타 중 무엇인가? | 내용의 형식과 확인일 |
| 실행 조건 | 어떤 환경·파일·dependencies가 필요한가? | 실행 절차와 버전 |
| 사용 조건 | 적용하려는 용도로 사용할 수 있는가? | license·약관 원문과 검토 결과 |
| 결과 | 요구한 외형과 동작을 재현했는가? | 화면·동작 기록과 오류 로그 |

code라면 imports, assets 경로, dependency 변경과 실행 조건을 검토한다. prompt라면 누락된 요구사항을 보완하고 생성 결과를 원래 의도와 대조한다. 어느 경우든 외형만으로 rendering engine을 단정하지 않는다.

## 2. Codex·Claude Code 비교 실험

1. 동일한 초기 프로젝트와 reference, 요구사항을 준비한다.
2. 입력 자료, framework·버전, 도구·모델 버전과 수정 기회를 기록한다.
3. 각 결과를 외형·동작·실행·오류·dependency 변화로 나누어 평가한다.
4. 수동 수정과 미완료 항목을 포함해 결과를 적는다.

자료에는 실제 입력이나 결과가 없어 우열을 미리 정할 수 없다. 단일 사례의 결과를 일반적인 도구 성능으로 확대하지 않는다.

## 3. 애니메이션 배경 평가

실제 배경을 확보할 수 있을 때만 실행한다. 아래 항목의 지원 여부는 자료에서 확인되지 않았다.

- 본문 가독성: 움직임과 대비가 텍스트 읽기를 방해하는지 확인.
- 입력 반응: 클릭·키보드 조작 중 지연이나 방해 여부 확인.
- 화면 크기: 작은 화면과 큰 화면에서 배치·잘림 확인.
- motion 감소: `prefers-reduced-motion: reduce` 환경에서 동작 확인. 지원하지 않으면 정적 대안 검토.
- 성능: 동일 기기·브라우저·화면 조건에서 배경 적용 전후를 측정하고 조건을 기록.

## 결과 기록 양식

```text
후보 / 출처 URL / 확인일:
전달 형식 / 사용 조건 / 실행 환경:
관찰한 요구사항 / 직접 추가한 요구사항:
외형 결과 / 동작 결과:
실행 성공 여부 / console error / dependency 변경:
가독성 / 입력 반응 / 화면 크기 / motion 감소 대응:
미확인·미완료 항목 / 다음 확인 작업:
```
