# 시작하기: 한 영역의 검토 기록

## 목표와 준비

예약 캘린더처럼 한 화면을 골라, 의견의 위치·이유·확인 결과를 남긴다. 아래는 학습 제안이며 영상 속 명령의 재현 매뉴얼이 아니다.

준비물은 검토할 화면과 기록 문서다. 디자인 시스템 참조가 있으면 함께 준비하고, 없으면 목표값을 미확정으로 남긴다.

## 실습 순서

1. 한 영역을 선택하고 화면 위치와 현재 상태를 적는다.
2. “더 깔끔하게”라는 의견을 구성·색상·텍스트 등 확인 가능한 질문으로 바꾼다.
3. 화면 관찰과 시스템 대응 문제를 분리해 적는다.
4. 아래 표를 작성한다. 참조가 없는 값을 임의로 만들지 않는다.
5. 변경한다면 같은 내용·상태·viewport의 전후 화면을 남긴다. 이 조건은 실습 제안이다.
6. 확인 결과를 기록하고 미해결 항목을 남긴다.

| 대상 영역 | 현재 값 | 목표 스타일 또는 토큰 | 변경 이유 | 확인 결과 |
|---|---|---|---|---|
| 선택한 영역의 위치 | 측정 또는 관찰한 값 | 참조값 / 미확정 | 확인 가능한 이유 | 확인 / 보류 및 근거 |

## 기록 예시 형식

```text
대상: 예약 캘린더에서 선택한 날짜 영역
화면 관찰: 현재 표현을 직접 기록
시스템 대응: 참조가 없으면 미확정
변경 의도: 무엇을 확인하려는지 기록
확인 결과: 근거와 남은 의문 기록
```

## 완료 기준

- [ ] 의견마다 화면 위치와 변경 이유가 있다.
- [ ] 현재 관찰값과 목표 참조값을 구분했다.
- [ ] 변경했다면 전후 조건과 확인 결과가 남아 있다.
- [ ] 참조 없는 항목은 미확정으로 남겼다.

`/apply-ds-to-prototype`은 바로 실행 가능한 공개 명령으로 확인되지 않았다. 실행 도구·입력·권한·출력 위치가 확보되기 전에는 명령 실행을 실습 전제로 삼지 않는다.
