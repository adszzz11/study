# 심화 학습: 시스템 정합성과 시각적 결과

## 개념을 분리하기

| 개념 | 학습용 정의 | 검토 질문 |
|---|---|---|
| 디자인 | 전체 구성과 시각적 결과 | 의도한 정보와 상태가 표현되는가? |
| 컴포넌트 | 재사용 가능한 UI 단위 | 대응하는 단위와 variant가 확인되는가? |
| 토큰 | 스타일 의도를 관리하는 이름 있는 값 | 값과 의미가 참조 기준에 대응하는가? |

자료에는 상세 구조가 없으므로 실제 컴포넌트 이름·토큰 이름을 만들어 구현 사실처럼 적지 않는다. 같은 색상값이라는 사실만으로 token binding이 있다고 판단할 수 없다.

## 심화 실습

1. 한 영역에 쓰인 색상·텍스트 스타일·변수를 목록으로 만든다.
2. 제공된 시스템 자료에서 대응 후보와 근거를 찾는다.
3. 항목을 **대응 명확 / 판단 필요 / 참조 없음**으로 분류한다.
4. 실제 속성을 확인할 수 있으면 값과 연결 여부를 각각 기록한다. 확인할 수 없으면 미확인으로 남긴다.
5. 동일한 화면 상태로 전후 결과를 비교하고 누락 여부를 별도 검토한다.

| 항목 | 현재 관찰 | 참조 근거 | 대응 상태 | 실제 연결 확인 |
|---|---|---|---|---|
| 색상·스타일·변수 | 관찰한 값 | 문서 위치 / 없음 | 명확·판단 필요·참조 없음 | 확인 근거 / 미확인 |

## 증거별 판단 한계

| 표현 | 확인하기 좋은 질문 | 확정할 수 없는 것 |
|---|---|---|
| 속성 비교표 | 어떤 값과 변수를 비교하는가? | 전체 적용 정확도·누락 없음 |
| 전후 화면 | 표현이 어떻게 달라졌는가? | interaction·접근성·사용성 개선 |
| 영역 강조 | 어디를 논의하는가? | 선정 이유·우선순위 |

## 검토를 마치는 조건

시각적 변화와 시스템 대응을 별도 결론으로 남긴다. 실제 동작은 interaction 검증, 접근성은 별도 점검, 사용성 개선은 적절한 사용자 평가가 필요하다. 이들 검증이 영상에서 수행됐다는 근거는 없다.
