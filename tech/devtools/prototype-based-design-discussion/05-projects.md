# Projects: 실전 적용 과제

아래 과제는 관찰된 흐름을 바탕으로 한 학습 제안이다. 영상 속 도구의 지원 기능을 뜻하지 않는다.

## 1. 예약 캘린더 디자인 검토 기록

- **대상:** MeetBook 사례와 같은 예약 캘린더. 원본이 없으면 별도로 준비한 화면임을 표시한다.
- **작업:** 영역별로 위치·현재 상태·변경 이유를 적고 전후 이미지를 연결한다.
- **산출물:** `검토 의견 → 변경 항목 → 확인 결과` 추적표.
- **완료 기준:** 모든 의견에 대상과 확인 결과가 있고, 미해결 항목이 표시되어 있다.

| 의견 ID | 화면 위치 | 변경 이유 | 변경 항목 | 전후 이미지 위치 | 확인 결과 |
|---|---|---|---|---|---|
| 기록할 ID | 구체적 영역 | 근거 | 실제 변경 / 보류 | 확보한 이미지 경로 | 결과·미해결 사항 |

## 2. 디자인 시스템 적용 후보 정리

- **작업:** 색상·텍스트 스타일·변수를 수집해 제공된 시스템 자료와 대응시킨다.
- **산출물:** 대응 명확 / 판단 필요 / 참조 없음으로 구분한 후보표.
- **완료 기준:** 각 대응의 근거가 있고, 참조 없는 값·토큰·컴포넌트 구조를 꾸며 넣지 않았다.
- **목적:** 자동화 전에 적용 기준을 구체화한다.

## 3. 명령 기반 적용 도구 요구사항 정의

| 구분 | 정의할 질문 | 산출물 |
|---|---|---|
| 입력 | 대상 프로토타입과 시스템 참조를 어떻게 구분하는가? | 입력 형식과 예외 조건 |
| 처리 | 어떤 속성까지 비교·변경하는가? | 지원 범위와 제외 범위 |
| 출력 | 변경 내역과 전후 화면을 어떻게 보여주는가? | 결과 화면·기록 형식 |
| 검토 | 불확실한 대응을 어떻게 표시·확인하는가? | 보류·승인 기준 |

완료 기준은 각 요구사항에 입력, 기대 결과, 실패·보류 조건이 있는 것이다. 이는 새 도구의 설계 과제이며 영상 도구가 이미 지원한다는 주장이 아니다.
