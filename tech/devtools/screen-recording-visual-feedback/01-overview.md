# Overview: What / Why / 특징

## What

화면 녹화 피드백은 구현 의도를 적은 텍스트와 실제 동작을 보여주는 녹화를 함께 사용한다. Screenshot이 특정 순간을 보여준다면 녹화는 순간 사이의 변화도 검토할 수 있게 한다.

## Why

같은 최종 화면이라도 등장 순서·이동 경로·전환 속도에 따라 인상이 달라진다. 따라서 모션그래픽에서는 외형과 시간 흐름을 함께 확인해야 한다. 이는 일반적인 분석이며, 제공 사례에서 특정 시간 오차가 측정된 것은 아니다.

## 자료에서 확인되는 것과 한계

| 구분 | dossier가 전하는 관찰 | 확인할 수 없는 것 |
|---|---|---|
| 작업 맥락 | Claude에서 모션그래픽 수정 반복 | 구현 코드·실행 환경 |
| 피드백 입력 | 수정 요청과 녹화 첨부 | 영상 전체 분석·프레임 추출·별도 도구 사용 여부 |
| 비교 | 유사 웹 화면 두 개를 나란히 배치 | 기준 화면·동일 비교 조건 |
| 자동화 | 자동 수정 언급 | 감지·코드 변경·재실행의 범위와 성공률 |
| 완료 표시 | CMS Drafts의 `417 / 417`, 찬 진행 막대 | 수치 단위·검증 기준·실제 일치 여부 |

## 핵심 특징과 개념 모델

```text
수정 요청 + 화면 녹화
          ↓
     구현 결과 확인
          ↓
  화면 비교와 차이 해석
          ↓
       추가 수정
          ↓
    재녹화와 재검토 ──→ 차이가 남으면 반복
```

이 도식은 작업 방식의 추상화이며 시스템 내부 아키텍처가 아니다.

- **Spatial fidelity**: 화면의 위치·크기·간격·정렬.
- **Temporal fidelity**: 시작 시점·지속 시간·등장 순서·전환 흐름.
- 두 축은 실습용 분석 틀이며 자료에 실제 평가 점수가 제시되지는 않았다.
- viewport·초기 상태·재생 시작점이 다르면 관찰 조건 차이를 구현 차이로 오인할 수 있다.
- 일부만 보이는 `/reanimate`의 전체 문법·제공 주체·API 여부는 불명이다.
- 작업 완료와 품질 통과는 별개다. `417 / 417`을 처리 건수·테스트 통과 수·프레임 일치 수로 바꾸어 읽지 않는다.
