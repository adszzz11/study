# 심화: 비교 조건과 검증 설계

## 비교 조건을 고정하기

| 조건 | 기록할 내용 | 불일치 시 위험 |
|---|---|---|
| viewport | 폭·높이·배율 | 반응형 배치 차이를 결함으로 오인 |
| 초기 상태 | 데이터·스크롤·선택 상태 | 서로 다른 장면 비교 |
| 시작 기준 | 클릭 등 공통 이벤트 | 전체 타이밍이 어긋나 보임 |
| 실행 조건 | 입력 순서·로딩 상태 | 네트워크 지연과 모션 차이가 섞임 |
| 녹화 조건 | 재생 속도·범위·누락 여부 | 캡처 문제를 구현 문제로 오인 |

시작 기준 이벤트를 맞춘 뒤 동일 구간을 반복 재생한다. 눈에 보이는 차이가 실제 구현 때문인지 확신할 수 없으면 추가 녹화를 수행하고 판정을 보류한다. 사례에서 이런 통제가 이루어졌는지는 알 수 없다.

## Spatial / Temporal 분리

- Spatial fidelity: 같은 상태의 프레임을 정지해 위치·크기·간격·정렬을 비교한다.
- Temporal fidelity: 공통 시작점을 기준으로 등장 순서·지속 시간·전환 흐름을 확인한다.
- 프레임별 시각 차이만으로 의미상 품질을 확정하지 않는다. 캡처·렌더링 조건이 다를 수 있다.
- 수치 기준이 필요하면 실험 전에 허용 범위를 정하고 측정 방법을 기록한다. 이 사례에서 측정된 수치는 없다.

## 자동 수정 범위 분해

| 단계 | 남길 증거 | 별도 판정 |
|---|---|---|
| 차이 설명 | 구간·대상·관찰 로그 | 제3자가 같은 문제를 찾는가 |
| 수정 제안 | 기대 동작과 변경 계획 | 의도와 부합하는가 |
| 변경 적용 | 변경 내역·실행 결과 | 변경이 실제 반영됐는가 |
| 재검토 | 같은 조건의 재녹화 | 차이 해결과 부작용을 확인했는가 |

이 표는 자동화 실험을 위한 설계다. 실제 Claude 내부 처리 방식에 대한 설명이 아니다. 변경을 되돌릴 수 있게 기록하고, 재검토 실패 시 다음 반복의 범위를 다시 줄인다.

## 완료 기준 분리

```text
진행 상태: 계획한 수정 항목의 적용 여부
품질 상태: 사전에 정한 기대 동작의 충족 여부
판정 상태: 통과 / 미통과 / 증거 부족으로 보류
```

`417 / 417`처럼 단위가 없는 완료 표시를 품질 판정 대신 사용하지 않는다. 반복 횟수나 작업 시간 절감도 별도로 측정하기 전에는 성과로 주장하지 않는다.
