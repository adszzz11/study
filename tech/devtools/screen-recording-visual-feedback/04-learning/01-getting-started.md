# 시작하기: 한 동작의 피드백 루프

## 목표와 준비

요소 등장이나 화면 전환 하나를 선택해 녹화를 구체적인 수정 요청으로 바꾼다. 기준 동작과 수정 가능한 구현, 화면 녹화 도구를 준비한다. 특정 Claude 명령이나 자동 수정 기능은 전제하지 않는다.

## 실습 순서

1. 시작과 끝이 구분되는 짧은 동작을 고른다.
2. viewport, 초기 화면, 입력 동작, 녹화 범위를 적는다. 기준과 구현에 같은 조건을 적용한다.
3. 개인정보·토큰·알림을 가린 뒤 필요한 구간만 녹화한다.
4. 관찰과 판단을 분리한다. “제목이 버튼 뒤에 나타남”은 관찰이고 “순서가 잘못됨”은 의도 확인이 필요한 판단이다.
5. 위치·크기·타이밍 중 한 종류의 차이를 선택해 수정한다.
6. 같은 조건으로 다시 녹화하고 개선과 부작용을 확인한다.

## 기록 양식

```text
대상 동작:
기준 녹화 / 구현 녹화:
viewport / 초기 상태 / 입력 순서:
시작 기준 이벤트 / 녹화 범위:
문제 구간 → 관찰된 동작 → 기대 동작 → 수정 후 확인 방법
변경한 항목:
재녹화 결과: 통과 / 미통과 / 판단 보류
남은 차이 / 부작용:
```

## 수정 요청 예시

다음은 학습용 가상 예시이며 원본 사례의 측정 결과가 아니다.

```text
문제 구간: 시작 버튼 클릭 이후 제목과 버튼이 나타나는 구간
관찰: 구현에서는 버튼이 제목보다 먼저 나타난다.
기대: 기준처럼 제목 다음에 버튼이 나타나야 한다.
수정: 이번 반복에서는 등장 순서만 변경한다.
확인: 동일 초기 상태에서 재녹화해 순서와 기존 배치 유지 여부를 확인한다.
```
