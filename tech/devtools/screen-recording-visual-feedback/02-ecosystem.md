# Ecosystem: 피드백 방식 비교

## 비교 범위

자료에는 경쟁 제품 목록이 없다. 아래 표는 제품 순위나 성능 측정이 아니라 피드백 방식의 개념적 비교다.

| 방식 | 전달 정보 | 장점 | 한계·주의점 |
|---|---|---|---|
| 텍스트 피드백 | 수정 의도·요구사항 | 원하는 변화를 명시하기 좋음 | 동작의 느낌·시점 설명이 어려울 수 있음 |
| Screenshot 비교 | 특정 순간의 화면 구성 | 정렬·간격·크기 검토 | 순간 사이의 변화를 담지 못함 |
| 화면 녹화 피드백 | 시간에 따른 변화 | 순서·전환 흐름 검토 | 문제 구간·기대 동작을 별도로 지정해야 함 |
| 두 화면 나란히 비교 | 결과 간 시각적 차이 | 대응 요소를 직접 대조 | 재생 시점·화면 조건이 다르면 오판 가능 |
| 자동 수정 루프 | 차이를 수정 과정에 연결 | 반복 작업 자동화 설계 가능 | 사례의 구현 범위·성공률은 미검증 |

## 선택 가이드

1. 정적 배치 문제는 Screenshot과 텍스트로 시작한다.
2. 시간 흐름 문제는 짧은 녹화에 문제 구간과 기대 동작을 붙인다.
3. 나란히 비교할 때는 같은 시작 상태와 재생 기준점을 먼저 맞춘다.
4. 자동화를 붙이면 감지·제안·적용·재검토의 결과를 따로 기록한다.

녹화는 현상을 보여주고, 텍스트는 수정 의도를 지정한다. 두 역할을 결합하는 것이 실습의 기본 구성이다.
