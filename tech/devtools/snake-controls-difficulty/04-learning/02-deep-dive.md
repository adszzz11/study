# 심화: Input과 Difficulty의 경계 조건

## Control specification

다음 항목을 명시해야 재현 가능한 검사가 가능하다. 아래 정책은 선택지이며 확인된 구현이 아니다.

| 결정 | 선택지 | 검사 예 |
|---|---|---|
| 반대 방향 | 허용 / 차단 | 오른쪽 이동 중 왼쪽 입력 |
| 연속 입력 | 마지막 입력 / 큐 / tick당 한 입력 | 한 tick에 위·왼쪽 입력 |
| 반영 시점 | 즉시 / 다음 tick | tick 직전·직후 입력 |

반대 방향 차단을 선택했다면, 연속 입력도 현재 이동 방향과 일관되게 검사해야 한다. 마지막 키만 저장하는 정책과 입력 큐 정책은 서로 다른 이동 경로를 만들 수 있다.

## 속도와 이동 간격

격자 한 칸을 tick마다 이동한다고 가정한 학습용 모델이다.

```text
interval_ms = 한 칸 이동 간격(ms)
speed_cells_per_sec = 1000 / interval_ms
예: 200ms → 5칸/초, 100ms → 10칸/초
```

초당 속도와 간격을 혼용하지 않는다. 간격을 일정량 줄이는 정책은 초당 속도를 일정량 높이는 정책과 다르다.

## 단계별 증가 예시

아래는 원자료 사양이 아닌 실험용 제안이다. 먹이 개수 N을 Trigger로 선택한 경우다.

```text
초기 간격 I0 = 200ms
최소 간격 Imin = 80ms
단계 기준 K = 먹이 5개
단계별 감소 ΔI = 20ms
level = floor(N / K)
interval = max(Imin, I0 - level * ΔI)
```

| N | 기대 간격 | 검사 목적 |
|---|---|---|
| 4 | 200ms | 첫 임계값 직전 |
| 5 | 180ms | 첫 임계값 도달 |
| 6 | 180ms | 중복 증가 방지 |
| 30 | 80ms | 최소 간격 도달 |
| 35 | 80ms | 상한 이후 유지 |

현재 level에서 간격을 계산하면 같은 N을 반복 평가해도 계속 감소하지 않는다. 한 프레임마다 간격에서 ΔI를 빼는 방식은 Trigger를 중복 적용할 수 있다.

## 연속 증가 대안

시간 기반 실험이라면 `interval(t) = max(Imin, I0 - r*t)`처럼 정의할 수 있다. 여기서 t는 경과 초, r은 초당 간격 감소량(ms/s)이다. 일시정지 시간을 포함할지는 추가 설계 결정이다. 이 공식은 간격의 선형 감소이며 속도의 선형 증가는 아니다.

## 검증 범위

명목 간격과 실제 이동 시각을 함께 기록한다. 렌더링 지연이나 타이머 오차가 있으면 설정값만으로 체감 속도를 판단하지 않는다. 충돌 위험은 별도 충돌 규칙을 정한 후 평가한다.
