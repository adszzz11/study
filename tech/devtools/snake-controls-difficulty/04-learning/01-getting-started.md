# 시작하기: 요구사항을 검사 항목으로 바꾸기

## 1. 확정 사항과 미정 값 분리

| 항목 | 상태 | 작성할 명세 |
|---|---|---|
| 방향키 | 확인됨 | 방향 전환·입력 반영 정책 |
| 섭취 후 성장 | 확인됨 | 성장량과 적용 시점 |
| 속도 증가 조건 | 존재만 확인됨 | 초기값, Trigger, 증가 폭, 상한 |
| 충돌·종료·재시작 | 자료에 없음 | 도입 시 추가 요구사항으로 표시 |

## 2. Input 검사

1. 각 방향키를 눌러 선택한 방향으로 이동하는지 관찰한다.
2. 반대 방향 입력과 한 tick 안의 연속 입력을 검사한다.
3. 입력 즉시 이동인지 다음 tick 반영인지 기록한다. 자료에는 정답이 없다.

## 3. Growth 검사

먹이 섭취 전후 길이를 비교한다. 선택한 성장량을 g라 하면 `섭취 후 길이 = 섭취 전 길이 + g`인지 확인한다. 먹이를 먹지 않은 tick에는 의도하지 않은 성장이 없어야 한다는 기준도 명세로 채택할 수 있다.

## 4. Difficulty 검사

이동 간격으로 속도를 구현한다면 간격이 짧아질수록 빨라진다. Trigger 직전·도달·직후를 비교하고, 한 조건으로 증가가 여러 번 적용되는지 확인한다.

## 5. Build·Check 기록

```text
요구사항: [확인된 요구 / 추가 설계]
선택한 규칙: [미정이면 설계 결정 필요]
입력 및 초기 상태:
기대 결과:
관찰 결과:
수정 사항:
재검사 결과: [통과 / 실패 / 미검사]
```

화면 완성도와 동작 정확성을 별도로 기록한다. 웹사이트 유사도 수치를 합격 기준으로 쓰지 않는다.
