# Projects: 실전 검토 산출물

## 1. 예약 캘린더 디자인 비교 dossier

- **목표:** MeetBook 사례와 같은 예약 화면의 변경 근거를 한 문서로 묶는다.
- **작업:** 한 영역 선택 → 현재 상태와 기준 기록 → 전후 화면 대조 → 차이 목록 작성.
- **산출물:** 영역 표시 화면, 속성별 비교 표, 변경별 근거와 미확인 목록.
- **완료 기준:** 모든 변경이 화면 위치 및 비교 항목에 연결되고 판단 불가 항목이 명시된다.

## 2. 디자인 시스템 적용 workflow 검증

- **목표:** 입력 자료·적용 요청·결과 검토 단계를 재현 가능한 범위에서 기록한다.
- **사전 조건:** 실제 환경의 명령 지원 여부, 입력 규칙, 참조 대상, 권한과 변경 범위 확인.
- **작업:** 입력 기준 고정 → 지원되는 적용 방식 실행 → 자동 적용·수동 수정 구분 → 결과 검토.
- **산출물:** 환경·입력 기록, 항목별 변경 내역, 전후 증거, 미검증 범위.
- **완료 기준:** 무엇이 어떻게 바뀌었는지 근거로 설명한다. 명령 실행 여부만으로 성공 판정하지 않는다.

명령을 사용할 수 없으면 실행 검증은 미수행으로 기록하고 수동 비교 기록을 작성한다. 자료만으로 해당 명령을 재현할 수 있다고 전제하지 않는다.

## 3. AI 디자인 인수 검토 양식

- **목표:** 반복 인수 작업에서 확인된 변경과 미확인 상태를 일관되게 전달한다.
- **포함 항목:** 검토 영역, 색상·텍스트·변수 비교, 디자인·컴포넌트·토큰 정보, 전후 확인 결과.
- **산출물:** 재사용 가능한 빈 양식과 한 화면에 적용한 작성 예시.
- **완료 기준:** 다른 검토자가 관찰·기준·판정 근거를 구분하고 미확인 항목을 찾을 수 있다.

## 공통 결과 보고 양식

```text
대상 화면 / 영역:
기준 자료 / 버전:
적용 방식 및 수행 범위:
확인된 변경과 근거:
자동 적용 / 수동 수정:
비교 불가 항목 및 이유:
추가 확인 사항:
```

효과를 별도 측정하지 않았다면 정확도 향상이나 시간 단축을 프로젝트 성과로 쓰지 않는다.
