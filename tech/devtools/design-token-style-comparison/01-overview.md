# Overview: What / Why / 특징

## What

프로토타입의 시각적 속성을 디자인 시스템의 확인된 기준과 대조하는 검토 작업이다. 화면에서 보이는 변화와 그 변화가 어떤 속성·구성 단위에 해당하는지를 함께 기록한다.

## Why

AI가 만든 화면을 빠르게 논의할 수 있어도, 화면의 인상만으로는 어떤 속성이 기준에 맞는지 알기 어렵다. MeetBook 사례는 예약 캘린더를 출발점으로 특정 영역을 좁혀 보고, 색상 코드·텍스트 스타일·디자인 변수를 비교하는 흐름을 제시한다. 강조 영역의 실제 문제나 수정 요구는 알려져 있지 않다.

## 핵심 특징

| 특징 | 관찰 또는 해석 | 주의점 |
|---|---|---|
| 프로토타입 중심 | 예약 캘린더와 특정 영역을 제시 | 강조가 오류를 뜻한다고 단정하지 않는다 |
| 명령과 디자인 참조 | 채팅에 명령과 Figma URL 입력 | 공개 표준 명령인지 custom workflow인지 미확인 |
| 속성별 비교 | 색상·텍스트 스타일·디자인 변수 표 | 실제 값과 판정 규칙 미제공 |
| 디자인·컴포넌트·토큰 | 세 항목이 자료에 등장 | 실제 데이터 계층이나 자동 변환 구조의 증거는 아님 |
| 전후 검토 | 예약 화면의 전후 디자인 탭 | 외형만으로 내부 연결을 입증할 수 없음 |

## 작업 흐름의 재구성

```text
AI 완성 디자인 수령 → MeetBook 프로토타입으로 논의
→ 특정 영역 검토 → 명령과 Figma 디자인 URL 입력
→ 색상·텍스트 스타일·디자인 변수 비교 → 전후 디자인 확인
```

이 흐름은 화면에 제시된 작업을 재구성한 것이며 내부 실행 순서나 시스템 구성도가 아니다.

## 검토 관점

- **디자인:** 사용자가 보는 화면의 변화.
- **컴포넌트:** 화면을 구성하는 단위의 변화.
- **토큰:** 시각적 속성을 표현하거나 참조하는 기준의 변화.

위 구분은 분석을 위한 관점이다. 디자인 변수와 토큰의 구체적인 대응 관계, 컴포넌트 교체 여부, 코드 생성 여부는 확인되지 않았다.
