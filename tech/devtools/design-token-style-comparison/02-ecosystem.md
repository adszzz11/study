# Ecosystem: 검토 방식 비교

## 비교 범위

자료에 경쟁 제품이나 별도 token 관리 도구는 등장하지 않는다. 따라서 제품 간 우열 대신 관찰된 검토 방식을 비교한다. 아래 장점은 기대 가능한 활용점이며 측정된 효과가 아니다.

| 관점·방식 | 검토 대상 | 기대할 수 있는 장점 | 한계·미확인 사항 |
|---|---|---|---|
| 프로토타입 중심 논의 | 예약 캘린더와 강조 영역 | 구체적인 화면으로 범위 설정 | 토큰 연결 상태까지 보이는지 미확인 |
| 속성별 비교 표 | 색상·텍스트 스타일·디자인 변수 | 차이 기록과 추적 | 실제 값·판정 규칙 없음 |
| 디자인·컴포넌트·토큰 관점 | 화면·구성 단위·속성 기준 | 변경 수준 구분 | 세 항목의 실제 연결 구조 미확인 |
| 명령 기반 적용 | 명령과 Figma 참조 | 반복 작업을 workflow로 묶는 접근 | 환경·권한·자동화 범위 미확인 |
| 전후 디자인 비교 | 적용 전후 예약 화면 | 시각적 변화 직접 대조 | 내부 참조 적정성 입증에는 불충분 |

## 조합 방법 — 실습 제안

1. 화면에서 논의할 영역을 고정한다.
2. 표에 속성별 차이와 확인된 기준을 기록한다.
3. 변경을 디자인·컴포넌트·토큰 관점으로 설명한다.
4. 전후 화면이 표의 변경과 같은 대상을 보여주는지 검토한다.

명령 기반 적용은 실제 환경에서 지원 여부를 확인한 경우에만 추가한다. 수동 비교만으로도 학습 기록을 작성할 수 있다.

## Figma의 역할

Figma는 자료에서 디자인 URL을 제공하는 참조 도구로 확인된다. URL이 원본 프로토타입인지 디자인 시스템인지 확정할 수 없다. 별도 token 저장소, 코드 프레임워크, 동기화 도구와의 연동 근거도 없다.
