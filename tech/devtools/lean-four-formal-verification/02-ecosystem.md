# Lean 4 ecosystem과 대안 비교

> **근거 범위:** 제공된 dossier를 재구성한 노트다. 수집 출처가 없고 외부 검증을 수행하지 않았으므로 기술 설명·비교·적용 가능성은 **확인 필요**다. 현재 버전·지원 현황·성능·채택 규모는 판단하지 않는다.

## 비교 기준

아래는 목적과 접근법을 비교하는 개략적 표다. 현재 기능·호환성·우열을 검증한 결과가 아니며 **모든 항목은 확인 필요**다.

| 도구·접근 | 중심 접근 | 비교할 지점 | 선택 질문 |
|---|---|---|---|
| Lean 4 | Dependent types 기반 증명과 프로그래밍 | 명제·프로그램·증명의 연결 | 필요한 이론과 library가 있는가? |
| Coq | Dependent type theory 기반 proof assistant | 언어·자동화·library 차이 | 기존 증명 자산과 팀 경험은 어디에 있는가? |
| Isabelle/HOL | Higher-order logic 기반 증명 | 논리 기반과 작성 방식 | 문제를 어느 논리에서 자연스럽게 표현하는가? |
| Agda | Dependent types 기반 프로그래밍과 증명 | 프로그램 구성과 증명의 결합 | 프로그램 구성과 정리 축적 중 무엇이 중심인가? |
| SMT solver | 지원 이론 내 논리식 자동 해결 | 자동화 범위와 명세 표현 | 지원 이론으로 문제를 표현할 수 있는가? |
| Property-based testing | 생성 입력에 대한 성질 검사 | 실행 기반 검사와 보편적 증명의 차이 | 빠른 반례 탐색이 우선인가? |

## 관련 구성 요소

| 요소 | 알려진 역할 | 검증할 점 |
|---|---|---|
| mathlib | 수학 library | 목표 정리와 기반 이론의 존재, 의존성 |
| Lake | package/build 도구 | 프로젝트 구성과 명령 |
| elan | toolchain 관리 | 설치·버전 선택 방식 |
| Editor 연동 | goal 및 오류 확인 | 사용하는 editor의 설정과 기능 |

각 역할과 정확한 구성·지원 상태는 **확인 필요**다.

## 선택 절차

- 목표 정리를 자연어로 먼저 작성한다.
- 재사용 가능한 정의·보조정리를 조사한다.
- 가장 작은 예제로 형식화 비용을 측정한다.
- 명세 변경 시 증명 수정 범위를 기록한다.

언어 표현력이 충분해도 기반 이론을 직접 구축해야 하면 전체 비용이 커질 수 있다.
