# Lean 4 실전 프로젝트 제안

> **근거 범위:** 제공된 dossier를 재구성한 노트다. 수집 출처가 없고 외부 검증을 수행하지 않았으므로 기술 설명·비교·적용 가능성은 **확인 필요**다. 현재 버전·지원 현황·성능·채택 규모는 판단하지 않는다.

## 프로젝트 후보

실제 수행 사례가 아닌 적용 가능성 탐색안이다. **모든 적용 가능성은 확인 필요**다.

| 프로젝트 | 명세·증명 목표 | 핵심 난점 | 완료 기준 |
|---|---|---|---|
| 정렬 알고리즘 | 결과 순서성, 입력 원소 보존 | 중복 원소의 개수까지 보존 | 두 성질을 별도 정리로 증명 |
| 안전한 stack API | 빈 stack 처리와 연산 법칙 | 실패 처리와 type 설계 | 경계 조건과 push/pop 관계 확인 |
| 상태 전이 모델 | 금지 상태에 도달하지 않음 | 전이 누락과 과도한 단순화 | 초기 상태 성립 및 모든 허용 전이의 invariant 보존 증명 |
| AI 증명 후보 검사 | 생성 후보의 검사 | 명세 오류·미완성 증명·추가 가정 | 검사 결과와 허용 가정을 함께 보고 |

## 첫 프로젝트 진행안

1. 리스트 연산처럼 범위가 작고 명세가 명확한 순수 함수를 고른다.
2. 빈 입력과 경계 조건을 포함한 자연어 명세를 작성한다.
3. 실행 예제를 확인한 뒤 별도의 정확성 정리를 작성한다.
4. 필요한 보조정리를 찾아 증명한다.
5. 미완성 증명과 axiom을 검토하고 명세를 다시 읽는다.

## 측정할 항목

- 최초 명세·증명 작성에 든 시간.
- 기존 보조정리의 재사용 정도.
- 명세 변경 시 수정한 정의와 증명의 범위.
- 모델 밖에 남은 외부 시스템·환경 가정.

