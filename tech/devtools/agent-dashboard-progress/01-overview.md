# Overview: 무엇을 보여주고 무엇을 입증하는가

## What

중앙 JEV 노드 주위에 이름이 붙은 Agent와 지표 패널이 놓인 인터페이스다. 영상 00:00과 00:05 사이에 노드 배치가 달라지고 수치와 진행 막대가 증가한다.

## Why

복잡한 Agent 집단을 한눈에 보여주고 작업이 진행된다는 인상을 준다. 그러나 지표명·단위·계산식, 진행률의 분모, 실제 실행 기록이 없어 변화가 업무 성과를 뜻하는지는 알 수 없다.

| 층위 | 자료가 말하는 것 | 해석의 경계 |
|---|---|---|
| 관찰 | 중앙·주변 노드, 패널, 막대와 두 장면 사이 변화 | 화면 변화까지 확인 가능 |
| 홍보 주장 | JEV+Claude 기반 37개 AI Agent 팀이 회사 전체 운영 가능 | 검증된 능력으로 인용하지 않음 |
| 미검증 | 실제 Agent 수·실행·협업·지표 의미·운영 능력 | 로그와 산출물 필요 |

## 핵심 특징과 한계

- **중앙성:** JEV가 조정자처럼 보이지만 중심 배치만으로 orchestrator의 존재를 입증할 수 없다. 위임·메시지·의존성·결과 통합은 확인되지 않는다.
- **수치 패널:** 증가가 성과·비용·오류 중 무엇인지 알 수 없다. 이름과 단위 없이 개선으로 해석하지 않는다.
- **Progress bar:** 분모와 완료 조건이 없으면 업무 완료와 연결할 수 없다.
- **배치 변화:** 위치와 상태의 대응 규칙이 없어 재할당·협업 관계 변경·병렬성 증가로 단정할 수 없다.
- **시간 변화:** 두 장면만으로 실시간 갱신, 주기, 재생 여부를 판단할 수 없다.

## 검증 가능한 아키텍처 제안

```text
실행 이벤트 → 상태·지표 집계 → 대시보드 표시 → 근거 로그 조회
```

각 표시값에 작업 ID, 상태 변경 시각, 집계 기준을 연결한다. 실패와 재시도를 별도로 드러내고, 수치에서 원본 기록으로 이동할 수 있게 한다. 이 구조는 영상 구현에 대한 설명이 아닌 설계 제안이다.

## 기술스택 범위

- 등장 명칭은 JEV와 Claude이나 실제 연동 방식과 실행 구조는 확인되지 않는다.
- 확인된 UI는 Agent 노드·지표 패널·진행 막대 및 두 시점의 변화다.
- frontend framework, backend, database, 통신 방식은 특정할 수 없다.
- 구현 학습에서는 작업 이벤트·상태 모델·계산 기준·근거 로그 연결을 먼저 설계한다.
