# Cheatsheet: 화면을 성과로 읽기 전에

## 세 층위

| 분류 | 이 자료에서의 예 | 결론 |
|---|---|---|
| 관찰 | 두 장면 사이 값·막대·배치 변화 | 화면 변화 확인 |
| 홍보 주장 | 37개 AI Agent 팀의 회사 운영 | 근거 검증 필요 |
| 미검증 | 실제 실행·협업·성과·기술스택 | 단정 불가 |

## 빠른 검증 질문

- **Metric:** 무엇을 세는가? 단위·기간·범위·계산식은?
- **Progress:** 전체 대상과 완료 조건은? 작업 추가·실패·취소는 어떻게 반영하는가?
- **State:** queued/running/succeeded/failed의 전이 조건은?
- **Agent:** 노드가 역할·프로세스·세션 중 무엇을 뜻하는가?
- **Graph:** edge와 위치의 의미가 있는가? 관계 변경 이벤트가 있는가?
- **Freshness:** 마지막 발생·수신·화면 갱신 시각은?
- **Evidence:** task ID → 이벤트 → 산출물 → 검증 결과를 추적할 수 있는가?

## 학습용 계산 규칙

```text
completed_tasks = 최종 상태가 검증 통과인 고유 task 수
progress = completed_tasks / total_tasks
0개 또는 미확정 분모 = N/A
실행 중 Agent 수 ≠ 실행 중 작업 수 ≠ 검증된 결과 수
```

`1/4 → 2/4 → 2/10`은 `25% → 50% → 20%`다. 완료 수가 늘어도 범위 확대 후 비율은 낮아질 수 있다. 재시도는 attempt로 추적하고 작업 완료를 중복 집계하지 않는다.

## 해석 주의

- 중앙 노드 ≠ orchestrator 존재 증명.
- 수치 증가 ≠ 성과 개선.
- 위치 이동 ≠ 재할당·병렬성 증가 증명.
- 두 시점 변화 ≠ 실시간 갱신 증명.
- 변화 없음 ≠ 작업 중단 증명.

## 권장 표시
