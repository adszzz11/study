# Projects: 근거를 조회할 수 있는 대시보드

아래는 영상에서 확인되지 않은 검증 공백을 다루는 구현 과제다. 특정 framework나 backend는 전제하지 않는다.

## 프로젝트 1: Agent 작업 대시보드

- **입력:** task ID, Agent 이름, 현재 작업, 상태, 최근 변경 시각을 갖춘 작은 작업 집합.
- **구현:** 완료·실패·대기 패널과 작업 목록. 각 패널에서 집계 대상 작업으로 이동한다.
- **산출물:** 화면, Metric 정의서, 원본 이벤트 샘플, 재집계 절차.
- **완료 기준:** 표시된 모든 집계값을 원본 기록으로 재계산할 수 있다. 실행 종료와 결과 검증을 구분하며 stale 상태도 표현한다.

## 프로젝트 2: 진행률 해석 실험

- **입력:** 예상 작업량이 다른 작업과 동일한 상태 이벤트 스트림.
- **구현:** 개수 기준과 예상 작업량 기준 진행률을 나란히 표시한다.
- **실험:** 작업 추가, 실패, 재시도, 취소를 적용한다. 분모 변경 전후의 수치와 사유를 기록한다.
- **완료 기준:** 두 비율을 수작업으로 재현하고 차이의 원인을 설명할 수 있다. 특정 계산법의 우월성을 주장하지 않는다.

## 프로젝트 3: Agent 그래프 설명력 검증

- **입력:** 역할, 현재 작업, 관계 의미가 명시된 노드·edge와 관계 변경 이벤트.
- **구현:** 중앙·주변 노드 구성에 대기 이유와 의존성을 표시한다.
- **평가:** 사용자가 “누가 무엇을 수행하며 어디에서 대기하는가”를 설명하는지 확인한다.
- **완료 기준:** 단순 위치 이동은 업무 관계 변경으로 기록하지 않는다. 실제 관계 변경에는 근거 이벤트를 연결한다.

## 공통 리뷰 질문

- [ ] 화면의 모든 수치에 정의·단위·집계 범위가 있는가?
- [ ] 완료 기준·분모·실패·재시도 처리 정책이 공개되어 있는가?
- [ ] 관찰·해석·미검증 주장이 분리되어 있는가?
- [ ] 사람의 개입과 결과 품질을 별도로 확인할 수 있는가?
