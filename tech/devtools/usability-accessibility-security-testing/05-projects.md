# 실전 프로젝트

## 프로젝트 1: 주요 기능의 세 관점 점검표

기능 하나를 선택해 시작부터 완료까지 기록한다. 아래 기대 결과는 학습용 초안이며 실제 프로젝트의 목표·권한·정보 범위에 맞게 구체화한다.

| 대상 흐름 | 관점 | 기대 결과 | 실제 관찰 | 재점검 결과 |
|---|---|---|---|---|
| 선택 기능의 시작~완료 | Usability | 혼란 없이 목표 수행 | 작성 | 수정 후 작성 |
| 동일 흐름 | Accessibility: 스크린 리더 | 정보 파악·기능 이용 가능 | 작성 | 수정 후 작성 |
| 동일 흐름 | Accessibility: 큰 글자 | 정보 확인·흐름 진행 가능 | 작성 | 수정 후 작성 |
| 해당 기능의 접근 경계 | Security: 권한 우회 | 허용 범위 밖 접근 차단 | 작성 | 수정 후 작성 |
| 해당 기능의 보호 정보 | Security: 정보 유출 | 보호 대상 정보 비노출 | 작성 | 수정 후 작성 |

산출물에는 빌드, 이용 환경, 계정 권한, 재현 단계, 기대 결과, 관찰, 판정도 남긴다. 증거에는 실제 개인정보나 비밀정보 대신 테스트 데이터를 사용한다.

## 프로젝트 2: 변경 전후 비교

1. 프로젝트 1의 기록을 변경 전 기준으로 보관한다.
2. 화면 또는 기능을 변경하고 변경 내용을 적는다.
3. 같은 조건에서 다섯 행을 다시 점검한다.
4. 해결·지속·새로 발견한 문제와 미확인 항목을 구분한다.
5. 조건이 달라진 항목은 직접 비교의 한계를 명시한다.

이는 Regression testing의 설명에 연결한 실습안이며 영상의 정식 절차가 아니다.

## 완료 기준

- [ ] 어떤 조건에서 어떤 문제가 발생했는지 재현할 수 있다.
- [ ] 수정 후 달라진 결과를 근거와 함께 확인할 수 있다.
- [ ] 관찰과 원인 추정이 구분되어 있다.
- [ ] 자체 정량 기준이 있다면 프로젝트 기준이라고 표시했다.

테스트 건수 자체보다 조건·문제·변화가 드러나는 기록을 산출물로 삼는다.
