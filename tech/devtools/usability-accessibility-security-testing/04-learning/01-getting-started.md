# 시작하기: 같은 기능을 세 관점으로 보기

## 준비

허가된 테스트 환경과 테스트용 계정·데이터를 준비한다. 기능 하나와 완료 목표를 정한다. 예를 들어 “테스트 계정이 자신의 정보 화면을 열어 내용을 확인한다”를 목표로 삼을 수 있다. 이는 설명용 과제이며 영상의 사례가 아니다.

## 실습 순서

1. **기본 동작 확인:** 시작 상태, 실행 단계, 완료 상태를 기록한다.
2. **Usability 관찰:** 다음 행동이 불명확했던 단계, 망설임, 예상과 다른 결과를 구체적으로 적는다.
3. **스크린 리더 조건 확인:** 사용 환경을 기록하고 정보 파악과 기능 이용 가능성을 확인한다.
4. **큰 글자 조건 확인:** 글자 설정을 기록하고 정보 확인과 흐름 진행 가능성을 별도로 확인한다.
5. **Security 기대 결과 정의:** 계정별 허용 접근과 금지 접근, 보호 대상 테스트 데이터를 먼저 적는다. 허가된 범위에서 실제 결과와 비교한다.
6. **관찰과 추정 분리:** 직접 확인한 결과와 구현 원인에 관한 추측을 별도 칸에 남긴다.

스크린 리더 종류나 글자 설정에 관한 정해진 기준은 자료에 없다. 선택한 실습 환경을 기록하되 보편적인 합격 기준으로 제시하지 않는다.

## 기록 양식

```text
대상 기능 / 완료 목표:
빌드 / 계정 권한 / 이용 환경:
점검 관점 / 조건:
기대 결과:
재현 단계:
실제 관찰:
원인 추정(미확인):
판정: 통과 / 실패 / 미확인
수정 후 재점검:
```

## 완료 확인

- [ ] 흐름·스크린 리더·큰 글자·권한·정보 노출을 각각 기록했다.
- [ ] 수행하지 못한 항목은 통과가 아닌 미확인으로 남겼다.
- [ ] 관찰만으로 구현 원인을 단정하지 않았다.
