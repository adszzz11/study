# 심화: 판단 축과 증거 분리

## 같은 화면의 다른 문제

다음은 자료의 대상을 구체화한 가상 예시다.

| 관찰 | 주된 관점 | 추가로 확인할 사항 |
|---|---|---|
| 저장 후 다음 행동을 이해하지 못함 | Usability | 어느 단계에서 어떤 혼란이 발생했는가? |
| 스크린 리더로 특정 정보를 파악하지 못함 | Accessibility | 해당 환경과 재현 단계는 무엇인가? |
| 큰 글자에서 목표 수행이 중단됨 | Accessibility | 어떤 설정과 단계에서 중단되는가? |
| 권한 밖 정보에 접근 가능 | Security | 기대 권한과 실제 결과가 어떻게 다른가? |
| 보호 대상 정보가 노출됨 | Security | 무엇이 어떤 조건에서 노출되었는가? |

한 결함이 여러 관점에 영향을 주면 각 영향과 증거를 함께 기록한다. 분류 하나를 골랐다고 다른 관점의 검증이 끝나는 것은 아니다.

## 관찰과 원인 추정

“스크린 리더로 정보 X를 파악하지 못했다”는 관찰이다. “구현 속성 Y가 빠졌다”는 구현을 확인하기 전까지 추정이다. 관찰에는 환경·재현 단계·결과를 붙이고, 원인은 별도의 조사 결과로 남긴다.

## 통과 조건 분리

- Usability: 정한 목표의 수행 과정에서 어떤 혼란이 관찰되었는가?
- Accessibility: 스크린 리더와 큰 글자 각각에서 정보 파악과 목표 수행이 가능한가?
- Security: 기대 권한 경계가 유지되고 보호 대상 정보가 노출되지 않는가?

이 질문은 실습용이다. 관찰된 혼란이 없었다고 모든 사용자에게 문제가 없다는 결론을 낼 수 없고, 선택한 환경에서 통과했다고 전체 접근성·보안을 보장할 수도 없다.

## 변경 후 재점검

동일한 목표·계정 권한·이용 조건을 유지하고 변경 전후 결과를 비교한다. 조건이 달라졌다면 차이를 기록한다. 수정한 문제뿐 아니라 동일 흐름의 다른 관점도 확인하는 방식은 Regression 설명과 연결한 적용 제안이다.

성공률·소요 시간 등 수치 기준을 도입한다면 “프로젝트가 별도로 정한 기준”으로 표시한다. 자료가 제공한 수치처럼 인용하지 않는다.
