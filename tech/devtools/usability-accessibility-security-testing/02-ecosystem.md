# QA 테스트와의 비교

## 비교 기준

자료에는 경쟁 제품·도구 정보가 없다. 아래는 대체 제품 비교가 아니라 점검 목적과 수행 방식의 비교다.

| 테스트 | 자료의 점검 대상·방식 | 세 관점과의 관계 |
|---|---|---|
| Smoke | 새 빌드 핵심 기능의 빠른 확인 | 기본 동작 확인과 세 관점 점검은 별개 |
| Regression | 변경 후 기존 기능 재점검 | 수정한 세 영역의 재점검에 연결 가능: 적용 제안 |
| Exploratory | 시나리오 없이 사용하며 버그 탐색 | 탐색 방식이며 세 관점은 점검 대상 |
| Acceptance | 고객·기획 기준의 출시 준비 여부 | 세 관점 포함은 가능하나 자료에 포함 여부 없음 |
| Performance | 응답 속도 측정 | 응답 속도와 흐름의 혼란은 별개 |
| Compatibility 관련 점검 | 기기·브라우저 간 호환성 | 환경 호환과 접근 지원 조건 확인은 별개 |
| Usability | 혼란 없는 사용 흐름 | 사용 과정의 이해와 진행 |
| Accessibility | 스크린 리더·큰 글자 지원 | 제시된 접근 조건에서의 이용 |
| Security | 권한 우회·정보 유출 | 권한 경계와 정보 보호 |

## 비교 해석

- Regression은 변경 후 다시 확인한다는 맥락이고, Usability 등은 무엇을 확인하는가에 관한 관점이다. 함께 적용할 수 있다.
- Exploratory 방식으로 탐색하더라도 관점별 결과를 별도로 기록할 수 있다. 이는 학습용 적용 제안이다.
- Alpha/Beta의 참여자 차이와 Sanity·Load의 등장은 요약에 언급되지만, 세부 점검 대상이 충분하지 않아 표에서 제외했다.
- 자료에 없는 제품 추천이나 자동화 가능 범위는 이 비교로 판단할 수 없다.
