# What / Why / 특징

## What

| 테스트 | 점검 대상 | 핵심 질문 |
|---|---|---|
| Usability testing | 혼란 없는 사용 흐름 | 다음 행동과 결과를 이해하는가? |
| Accessibility testing | 스크린 리더·큰 글자 지원 | 해당 조건에서 정보를 파악하고 이용 가능한가? |
| Security testing | 권한 우회·정보 유출 | 권한 경계와 정보 보호가 유지되는가? |

## Why

Smoke testing으로 새 빌드의 핵심 동작을 확인하거나 Regression testing으로 기존 기능을 다시 확인해도 세 관점이 자동으로 검증되지는 않는다. “기능이 작동한다”와 “이용 과정에서 문제가 없다”는 별도의 판단이다.

## 핵심 특징

### Usability: 과정의 혼란

기능에 도달하고 다음 행동으로 이어가는 과정에 주목한다. 무엇을 해야 하는지 이해하는지, 행동 결과를 파악하는지, 망설임이나 잘못된 경로가 있는지 관찰한다. 이 질문은 자료의 표현을 구체화한 것으로, 사용자 집단·관찰 방식·성공률·소요 시간 기준은 자료에 없다.

### Accessibility: 조건별 이용 가능성

스크린 리더와 큰 글자는 별도로 확인한다. 지원 설정의 존재와 실제 목표 수행 가능성을 구분한다. 이 두 조건은 자료에 명시된 범위이며 Accessibility의 완전한 목록은 아니다.

### Security: 서로 다른 실패

| 대상 | 기록할 내용 |
|---|---|
| 권한 우회 | 기대 권한, 허용 범위, 실제 접근 결과 |
| 정보 유출 | 보호 대상 정보, 실제 노출 결과 |

권한 우회로 정보가 유출될 수는 있지만 자료는 구체적인 인과관계를 설명하지 않는다. 하나를 확인했다는 이유로 다른 점검을 생략하지 않는다.

## 통합 구조와 경계

```text
대상 기능 선정 → 기본 동작 확인 → 관점별 점검 → 결함 기록 → 변경 후 재점검
```

위 구조는 학습용 구성안이며 영상의 시스템 아키텍처가 아니다. 다음 행동을 이해하기 어려운 화면은 사용 흐름, 스크린 리더로 정보를 파악하기 어려운 화면은 접근 지원, 허용되지 않은 정보에 접근 가능한 화면은 권한 통제의 예다. 이 역시 실제 영상 결함 사례가 아닌 설명용 예시다.
