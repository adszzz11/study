# Projects: 목적과 범위를 명시하는 QA 실습

다음 프로젝트는 제공 정의에 근거한 적용 제안이다. 특정 도구나 CI/CD 사용은 전제하지 않는다.

## 프로젝트 1: 새 빌드 핵심 기능 체크리스트

- 작은 서비스의 핵심 기능을 선정한다.
- 각 항목에 우선 확인 이유·사전 조건·실행 방법·기대 결과를 적는다.
- 새 빌드에서 실행하고 실제 결과를 남긴다.
- **산출물:** Smoke 체크리스트와 실행 기록.
- **완료 기준:** 항목 수보다 각 기능을 우선 확인하는 이유를 설명할 수 있는가?

## 프로젝트 2: 변경 전후 기존 기능 비교

- 변경 대상과 유지되어야 할 기존 동작을 정한다.
- 변경 전 기대 동작을 기록하고 변경 후 재실행한다.
- 새 동작의 확인과 기존 동작의 유지 결과를 구분한다.
- **산출물:** 기존 동작 목록과 Regression 결과.
- **완료 기준:** 각 결과가 어떤 기존 기대 동작을 근거로 판정되었는지 추적 가능한가?

## 프로젝트 3: 목적별 QA 보고서

같은 빌드에 대해 Smoke와 Regression 결과를 별도로 정리한다.

```text
빌드 / 변경:
Smoke 목적 / 확인 범위 / 결과:
Regression 목적 / 확인 범위 / 결과:
발견 문제 / 재현 조건:
실행 못한 항목:
미점검 영역:
결과로 판단할 수 있는 범위:
```

- **산출물:** 목적·범위·발견 문제가 명시된 결과 보고서.
- **완료 기준:** 성능·보안·접근성은 실제 점검 근거가 있을 때만 결과를 기재한다. 전체 품질을 보증하는 표현을 쓰지 않는다.
