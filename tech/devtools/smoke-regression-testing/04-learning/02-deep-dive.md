# 심화: 겹치는 대상과 결론의 범위

## 1. 같은 동작을 목적별로 해석하기

인증 로직을 변경했다고 가정한다. 새 빌드에서 로그인 실행 여부를 빠르게 확인하는 것은 Smoke 관점이다. 기존 계정의 기대 동작이 유지되는지 재확인하는 것은 Regression 관점이다. 실행 절차가 같아도 선정 이유와 비교 기준을 기록해야 한다.

새로 추가한 동작의 의도 충족 확인과 기존 동작의 유지 확인도 구분한다. 새 기능 하나가 성공했다고 기존 기능 전체가 유지된 것은 아니다.

## 2. 범위 선정 실습

1. 변경 내용과 기존 동작 목록을 적는다.
2. 새 빌드에서 우선 확인할 핵심 기능을 표시한다.
3. 변경 후 재점검할 기존 동작을 고르고 선정 이유를 적는다.
4. 겹치는 항목에는 두 목적을 모두 기재한다.
5. 제외한 항목과 제외 이유를 남긴다.

이는 정의에서 도출한 설계 제안이다. 자료가 특정 범위 선정 알고리즘을 제시한 것은 아니다.

## 3. 보고 문장 교정

| 과도한 결론 | 범위를 제한한 기록 |
|---|---|
| Smoke 통과, 전체 정상 | 빌드 B에서 선정한 로그인·조회 핵심 기능이 기대대로 동작함 |
| Regression 통과, 모든 기능 유지 | 변경 C 후 재점검한 기존 계정 로그인 동작이 유지됨 |
| 기능 테스트 통과, 보안도 안전 | 기능 점검 통과. 보안은 미점검 |

## 4. 운영 적용 전 결정할 사항

주기·자동화 여부·실행 순서·중단 조건·통과 기준은 팀이 별도로 정해야 한다. 예를 들어 핵심 기능 실패 시 후속 점검을 중단하는 정책을 선택할 수 있지만, 이는 자료가 요구하는 규칙이 아니다.
