# 시작하기: 테스트 이름보다 질문부터

## 목표

동일한 기능에 서로 다른 검증 목적을 부여하고 기대 결과를 명시한다. 다음 로그인 예시는 실습용 제안이다. 특정 프레임워크나 자동화 도구는 필요하지 않다.

## 1. 기능과 목적 선정

| 기능 | 새 빌드에서 핵심인가? | 변경 후 유지할 기존 동작인가? |
|---|---|---|
| 기존 계정 로그인 | 예 | 예 |
| 프로필 조회 | 서비스에 따라 결정 | 기존 기능이라면 검토 |

핵심성은 서비스 맥락으로 설명한다. 두 범주가 겹치는 것은 정상이다.

## 2. 질문과 기대 결과 작성

- Smoke: 새 빌드에서 핵심 기능인 로그인이 동작하는가?
- Regression: 인증 관련 변경 후 기존 계정의 로그인 기대 동작이 유지되는가?
- 기대 결과 예: 유효한 테스트 계정으로 로그인하면 계정 홈이 표시된다.

## 3. 실행과 기록

```text
빌드 / 변경 식별자:
점검 목적: Smoke 또는 Regression (둘 다라면 목적별 기록)
확인 기능:
대상 선정 이유:
사전 조건 / 입력:
실행 방법:
기대 동작:
관찰 결과:
판정: 통과 / 실패 / 실행 못함
판단 가능한 범위:
미점검 영역:
```

## 완료 기준

- [ ] 핵심성과 기존 동작 유지의 차이를 설명한다.
- [ ] 목적·기대 동작·관찰 결과를 구분한다.
- [ ] 실행하지 못한 항목을 통과로 기록하지 않는다.
- [ ] 미점검 영역까지 결론을 확장하지 않는다.
