# Cheatsheet: 목적에 따른 빠른 판단

| 판단 질문 | 적용 관점 | 대상 선정 기준 |
|---|---|---|
| 새 빌드의 핵심 기능이 동작하는가? | Smoke testing | 핵심성·우선 확인 이유 |
| 변경 후 기존 기능이 유지되는가? | Regression testing | 유지할 기존 기대 동작 |
| 핵심이면서 기존 기능인가? | 두 관점에 포함 가능 | 각 목적과 비교 기준을 명시 |

## 실행 전

- [ ] 빌드 또는 변경을 식별한다.
- [ ] 확인 목적과 대상 선정 이유를 적는다.
- [ ] 입력·실행 방법·기대 동작을 정한다.

## 실행 후

- [ ] 관찰 결과와 판정을 분리해 기록한다.
- [ ] 실제 확인 범위와 미점검 영역을 남긴다.
- [ ] 실행 못한 항목은 통과에 포함하지 않는다.

## 기억할 경계

- Smoke 통과 ≠ 모든 기존 기능 유지.
- Regression testing ≠ 반드시 전수 검사.
- 두 테스트 통과 ≠ 성능·보안·접근성 검증.
- 속도만으로 구분하지 말고 질문과 기대 기준으로 구분한다.
- 필수 순서·주기·자동화·통과 기준은 자료에 없다.
- Sanity / Load는 명칭만 확인되므로 상세 관계를 단정하지 않는다.

이 체크리스트는 실무 적용을 위한 제안이다.
