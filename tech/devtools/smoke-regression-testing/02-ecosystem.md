# Ecosystem: 다른 QA 관점과 비교

## 비교 기준

아래 항목은 경쟁 제품이나 상호 대체재가 아니라 서로 다른 질문을 확인하는 QA 관점이다.

| 관점 | 제공 자료의 설명 | Smoke / Regression과의 관계 |
|---|---|---|
| Smoke testing | 새 빌드의 핵심 기능을 빠르게 확인 | 빌드의 핵심 동작 |
| Regression testing | 변경 후 기존 기능 재점검 | 기존 동작의 유지 |
| Exploratory testing | 시나리오 없이 사용하며 버그 탐색 | 탐색 방식이 강조됨 |
| Acceptance testing | 고객·기획 기준으로 출시 준비 여부 확인 | 별도의 수용 기준 |
| Alpha / Beta testing | 내부 참여자와 실제 사용자 역할 구분 | 참여자 관점 |
| Performance testing | 응답 속도 측정 | 기능 동작과 다른 측정 관점 |
| 기기·브라우저 호환성 | 환경 간 호환성 확인 | 환경에 따른 차이 |
| 사용 흐름 점검 | 혼란 없는 사용 흐름 확인 | 사용 과정의 이해 가능성 |
| 접근성 점검 | 스크린 리더·큰 글자 지원 확인 | 접근성 지원 |
| 보안 점검 | 권한 우회·정보 유출 점검 | 보호 경계와 정보 |
| Sanity / Load testing | 전체 12종 화면에 명칭 등장 | 정의가 없어 상세 비교 불가 |

## 해석 시 주의

이 표는 dossier가 요약한 설명이며 각 테스트의 포괄적 표준 정의가 아니다. Sanity와 Smoke의 차이, Load와 Performance의 관계는 제공 자료만으로 확정할 수 없다. 명칭의 등장과 정의의 제공을 구분한다.

새 빌드의 로그인 성공 여부를 확인해도 응답 속도·권한 우회·스크린 리더 지원은 입증되지 않는다. 각 영역에 맞는 기대 기준과 관찰 근거가 필요하다.
