# Overview: What / Why / 특징

## What

| 구분 | Smoke testing | Regression testing |
|---|---|---|
| 출발점 | 새 빌드 | 소프트웨어 변경 |
| 질문 | 핵심 기능이 동작하는가? | 기존 기능이 계속 동작하는가? |
| 대상 선정 | 기능의 핵심성 | 유지해야 할 기존 동작 |
| 자료의 명시적 특성 | 빠른 확인 | 기존 기능 재점검 |
| 결과의 의미 | 확인한 핵심 기능의 동작 여부 | 재점검한 기존 기능의 유지 여부 |

## Why

새 빌드의 기본 상태는 핵심 기능부터 확인해야 빠르게 파악할 수 있다. 반면 변경한 부분이 의도대로 동작한다는 사실만으로 기존 기능의 유지까지 입증할 수는 없다. 두 불확실성을 별도의 질문으로 다루는 것이 목적이다.

## 특징

- **대상은 겹칠 수 있다.** 핵심 기능이면서 기존 기능이라면 두 점검에 모두 포함된다.
- **목적과 기대 동작을 기록한다.** 실행 단계만 보고 테스트 종류를 확정하지 않는다.
- **결론은 확인한 범위에 한정한다.** 미점검 기능과 품질 영역은 통과로 추정하지 않는다.
- **절차는 고정되어 있지 않다.** 필수 순서·주기·자동화 여부·통과 기준은 제공 자료에 없다.

예를 들어 로그인 기능을 새 빌드에서 우선 실행하면 Smoke 목적이다. 인증 관련 변경 후 기존 계정의 로그인 동작이 유지되는지 재확인하면 Regression 목적이다. 이는 정의를 적용한 예시다.

## 적용 흐름 제안

1. 핵심 기능과 기대 결과를 정한다.
2. 새 빌드에서 빠르게 실행한다.
3. 변경 후 유지할 기존 동작을 선정한다.
4. 해당 동작을 재점검한다.
5. 목적·범위·관찰 결과를 기록한다.

이 순서는 실습용 제안이며 필수 실행 순서가 아니다.
