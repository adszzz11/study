# 심화: prompt와 적용 결과 검증

## Copy prompt 검토

큐브 그리드 페이지에 메뉴가 있다는 사실과 구현 성공은 별개다. 수집 자료에는 prompt 본문이 없어 현재 분석할 수 없다. 원문을 확보한 뒤 아래를 점검한다.

- 표현 요구: 무엇을 재현하라고 하는가?
- 설치 요구: 패키지, 버전, 외부 리소스를 요청하는가?
- 수정 범위: 어느 파일과 화면을 바꾸도록 하는가?
- 검증 요구: 결과를 어떤 기준으로 확인하는가?

다음은 서비스의 실제 prompt가 아닌 **추가 요구사항 작성용 템플릿**이다.

```text
목적: [효과를 쓰는 이유]
대상 화면과 위치: [범위]
확인된 원본 자료: [URL·코드·사용 조건]
수정 가능한 파일: [범위]
유지할 콘텐츠와 레이아웃: [조건]
검증: 가독성, 조작 방해, 성능, 접근성
미확인 API·의존성은 먼저 확인하고 가정을 명시할 것.
```

## 적용 전후 실험

동일 콘텐츠·레이아웃·뷰포트·입력 조건을 유지한 기본 화면 A와 효과 화면 B를 비교한다. 효과 외의 변경이 있으면 따로 기록한다.

| 검증 축 | 관찰 질문 | 기록 방식 |
|---|---|---|
| 정보 전달 | 핵심 메시지가 더 잘 보이는가? | 동일 과제 수행 관찰 |
| 가독성 | 텍스트와 효과가 겹치거나 시선을 분산하는가? | 위치·문제 상황 기록 |
| 조작성 | 포인터·터치·키보드 입력을 방해하는가? | 입력별 재현 절차 |
| 성능 | 로딩·프레임·입력 응답이 달라지는가? | 같은 기기·환경에서 측정 |
| 접근성 | 키보드·포커스·보조기술·모션 감소 설정을 고려했는가? | 실제 구현에서 확인 |

접근성·성능 항목은 제안하는 검증 기준이다. 후보 컴포넌트가 해당 기능을 제공하거나 기준을 통과했다는 의미는 아니다.

## 도입 판단

목적 달성의 증거가 있고 사용 조건·호환성이 확인되면 도입을 검토한다. 가독성이나 입력을 방해하면 축소·제거를 검토한다. 측정하지 않은 항목은 통과로 처리하지 않는다.
