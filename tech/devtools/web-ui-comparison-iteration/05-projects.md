# Projects: 화면 비교를 기록과 검증으로 확장하기

아래 프로젝트는 학습 제안이다. 영상에서 실제로 구현되었거나 성공한 시스템을 재현한다고 주장하지 않는다.

## 1. 모션그래픽 재현 비교 기록

짧은 장면 하나를 골라 기준·초기 구현·수정 결과를 같은 시작 조건으로 녹화한다.

- 작업: 반복마다 관찰한 차이, 수정 요청, 변경 범위, 재관찰 결과를 적는다.
- 산출물: 기준 녹화, 반복별 녹화, 조건표, 변경 기록.
- 완료 기준: 어떤 요청이 어떤 차이를 줄였는지 증거와 함께 설명하고, 외형과 전환 순서를 각각 판정한다.

## 2. 웹 UI 비교 보드

기준 화면과 현재 화면을 나란히 보여주고 차이를 Layout·시각 표현·Motion·상호작용으로 분류한다.

| 보드 필드 | 기록할 내용 |
|---|---|
| 차이 ID·분류 | 항목의 고유 식별자와 비교 축 |
| 조건 | viewport, 데이터, 초기 state, 시작 이벤트 |
| 근거 | 기준·수정 전·수정 후 자료 |
| 요청·변경 | 관찰과 연결된 제한된 수정 |
| 판정 | 통과·실패·보류, 남은 차이 |

- 산출물: 병렬 비교 보드와 항목별 근거 기록.
- 완료 기준: 모든 항목을 같은 조건에서 재검토할 수 있다. Motion에는 녹화 근거가 있다.
- 초점: 자동 판정 전에 조건과 검토 기준을 명확히 한다.

## 3. 검증 가능한 자동 수정 루프

차이 기록을 입력으로 제한된 수정을 수행하고 재캡처한 결과를 검토 대상으로 돌려준다.

- 작업: 변경 실행·결과 수집·검증 통과·미해결 차이를 별도 상태로 관리한다.
- 제한: 수정 범위와 반복 상한을 미리 정하고, 개선 없음이나 회귀 발생 시 검토로 전환한다.
- 산출물: 입력 차이 목록, 변경 diff, 결과 자료, 항목별 판정 로그.
- 완료 기준: 실행 성공과 검증 성공을 구분하고, 실패한 반복도 추적 가능하다.
- 지표: 완료 수치를 쓰려면 무엇을 센 값인지 명시한다. 그 값만으로 UI 일치를 주장하지 않는다.
