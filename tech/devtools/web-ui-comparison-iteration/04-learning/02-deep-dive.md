# 심화: 시간 정렬과 검증 가능한 반복 루프

## 핵심 개념

| 용어 | 실습에서의 의미 |
|---|---|
| baseline | 비교 대상으로 정한 기준 자료 |
| viewport | 렌더링 영역의 크기 |
| state | 데이터·선택·로딩 등 화면의 현재 조건 |
| temporal alignment | 공통 이벤트를 기준으로 시간축을 맞추는 과정 |
| visual regression | 정의한 조건에서 시각적 변경을 감지·검토하는 검증 |
| acceptance criteria | 완료로 판정할 관찰 가능한 조건 |

이 용어는 실습을 구조화하기 위한 것이며 영상에서 사용되었다는 뜻은 아니다.

## 정적 비교 실험

1. 같은 viewport·배율·데이터·폰트·state에서 기준과 결과를 캡처한다.
2. Layout과 시각 표현을 나누어 검토한다.
3. 동적 데이터나 렌더링 환경이 만든 차이인지 확인한 뒤 구현을 바꾼다.
4. baseline은 의도된 변경임을 검토한 뒤 갱신한다. 실패를 없애기 위한 무조건 갱신은 피한다.

Screenshot diff는 변경을 감지할 수 있지만 의도된 변경인지까지 자동으로 결정하지 않는다. 허용 오차를 쓰면 이유와 놓칠 수 있는 차이를 기록한다.

## Motion 실험

- 공통 시작점: 같은 버튼 클릭 또는 같은 초기 상태 진입을 사용한다.
- 같은 구간: 시작 전 상태부터 종료 후 안정 상태까지 녹화한다.
- 비교 항목: 등장 순서, 시작·종료 시점, 이동 경로, 전환 속도.
- 한 번에 한 축: 순서를 고친 뒤 속도를 검토한다.
- 시간값을 기재할 때는 프레임 또는 타임스탬프 등 측정 근거를 남긴다.

애니메이션을 멈춘 캡처는 정적 비교를 안정화할 수 있다. 그 결과만으로 Motion이 일치한다고 판정하지 않는다. `prefers-reduced-motion` 등 환경 설정도 비교 조건에 포함한다.

## 자동 수정 루프의 상태 분리

```text
차이 기록 → 제한된 변경 실행 → 결과 수집 → acceptance criteria 검증
                                             ├─ 통과: 근거 저장
                                             └─ 미해결: 차이 갱신 → 다음 반복
```

이 구조는 제안이며 영상의 자동화 구현을 복원한 것이 아니다.

| 상태 | 필요한 증거 |
|---|---|
| 변경 실행 | 변경 기록 또는 diff |
| 결과 수집 | 조건과 연결된 캡처·녹화 |
| 검증 통과 | 판정 항목별 결과와 근거 |
| 미해결 차이 | 남은 차이, 실패·보류 사유 |

실습의 종료 조건으로 반복 횟수 상한, 개선 없음, 회귀 발생 시 검토 중단을 정할 수 있다. 진행 숫자를 표시한다면 분자·분모의 의미를 정의한다. “검토한 항목 수”는 “시각적 일치율”과 다른 값이다.
