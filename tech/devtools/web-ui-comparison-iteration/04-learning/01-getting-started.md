# 시작하기: 한 차이를 수정하고 다시 관찰하기

## 목표와 준비

정지 화면의 차이 하나를 선택해 변경 전후를 설명한다. 아래는 dossier의 흐름을 바탕으로 만든 실습안이며 영상의 실행 절차가 아니다.

준비물: 기준 화면, 실행 가능한 구현, 캡처 수단, 변경 기록. 특정 framework나 browser automation은 필수가 아니다.

## 실습 순서

1. **조건 고정:** viewport, 배율, 표시 데이터, 초기 state를 맞춘다. 폰트 로딩과 스크롤 위치도 기록한다.
2. **관찰 작성:** “어색하다” 대신 “제목이 기준보다 아래에 있다”처럼 대상과 차이를 적는다. 측정하지 않은 픽셀·시간값은 쓰지 않는다.
3. **수정 범위 제한:** Layout 또는 Motion 중 한 축을 고른다. 대상·원하는 변화·확인 방법을 요청에 포함한다.
4. **재수집:** 수정 후 같은 조건과 같은 상태에서 캡처한다. Motion은 공통 시작점의 동일 구간을 녹화한다.
5. **판정:** 배치, 전환 순서, 기존 상호작용 유지 여부를 별도로 판정한다.

## 수정 요청 예시

```text
대상: 첫 화면 제목과 상단 패널
관찰: 제목이 기준보다 아래에 있다.
요청: 제목의 세로 위치만 조정한다.
확인: 동일 viewport와 초기 state에서 다시 캡처해 위치를 비교한다.
회귀 확인: 버튼 클릭과 패널 전환이 기존대로 작동하는지 확인한다.
```

## 반복 기록 양식

```text
반복 ID:
기준 자료 / 결과 자료:
비교 조건: viewport / 배율 / 데이터 / state / 스크롤
관찰한 차이:
수정 범위와 변경 내용:
재관찰 결과: 개선 / 동일 / 악화 / 판단 보류
회귀 확인:
미해결 차이와 다음 행동:
```

## 완료 기준

- [ ] 변경 전후 자료가 같은 조건이다.
- [ ] 요청한 차이의 개선 여부를 근거와 함께 설명할 수 있다.
- [ ] 기존 상호작용을 확인했다.
- [ ] 미확인 항목을 통과 처리하지 않았다.
