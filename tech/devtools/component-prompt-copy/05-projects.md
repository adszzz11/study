# Projects — 실전 적용 제안

세 프로젝트 모두 미실행 제안이다. 실제 결과를 관찰 사실처럼 기재하지 않는다.

## 1. 컴포넌트 프롬프트 비교 기록

- 입력: 동일 컴포넌트에서 확보한 도구별 원본 payload.
- 작업: 공통 설명, 도구별 차이, 누락 조건, 추가 지시를 비교한다.
- 산출물: 비교표와 프로젝트 조건을 보완한 요청문.
- 완료 기준: 도구별 차이가 있는지 원문으로 설명하고, 미확인 항목을 남긴다.

## 2. 레퍼런스에서 구현까지 소규모 실험

- 입력: 하나의 컴포넌트, 고정된 프로젝트 조건, 직접 작성한 요청과 복사한 요청.
- 작업: 같은 초기 상태에서 각각 실행하고 초기 적합성·누락·수정 횟수·완료까지 작업량을 기록한다.
- 산출물: 원본 요청 두 개, 결과 기록, 수정 이력, 비교 결론.
- 완료 기준: 복사가 설명 누락과 재작업을 줄였는지 기록으로 판단한다. 재현 성공과 디자인 성공은 별도 판정한다.

| 요청 방식 | 준비 시간 | 초기 누락 | 수정 횟수 | 총 작업 시간 | 재현 | 디자인 적합성 |
|---|---|---|---|---|---|---|
| 직접 작성 | 미실행 | 미실행 | 미실행 | 미실행 | 미실행 | 미실행 |
| 복사 후 보완 | 미실행 | 미실행 | 미실행 | 미실행 | 미실행 | 미실행 |

## 3. 팀용 컴포넌트 선택·검수 템플릿

목적은 전달 편의를 활용하면서 선택 근거와 최종 검수 책임을 남기는 것이다.

```text
컴포넌트 / 출처 URL / 수집일:
선택 이유 / 사용할 화면:
유지할 시각적 특징과 동작:
프로젝트에 맞게 변경할 조건:
대상 도구 / 원본 payload:
추가 지시:
구현 결과 / 누락 / 수정:
디자인 검토 결과 / 검토자 / 판단 근거:
```

완료 기준: 다른 팀원이 원본 요청, 변경 이유, 구현 판정, 디자인 판정을 구분해 추적할 수 있다.
