# Deep Dive — payload와 결과를 나누어 검증하기

## 핵심 개념

| 개념 | 검토 질문 |
|---|---|
| 시각적 레퍼런스 | 유지하려는 외형과 동작은 무엇인가? |
| prompt payload | 설명·코드·링크·설치 조건 중 무엇을 전달하는가? |
| 도구별 지시 형식 | 텍스트가 실제로 다른가, 차이가 어떤 작업을 요구하는가? |
| 프로젝트 맥락 | framework·입력·화면 조건을 어떻게 보완해야 하는가? |
| 결과 검증 | 재현과 최종 디자인을 어떤 기준으로 평가하는가? |

## 1. 도구별 텍스트 비교

동일 컴포넌트에서 제공되는 Claude Code, Codex, ChatGPT용 텍스트를 확보한다. 제공되지 않는 항목은 ‘미제공’, 확보하지 못한 항목은 ‘미확인’으로 남긴다.

| 도구 | 공통 설명 | 고유 지시 | 설치·의존성 | 검증 기준 | 추가할 조건 |
|---|---|---|---|---|---|
| Claude Code | 미확인 | 미확인 | 미확인 | 미확인 | 미확인 |
| Codex | 미확인 | 미확인 | 미확인 | 미확인 | 미확인 |
| ChatGPT | 미확인 | 미확인 | 미확인 | 미확인 | 미확인 |

내용이 같다면 메뉴 선택 자체가 도구별 최적화를 의미하지 않는다. 내용이 달라도 성능 차이는 별도 실험으로 확인해야 한다.

## 2. 직접 작성 요청과 비교

아래는 실험 설계 제안이며 실행 결과가 아니다.

- A: 미리보기를 보고 직접 작성한 요청.
- B: 복사한 payload에 필요한 프로젝트 조건을 추가한 요청.
- 동일하게 유지: 컴포넌트, 목표, 시작 코드, 프로젝트 조건, 사용 도구·모델·설정, 종료 기준.
- 분리 기록: 요청 준비 시간, 실행 시간, 수정 횟수, 누락 사항, 최종 결과.
- 가능하면 독립된 초기 상태에서 반복하고 실행 순서를 바꾼다. 단일 결과는 일반적인 우열의 근거로 삼지 않는다.

| 평가 축 | 확인 방법 |
|---|---|
| 재현 | 배열·형태·움직임을 사전 기준과 비교 |
| 적용성 | 프로젝트 화면·입력 조건에서 확인 |
| 작업량 | 요청 준비와 후속 수정 시간을 함께 기록 |
| 디자인 적합성 | 화면 목적·다른 요소와 조화 검토 |

## 3. 해석의 경계

프롬프트가 상세해도 프로젝트 제약을 충족한다는 보장은 없다. 원본과 비슷한 결과도 해당 화면에서는 부적합할 수 있다. payload가 없는 현재 자료에서는 설명 시간 절감과 구현 정확도 향상에 대한 결론을 유보한다.
