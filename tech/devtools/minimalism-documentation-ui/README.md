# Minimalism — 기술 문서 UI의 시각적 절제와 정보 위계

> **한 줄 정의**: Minimalism은 UI의 시각적 요소를 절제하는 디자인 접근이며, 제공 자료에서는 옅은 색의 기술 문서 웹페이지로 제시된다.

## Overview

이 tool-study는 특정 제품이나 framework가 아닌 **기술 문서 UI의 디자인 접근**을 다룬다. 핵심 질문은 “얼마나 없앨까?”보다 “읽기와 탐색에 필요한 구분을 유지하면서 무엇을 덜어낼까?”다.

| 근거 수준 | 내용 |
|---|---|
| 관찰 | dossier는 Minimalism 예시를 옅은 색의 기술 문서 웹페이지로 설명한다. |
| 해석 | 시각적 절제가 본문과 정보 구조에 주의를 모으는 방향으로 읽힐 수 있다. |
| 미확인 | 가독성, 탐색 속도, 만족도, accessibility, 구현 기술, 성능 |

옅은 색은 해당 예시의 단서다. Minimalism의 필수조건이나 충분조건으로 일반화하지 않는다. 화면의 단순함과 정보 이해의 용이성은 별도로 검증한다.

## When To Use

- 기술 문서의 본문·참조 정보·탐색 요소 사이의 정보 위계를 검토할 때
- 장식을 줄이되 링크, 현재 위치, focus 등 필요한 단서를 보존하려 할 때
- 동일 콘텐츠로 시각적 표현의 영향을 실험할 때

## When Not To Use

- 이 영상만으로 특정 디자인의 사용성 우수성을 주장할 때
- 옅은 색이나 요소 개수만으로 accessibility·가독성을 판단할 때
- framework·component library·backend·배포 환경을 선정할 근거가 필요할 때: 자료에 기술 정보가 없다.
