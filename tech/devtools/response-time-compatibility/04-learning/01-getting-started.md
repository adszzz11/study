# 시작하기: 첫 검증 기록

## 목표와 준비

하나의 핵심 기능을 같은 조건으로 수행하고 기능 결과와 시간을 분리해 남긴다. 아래는 학습 제안이며 특정 도구 설치를 전제하지 않는다. 확인할 빌드, 시나리오, 접근 가능한 환경을 먼저 준비한다.

## 실습 순서

1. **시나리오 고정**: 시작 조건·입력·기대 완료 상태를 적는다.
2. **측정 구간 정의**: 어떤 행동부터 어떤 결과까지 측정할지 적는다. 측정 수단과 단위도 기록한다.
3. **환경 명시**: 기기, OS, 브라우저와 버전을 기록하고 미검증 조합도 별도로 적는다.
4. **실행·관찰**: 같은 시나리오를 수행하고 기능 성공 여부와 응답 시간을 별도 칸에 남긴다.
5. **판정 분리**: 합의된 기준이 있으면 적용한다. 없으면 관찰값으로 보고하고 판정을 유보한다.
6. **변경 후 재실행**: 같은 조건으로 반복하고 조건이 달라졌다면 차이를 기록한다.

## 기록 템플릿

```text
빌드 / 실행 일시:
시나리오 / 시작 조건 / 입력:
기대 완료 상태:
측정 시작 → 종료 / 측정 수단 / 단위:
기기 / OS / 브라우저 / 버전:
네트워크 등 실행 조건:
기능 결과 / 관찰 문제:
응답 시간 관찰값:
합의된 기준 / 기준 출처:
판정: 충족 / 미충족 / 기준 부재로 유보
미검증 환경 / 재현 절차:
```

네트워크 등 실행 조건 기록은 비교를 돕는 제안이다. 자료가 특정 조건을 규정하지는 않는다.

## 완료 점검

- [ ] 같은 시나리오로 환경을 비교할 수 있다.
- [ ] 시간의 시작·종료와 단위가 명확하다.
- [ ] 확인한 환경과 미검증 환경을 구분했다.
- [ ] 기능 성공을 속도 합격으로 해석하지 않았다.
- [ ] 기준이 없는 값을 임의로 합격 처리하지 않았다.
