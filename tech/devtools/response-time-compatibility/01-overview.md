# Overview: What / Why / 특징

## What

응답 속도 검증은 정의한 행동부터 결과까지의 시간을 관찰한다. 기기·브라우저 호환성 검증은 명시한 환경 조합에서 기능을 이용할 수 있는지 확인한다. 두 결과는 독립적으로 기록해야 한다.

## Why

Smoke testing으로 핵심 동작을 빠르게 확인해도 속도와 환경별 동작은 추가 검증 대상이다. 변경 이후에는 regression testing으로 기존 결과가 유지되는지 확인할 수 있다. 출시 판단은 고객·기획과 합의한 acceptance 기준에 연결해야 한다.

## 핵심 특징

| 검증 축 | 자료에서 확인되는 역할 | 실습에서 명시할 정보 |
|---|---|---|
| 응답 속도 | performance testing에서 응답 속도 측정 | 대상 행동, 시작·종료 지점, 관찰 시간 |
| 환경 호환성 | 기기·브라우저 간 호환성 확인 | 기기·브라우저 조합과 기능 범위 |
| 변경 이후 동작 | regression testing의 기존 기능 재점검 | 빌드와 이전 조건의 차이 |
| 출시 판단 | acceptance testing의 출시 준비 확인 | 합의된 기준과 판정 근거 |

오른쪽 열은 학습을 위한 구체화다. 영상이 이 기록 양식을 제공했다는 뜻은 아니다.

## 검증 구조

```text
사용 시나리오 → 기기·브라우저 조합
              → 기능 동작 확인 + 응답 시간 측정
              → 결과 비교 → 합의된 기준에 따른 판단
```

frontend/backend, 네트워크 경로, 자동화 환경, 결과 저장 방식은 자료에 없다. 따라서 여기서의 구조는 구현 아키텍처가 아니라 대상·환경·관찰·기준의 관계다.

## 해석의 경계

- 기능 성공과 응답 시간의 허용 여부는 별개다.
- 특정 환경의 문제를 발견해도 backend·기기·브라우저 중 원인을 바로 확정할 수 없다.
- 화면 표시와 기능 동작만으로 스크린 리더·큰 글자 지원을 검증했다고 볼 수 없다.
- 빠른 응답이 혼란 없는 사용 흐름이나 권한 통제·정보 보호를 입증하지 않는다.
