# Projects: 검증 결과를 검토 자료로 만들기

다음 프로젝트는 학습·적용 제안이다. 실제 서비스 결과나 영상의 실행 사례가 아니다.

## 프로젝트 1: 응답 속도·호환성 검증 매트릭스

하나의 핵심 기능에 대해 환경 조합별 행을 만든다.

| 기록 항목 | 목적 |
|---|---|
| 빌드·변경 식별 정보 | 검증 버전 구분 |
| 시나리오·기대 결과 | 환경별 비교 대상 고정 |
| 기기·OS·브라우저·버전 | 검증 범위 명시 |
| 측정 구간·수단·단위·관찰값 | 시간의 의미 보존 |
| 기능 성공 여부·문제 현상 | 동작과 속도 분리 |
| 판정 기준·판정 결과 | 관찰과 출시 판단 연결 |

**완료 산출물**: 환경별 결과표와 미검증 환경 목록. 지원 범위와 합격 기준이 없으면 “전체 호환성 확보”로 결론 내리지 않는다.

## 프로젝트 2: 변경 전후 regression 점검

동일한 시나리오와 환경 조합으로 변경 전후를 비교한다.

| 환경·시나리오 | 이전 빌드 기능·시간 | 이후 빌드 기능·시간 | 조건 차이 | 재현 정보 |
|---|---|---|---|---|
| 직접 기록 | 직접 기록 | 직접 기록 | 직접 기록 | 직접 기록 |

**완료 산출물**: 변화가 관찰된 조건과 재현 절차. 원인 확정은 추가 조사가 필요하다. 조건이 달라졌다면 변경 자체의 효과라고 단정하지 않는다.

## 프로젝트 3: 출시 검토용 QA 보고서

Smoke testing, 응답 속도, 환경 호환성, acceptance 기준을 연결한다. 사용 흐름·접근성·보안 결과는 별도 항목으로 둔다.

```text
대상 빌드 / 검증 시나리오:
Smoke testing 결과:
환경별 기능 결과:
응답 시간 정의와 관찰값:
Acceptance 기준과 충족 여부:
사용성 / 접근성 / 보안의 별도 검증 현황:
확인한 사실:
미검증 범위:
기준 부재로 판단을 유보한 항목:
추가 조사와 후속 검증:
```

**완료 산출물**: 각 결론을 관찰 조건과 기준으로 추적할 수 있는 보고서. 테스트 수행 사실만으로 출시 준비 완료를 선언하지 않는다.
