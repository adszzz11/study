# 심화: 컴포넌트·토큰과 재현성

## 세 관점 분리하기

| 관점 | 실습에서 묻는 질문 | 확보할 증거 |
|---|---|---|
| 디자인 | 해당 화면의 외형이 어떻게 달라졌나? | 동일 영역의 전후 화면 |
| 컴포넌트 | 재사용 요소 변경인가, 개별 요소 수정인가? | 요소와 컴포넌트의 대응 기록 |
| 토큰·변수 | 값만 바뀌었나, 기준과의 연결도 바뀌었나? | 값과 연결 관계의 별도 기록 |

자료에는 이 관점들이 등장하지만 구체적인 연결 구조는 설명되지 않는다. 토큰과 Figma 디자인 변수가 이 환경에서 동일한 개념으로 쓰이는지도 확인해야 한다.

## 대응표 실습

| 화면 요소 | 컴포넌트 | 토큰·변수 | 값 일치 | 연결 확인 | 다른 사용처 영향 |
|---|---|---|---|---|---|
| 선택한 요소 | 확인 후 기록 | 확인 후 기록 | 미확인 | 미확인 | 미확인 |

1. 한 요소의 색상 값과 참조 연결 여부를 따로 조사한다.
2. 같은 컴포넌트를 쓰는 다른 위치가 있다면 함께 확인한다.
3. 화면만 보고 전역 변경이 완료되었다고 결론 내리지 않는다.

## 재현성 검토 제안

명령 환경을 확보한 뒤에만 진행한다. 대상 프로토타입 상태, 참조 디자인 상태, 명령, 실행 환경과 결과를 기록한다. 가능한 경우 같은 초기 상태의 복제본에서 반복하고, 미적용 항목과 실행별 차이를 비교한다. 이미 변경된 화면에 다시 실행한 결과만으로 같은 조건의 재현성을 판단하지 않는다.

## 성공 판단의 경계

명시한 범위의 속성과 전후 화면이 대응하면 그 범위의 검토 결과를 기록할 수 있다. 이것만으로 코드 생성, 배포, 접근성 검증 또는 전체 화면으로의 전파가 완료되었다고 말할 수는 없다.
