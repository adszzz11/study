# 시작하기: 범위와 비교 기준 정하기

## 실습 전제

이 절은 관찰 요소를 바탕으로 만든 **실습 제안**이다. 실행 제품과 설치 절차가 없어 명령 실행을 보장하지 않는다. 명령 환경이 없어도 수동 비교 기록은 작성할 수 있다.

## 준비물

- 검토할 예약 캘린더 등 구체적인 프로토타입과 변경 전 화면.
- 사용자가 접근할 수 있는 Figma 참조 URL 및 참조 화면·영역 설명.
- 비교표를 기록할 문서와 적용 성공 기준.

## 순서

1. **대상 지정:** 논의할 영역과 실제 변경할 영역을 따로 기록한다.
2. **참조 확인:** URL이 가리키는 디자인과 사용 환경에서 읽을 수 있는 범위를 확인한다.
3. **기준 분리:** 색상 코드, 텍스트 스타일, 디자인 변수를 개별 항목으로 작성한다.
4. **환경 확인 후 요청:** 지원 제품에서만 명령을 시도한다. 아래 입력은 dossier를 옮긴 형식 예시다.
5. **결과 기록:** 속성 비교와 전후 화면을 대응시키고, 미변경·미확인 항목을 남긴다.

```text
/apply-ds-to-prototype <Figma 디자인 URL>
```

위 표기는 설치 명령이나 검증된 실행 구문이 아니다. 실제 Figma URL은 제공되지 않았다.

## 비교표 템플릿

| 화면 요소 | 항목 | 참조 기준 | 적용 전 | 적용 후 | 판정·근거 |
|---|---|---|---|---|---|
| 선택 날짜 셀 | 색상 코드 | 직접 확인 | 직접 확인 | 직접 확인 | 일치/불일치/미확인 |
| 날짜 라벨 | 텍스트 스타일 | 직접 확인 | 직접 확인 | 직접 확인 | 일치/불일치/미확인 |
| 선택 상태 | 디자인 변수 | 직접 확인 | 직접 확인 | 직접 확인 | 연결 여부 별도 확인 |

예시 요소명은 실습용이며 실제 MeetBook 속성값을 뜻하지 않는다. 한 항목의 일치를 다른 항목의 일치로 확대하지 않는다.

## 완료 기준

- [ ] 대상과 참조 범위를 기록했다.
- [ ] 세 종류의 속성을 각각 비교했다.
- [ ] 속성 변화와 전후 화면을 대응시켰다.
- [ ] 불일치·미확인 항목을 후속 검토로 남겼다.
