# Projects: 실전 적용 검토

아래 프로젝트는 후속 검증 제안이다. 영상에서 이미 완료되거나 검증된 작업으로 해석하지 않는다.

## 1. 예약 캘린더 디자인 시스템 적용 검토

- **목표:** MeetBook 사례와 같은 예약 화면에서 적용 범위를 명확히 한다.
- **작업:** 대상 영역과 참조 URL을 정하고 색상·텍스트 스타일·디자인 변수를 비교한다.
- **산출물:** 대상 화면, 참조 URL과 범위, 속성 비교표, 전후 화면, 미해결 목록.
- **완료 기준:** 범위 내 각 항목의 판정과 화면 증거가 연결되어 있다. 미확인 항목은 별도로 남긴다.

## 2. 디자인·컴포넌트·토큰 대응표

- **목표:** 외형 변화와 재사용 기준의 변화를 구분한다.
- **작업:** 화면 요소별 컴포넌트·토큰 후보를 조사하고 값과 연결 여부를 따로 기록한다.
- **산출물:** 요소 → 컴포넌트 → 토큰 대응표, 연결 근거, 다른 사용처 확인 기록.
- **완료 기준:** 확인한 연결과 미확인 연결이 구분된다. 자동 매핑 기능을 전제하지 않는다.

## 3. 명령 기반 적용 흐름의 재현성 검토

- **전제:** 명령을 지원하는 실행 환경이 확보되어야 한다.
- **목표:** 같은 초기 조건에서 결과가 일관되는지 조사한다.
- **작업:** 초기 프로토타입, 참조 상태, 입력 명령, 환경, 결과를 실행별로 기록한다.
- **산출물:** 실행 기록, 결과 비교표, 반복되는 미적용 항목 및 차이 목록.
- **완료 기준:** 반복 조건과 결과의 차이를 설명할 수 있다. 일관되지 않은 결과도 유효한 검증 산출물이다.

## 공통 검토 기준

- [ ] 명시한 범위의 속성 비교 결과와 전후 화면을 대응시켰다.
- [ ] 적용 완료와 검토 완료를 구분했다.
- [ ] 코드·배포·접근성·전체 변경 전파는 별도 검증 사항으로 남겼다.
