# Overview: What / Why / 특징

## What

Figma URL로 디자인 참조를 제시하고, 프로토타입의 속성과 전후 화면을 검토하는 작업 흐름이다. `/apply-ds-to-prototype`은 수집 자료에 등장한 명령 이름이며, Figma 공식 명령인지 특정 도구의 custom workflow인지는 확인되지 않았다.

## Why

MeetBook 예약 캘린더를 보고 특정 영역을 강조하며 빠르게 논의하는 장면이 출발점이다. 화면은 전달받은 결과물이자 후속 수정 대상이다. **화면 생성 완료와 디자인 시스템 준수는 별도의 판단**이므로, 시각적 인상 외에 구체적인 속성 비교가 필요하다.

## 특징과 작업 모델

| 단계 | dossier에서 확인되는 내용 | 확인 한계 |
|---|---|---|
| 대상 제시 | MeetBook 예약 캘린더 | 다른 화면 지원 여부 불명 |
| 논의 범위 | 특정 영역 강조, 빠른 논의 자막 | 실제 변경 범위 지정 기능 불명 |
| 적용 요청 | 명령과 Figma 디자인 URL 입력 | 실행 제품·권한·연동 방식 불명 |
| 기준 비교 | 색상 코드·텍스트 스타일·디자인 변수 표 | 비교표 생성 방식·누락 탐지 불명 |
| 결과 검토 | 디자인·컴포넌트·토큰 항목과 전후 탭 | 상세 기능·자동 연결 불명 |

```text
대상 프로토타입 → 명령·참조 링크 입력 → 속성 비교 → 전후 검토
```

이는 관찰을 재구성한 작업 모델이며, 내부 모듈이나 데이터 처리 순서를 확정한 아키텍처가 아니다.

## 해석할 때 구분할 것

- 참조 지정 ≠ 데이터 취득: URL만으로 API, plugin, MCP 사용을 추정하지 않는다.
- 속성 비교 ≠ 변경 실행: 차이가 표에 있다고 모든 차이가 자동 수정된 것은 아니다.
- 화면 변화 ≠ 시스템 일관성: 재사용 컴포넌트·토큰의 변경 전파는 별도 검증한다.
- 명령 이름 ≠ 공식 제품 기능: 지원 환경부터 확인해야 한다.
