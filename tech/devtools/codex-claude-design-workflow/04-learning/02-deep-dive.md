# 심화 학습: 재현성과 동일 조건 비교

## 시작 조건

실제 복사 원문, 요청문, 프로젝트 기준 상태와 실행 방법이 확보되어야 한다. 현재 dossier에는 복사 원문과 실행 결과가 없으므로 이 노트는 후속 실험 설계다.

## 단일 요소 재현

1. 버튼 또는 카드처럼 범위가 좁은 요소 하나를 고른다.
2. 입력 원문과 요구사항에 버전을 부여하고 원본을 보관한다.
3. 프로젝트 기준 상태, 도구·모델·설정과 실행일을 기록한다.
4. 확보한 입력과 요청을 전달하고 실제 실행 절차·오류를 기록한다.
5. 결과를 확인하고 수동 수정 전후를 구분해 남긴다.
6. 동일 입력으로 다시 시작할 수 있는지 점검한다.

특정 설치 명령이나 dependencies는 자료에 없으므로 여기서 임의로 지정하지 않는다.

## 시각과 동작을 분리한 검증

| 축 | 확인 항목 | 기록할 증거 |
|---|---|---|
| 정지 화면 | 형태·배치·색상·크기 요구 | 같은 viewport의 screenshot, 차이 설명 |
| 상호작용 | 명세에 적힌 click·hover 등의 동작 | 실행 단계와 관찰 결과 |
| 동적 표현 | 움직임·전환과 정지 상태 | 동작 기록, 기대와 실제 차이 |
| 실행 재현 | 필요한 환경과 실행 절차 | 실행 기록·오류·수정 내역 |

click·hover는 검증 설계 예시이며 영상에서 확인한 동작이 아니다. 애니메이션 배경의 정지 화면이 비슷하다는 것만으로 실제 동작을 통과 처리하지 않는다.

## Codex·Claude Code 비교

같은 프로젝트 기준 상태에서 각각 시작하고 동일 입력과 요청을 사용한다. 환경·설정 차이를 숨기지 않고 기록한다. 사전에 정한 요구 충족 기준을 적용하고 수동 수정 내역과 소요 시간을 남긴다. 결과 해석은 해당 조건과 실험 범위로 제한한다.

```text
실험 ID / 날짜:
도구 / 모델 / 버전 / 설정:
프로젝트 기준 상태 / 실행 환경:
입력 및 요청 버전:
실제 실행 절차:
수정 전 결과:
시각 확인 / 동작 확인:
오류 및 수동 수정:
수정 후 결과:
재시작 방법:
관찰의 한계:
```
