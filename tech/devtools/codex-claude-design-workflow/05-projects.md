# Projects: 명세·재현·비교

## 1. 디자인 전달 명세

- **과제**: 영상에서 언급된 요소 하나를 골라 관찰한 형태, 필요한 동작, 확보된 입력, 미확인 사항을 정리한다.
- **목적**: 시각적 참고로 확정할 수 있는 요구와 추가 정보가 필요한 요구를 분리한다.
- **산출물**: 전달 명세 한 건.
- **완료 기준**: 구현자가 임의로 결정해야 하는 부분이 명시되어 있다.
- **착수 조건**: 현재 dossier로 초안을 작성할 수 있다. 정확한 외형 명세에는 원본 시각 자료가 추가로 필요하다.

초안 예시: 책 형태 카드가 관찰되었다. 크기·색상·상호작용·입력 형식은 미확인이다. 이 항목을 확인하기 전에는 component 복제를 요구사항으로 확정하지 않는다.

## 2. 붙여넣기 workflow 재현 기록

- **과제**: 실제 복사 내용을 확보한 뒤 Codex 또는 Claude Code에 전달하는 과정을 기록한다.
- **목적**: 생략된 전달·구현 단계를 재현 가능한 절차로 구체화한다.
- **산출물**: 입력 원문, 요청문, 실행 환경, 결과물, 수정 내역.
- **완료 기준**: 같은 입력으로 작업을 다시 시작할 수 있다.
- **현재 제한**: 복사 원문이 없어 실행 단계까지 재현할 수 없다.

## 3. Codex·Claude Code 비교 실험

- **과제**: 확보된 동일 입력과 요구사항으로 두 도구의 결과를 비교한다.
- **목적**: 같은 활용 문맥에서 언급된 두 도구의 실제 차이를 관찰한다.
- **산출물**: 요구 충족, 시각·동작 확인, 수동 수정 내역을 정리한 비교표.
- **완료 기준**: 평가 조건과 관찰 결과가 함께 기록되어 있다.
- **현재 제한**: 후속 검증 제안이며, dossier에는 실험 결과가 없다.

## 진행 순서

전달 명세 → 입력·환경 확보 → 단일 도구 재현 → 동일 조건 비교. 미확인 항목을 추정값으로 채워 완료 처리하지 않는다.
