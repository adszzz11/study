# The Pragmatic Engineer

> **한 줄 정의**: The Pragmatic Engineer는 Big Tech·startup의 실제 engineering practice와 AI-era 개발 동향을 심층 취재하는 software/AI engineering intelligence newsletter·podcast다.

## Overview

Gergely Orosz가 운영하는 이 매체는 vendor 발표나 일반 기술 뉴스만으로 판단하기 어려운 현업의 신호를 인터뷰, 사례 분석, market signal로 엮는다. 제품 SDK나 framework가 아니라 **engineering 의사결정을 위한 research media**로 읽는 것이 알맞다.

- 2025년 자체 회고에 따르면 134개 edition을 발행했고, 연말 독자는 약 107만 명이었다.
- 주요 관찰 주제는 AI coding agent, AI engineering, developer tooling, code review, hiring·career, reliability/infra다.
- 무료 독자는 일부 Deepdive와 podcast를, 유료 독자는 전체 Deepdive·The Pulse·리소스/템플릿을 이용한다. 공개 가격은 월 $15 또는 연 $150이다.

자세한 배경과 읽는 법은 [[tech/devtools/the-pragramitic-engineer/01-overview|Overview]]에서, 대안 매체와의 역할 차이는 [[tech/devtools/the-pragramitic-engineer/02-ecosystem|Ecosystem]]에서 다룬다.

## When To Use

- AI coding, developer tooling, reliability, engineering management의 현업 사례를 맥락과 함께 파악할 때
- vendor의 1차 발표를 독립적 사례 분석 및 팀 영향과 함께 해석할 때
- 도구 도입 전 test, security, human accountability, metrics를 포함한 정책을 설계할 때
- 매주 팀에 중요한 industry signal을 짧은 brief로 정리할 때

## When Not To Use

- API spec, 가격, 지원 범위처럼 정확한 제품 사실이 필요할 때: vendor 공식 문서를 먼저 확인한다.
- 즉시 해결할 code-level 문제를 찾을 때: 공식 문서, issue tracker, Stack Overflow 같은 문제 해결 채널이 더 알맞다.
- 한 저자·매체의 관점을 곧바로 일반 법칙이나 조직 정책으로 채택하려 할 때: 조직 조건과 내부 지표로 검증한다.
- 최신성에 민감한 결정을 archive 글 하나에만 의존해 내려 할 때: 발행일과 후속 1차 소스를 함께 확인한다.
