# Overview: 부분 결과 출력

## What

부분 결과(partial result)는 음성 입력이 진행되는 동안 먼저 표시되는 인식 결과다. 최종 결과(final result)는 녹음 종료와 잔여 처리 이후의 전사다. **먼저 표시됨이 곧 확정됨을 뜻하지는 않는다.** Lightning-SimulWhisper의 확정 기준과 수정 가능 범위는 제공 자료에서 확인되지 않는다.

## Why

녹음 종료 후 일괄 변환에서는 발화 중 텍스트를 확인할 수 없다. 부분 결과는 확인 시점을 앞당겨 받아쓰기 상태를 살펴볼 수 있게 한다. 그러나 빨리 표시된 문구가 계속 바뀐다면 읽기 부담이 생기므로 속도와 안정성을 함께 평가해야 한다.

## 특징과 확인 범위

| 구성 | 자료의 설명 | 미확인 사항 |
|---|---|---|
| 입력 | 마이크·녹음 파일 | 형식, 분할 단위, 파일의 실시간 재생 여부 |
| 처리 위치 | 녹음을 서버에 보내지 않고 Mac 내부 처리 | 전체 네트워크 동작, 저장·로그 정책 |
| 실행 환경 | Mac 전용, M2 Neural Engine 강조 | 지원 기종, 연산별 실행 장치 |
| 모델 | tiny~large 선택 | 모델별 정확도·메모리·지연 |
| 출력 | 확실한 부분 우선 출력 | 확정 기준, 갱신 주기, 수정 정책 |
| 언어 | 한국어, 자동 언어 감지 | 언어별 품질, 혼합 언어 동작 |
| 보조 기능 | 단어 경계 유지, 후보 비교, 용어 사전 | 알고리즘과 적용 단계 |
| 무음 | 무음 건너뛰기 | 무음 기준, 발화 시작·종료 처리 |

## 기능적 흐름

```text
마이크·파일 입력 → Mac 내부 음성 처리 → 인식 결과 판단
                                      ↓
                           확실한 부분 우선 출력
                                      ↓
                              후속 음성 처리 지속
```

설명을 위한 기능적 구성이다. 실제 내부 모듈이나 구현을 확인한 아키텍처가 아니다.

- 출력 시점: 어느 정도 입력을 확보한 뒤 보여주는가?
- 확정 범위: 어디까지 안정된 결과로 취급하는가?
- 수정 범위: 후속 음성으로 해석이 바뀌면 기존 문구를 어떻게 갱신하는가?
- 경계 처리: 입력 구간에 걸친 단어와 끊긴 발화를 어떻게 잇는가?
- 종료 처리: 아직 표시하지 않은 내용을 어떻게 마무리하는가?

단어 경계 유지와 후보 비교가 확정 여부를 직접 결정하는지, 무음이 문장 확정 신호인지도 확인되지 않는다.

## 평가 관점

| 항목 | 관찰할 질문 |
|---|---|
| 최초 출력 지연 | 발화 시작 후 첫 텍스트가 언제 나타나는가? |
| 후속 출력 지연 | 이어지는 말이 얼마나 늦게 반영되는가? |
| 결과 안정성 | 앞서 출력한 문구가 얼마나 수정되는가? |
| 종료 후 지연 | 녹음 종료 후 최종 전사까지 얼마나 걸리는가? |
| 최종 정확성 | 최종 전사가 실제 발화와 얼마나 일치하는가? |

위 항목은 평가 제안이며 제공된 측정값이 아니다. 최대 18배·15배 주장을 출력 지연이나 전체 처리 속도의 검증된 개선율로 해석하지 않는다.
