# Projects: 관찰에서 적용까지

## 1. 한국어 받아쓰기의 부분 결과 품질 평가

- 입력: 짧은 문장, 긴 문장, 전문용어, 중간 멈춤을 포함한 테스트 녹음과 기준 전사.
- 실행: 같은 환경에서 모델별로 반복하고 첫 출력 시간, 수정 이벤트와 범위, 종료 후 지연, 최종 오류를 기록한다.
- 산출물: 실행 조건 표, 중간 출력 변화 기록, 모델별 관찰 결과.
- 완료 기준: 속도와 안정성을 함께 설명하고 미측정 항목을 명시한다.

목표는 “얼마나 빨리 나오나”와 “얼마나 믿고 읽을 수 있나”를 함께 평가하는 것이다. 비교 기준이 없는 영상 속 배속 주장의 재현은 목표에서 분리한다.

## 2. 전문용어 중심의 로컬 받아쓰기

- 준비: 사용할 분야의 용어 목록과 용어가 포함된 발화.
- 실행: 사전 형식과 적용 방법을 별도로 확인한 뒤 적용 전후를 같은 입력으로 비교한다.
- 산출물: 최종 인식 오류와 부분 결과의 오인식·수정 기록.
- 완료 기준: 사전 적용 효과를 관찰값으로 설명하고 효과가 없는 사례도 남긴다.

자료는 사전 기능의 존재만 소개한다. 등록 형식, 반영 단계, 효과는 확인이 필요하다.

## 3. 실시간 전사 화면의 상태 표현 설계

임시 출력과 확정 출력을 구분하는 UI 시안을 만들고, 기존 문구가 바뀔 때 사용자가 변화를 알아차릴 수 있는지 검토한다.

- 산출물: 상태별 표시 규칙, 수정 전후 화면 예시, 종료 처리 규칙.
- 시작 조건: 실제 연동을 한다면 API·출력 형식·확정 상태 제공 여부부터 확인한다.
- 완료 기준: 확정 신호가 없을 때 이를 임의로 생성하지 않고 상태 미확인을 드러낸다.

이는 적용 아이디어다. Lightning-SimulWhisper가 해당 API나 UI를 이미 제공한다는 뜻은 아니다. 연동이 확인되지 않으면 모의 데이터로 시안을 평가한다.
