# Projects: 검증 가능한 산출물 만들기

## 프로젝트 1: 커리큘럼의 기술 명세화

- **착수 조건:** 공식 실습 안내와 코드 확보. 현재 자료만으로 구현을 시작할 수 없다.
- **작업:** 문제 정의, 데이터, 모델 구조, 학습 범위, Loss, 평가 방식과 실행 환경을 정리한다.
- **산출물:** 한 장의 명세, 실행 절차, 근거 위치 목록.
- **완료 기준:** 제3자가 같은 조건으로 실습을 실행할 수 있고, 사용한 버전·설정·평가 기준을 확인할 수 있다.

## 프로젝트 2: 소개 논문과 교육 항목의 연결 검증

- **착수 조건:** 폐 기능 관련 논문 또는 perturbation signatures 기반 검색 논문의 정확한 식별 정보와 본문 확보.
- **작업:** 실제 방법·학습 경계를 읽고 공식 커리큘럼·실습 자료와 대조한다.
- **산출물:** 주장별 근거 표. 논문의 기술 방식과 교육 실습 대상 여부를 별도로 기록한다.
- **완료 기준:** 각 연결 주장에 직접 근거를 제시하거나, 근거 부족으로 미확인임을 명시한다. 조사 범위가 제한되면 그 한계도 기록한다.

| 검증할 주장 | 필요한 근거 | 현재 상태 |
|---|---|---|
| 논문이 End-to-End 학습을 사용한다 | 본문 방법·코드의 학습 경계 | 미확인 |
| 해당 논문이 실습 대상이다 | 공식 안내의 명시적 연결 | 미확인 |
| 논문 결과가 실습에서도 재현된다 | 동일 조건의 실행·평가 로그 | 미확인 |

## 프로젝트 3: 실습 결과의 근거 기록

- **착수 조건:** 실행 가능한 실습과 데이터 이용 조건 확보.
- **작업:** 설정·환경·데이터 분할·평가 결과·실패 사례를 함께 기록한다.
- **산출물:** 실행 로그, 결과 표, 재현 절차, 제한 사항.
- **완료 기준:** 보고한 수치를 실행 근거로 추적할 수 있고, 재현 실패와 미측정 항목도 공개한다.

논문 채택이나 취업 성과를 모델의 기술적 성능으로 보고하지 않는다. 측정하지 않은 성과를 프로젝트 결과에 추가하지 않는다.

## 권장 순서

프로젝트 1에서 실습의 기술 범위를 정한 뒤 프로젝트 3으로 검증한다. 프로젝트 2는 논문 식별 정보가 확보되면 별도로 진행할 수 있다.
