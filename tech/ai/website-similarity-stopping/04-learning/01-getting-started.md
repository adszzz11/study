# 시작하기: 평가 계약과 기록

## 1. 비교 대상을 정의한다

Reference 하나와 평가할 페이지·상태를 정한다. Screenshot 외형 평가와 기능 검사를 별도로 둔다. Metric이 없다면 점수를 만들어 넣지 말고 평가 방식 미정으로 기록한다.

## 2. 평가 환경을 고정한다

같은 viewport, 브라우저 조건, 페이지 상태, 폰트·이미지 로딩 조건으로 비교한다. 환경 변화와 구현 변화의 영향을 분리하기 위한 실습 제안이다.

## 3. 실습용 정책을 선언한다

- 점수 범위: 0~1, 목표: 0.90 이상
- 한 라운드: Build와 Check 한 쌍, 최초 Build 포함
- 최대 6라운드, 6번째에도 목표를 확인
- 동시 충족 시 목표 달성을 종료 이유로 우선 기록
- 평가 실패는 0점과 구분하고 실습을 중단해 원인을 확인

이는 실습에서 정한 계약이며 제품 구현 사실이 아니다.

## 4. 라운드 로그를 남긴다

```json
{
  "round": 1,
  "score": 0.72,
  "changes": ["header spacing"],
  "functional_check": "pass",
  "stop_reason": null
}
```

`score: null`은 평가 실패·미실시를 뜻하도록 별도 정의한다. 검사 실패 원인을 기록하고 유효 점수처럼 비교하지 않는다. 기능 실패는 외형 점수 통과로 덮지 않는다.

## 5. 확인한다

- 89%는 목표 미달, 90%와 91%는 목표 달성인가?
- 5라운드 미달은 계속하고 6라운드 미달은 한도로 멈추는가?
- 최종 결과와 최고 점수 결과가 다를 때 반환 대상을 알 수 있는가?
