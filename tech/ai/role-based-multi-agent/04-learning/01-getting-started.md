# 시작하기: 근거 제한형 순차 workflow

## 목표와 준비

제공된 dossier만으로 역할 협업을 설명하는 짧은 브리프를 만든다. 제품 자동화 기능은 필요하지 않다. 사람이 각 agent에 입력을 주고 결과를 전달해도 된다. 이는 역할 분리 연습이며 제품 간 자동 연동의 검증은 아니다.

- 입력: 동일한 dossier, 설명 대상 독자, 결과물 길이와 형식.
- 역할: Researcher → Writer → Reviewer.
- 예시 종료 조건: 근거 없는 확정 주장 0개, 사람의 최종 승인.
- 예시 반복 제한: 검토·수정 최대 2회. 미해결 항목은 남겨 사람에게 전달한다.

## 1. 공통 지시

```text
제공 자료만 사용하라. 자료에 없는 사실은 미확인으로 표시하라.
관찰 사실, 설계적 해석, 실습 제안을 구분하라.
자동 협업, shared memory, 성능 향상을 추정해 확정하지 마라.
```

## 2. Researcher: 근거 장부

| ID | 주장 | 근거 문장 | 확인 수준 | 미확인 사항 |
|---|---|---|---|---|
| E01 | Hermes에 연구자·작성자·검토자 역할이 등장 | dossier의 역할 설명 | 자료상 관찰 | 실행 순서·전달 형식 |
| E02 | Hermes에 메모리 설정이 등장 | dossier의 설정 설명 | 자료상 관찰 | 공유 여부·보존 기간 |

```text
Researcher: 주장마다 근거 문장과 ID를 붙여라.
역할의 존재와 실제 동작을 구분하고 미확인 사항을 별도 기록하라.
```

## 3. Writer: 초안

```text
Writer: 근거 장부로 짧은 브리프를 작성하라.
제품 관련 주장에는 근거 ID를 연결하라.
추가 workflow 아이디어는 '설계 제안'으로 표시하라.
```

원자료와 장부를 함께 전달한다. E02에서 '공유 메모리를 지원한다'는 문장을 도출하면 근거 범위를 벗어난다.

## 4. Reviewer: 대조와 반환

```text
Reviewer: 원자료, 장부, 초안을 대조하라.
근거 없는 주장 / 누락 / 관찰을 기능으로 과장한 문장을 찾아라.
각 문제의 위치, 근거 ID, 수정 요청, 재검토 필요 여부를 반환하라.
```

- '같은 화면에 보임'이 '자동 연동됨'으로 바뀌었는가?
- '메모리 설정'이 'shared memory'로 바뀌었는가?
- 실습 제안이 실제 제품 기능처럼 쓰였는가?

## 5. 수정과 완료

Writer가 수정하고 Reviewer가 재검토한다. 한도를 넘으면 미해결 목록과 함께 사람에게 넘긴다. 장부·초안·검토 기록·최종본을 보관하면 어느 handoff에서 정보가 바뀌었는지 확인할 수 있다.
