# Projects: 검증 가능한 선택 기록

아래 프로젝트는 앞으로 수행할 실습 설계다. 실제 측정 결과나 권장 모델을 제시하지 않는다.

## 1. 용량·성능 비교 기록표

- 목적: 작은 파일이라는 이유만으로 선택하지 않고 목표 업무 품질과 함께 비교한다.
- 준비: 식별 가능한 모델, 배포 파일 목록, 평가 과제와 기준.
- 산출물: 아래 표와 원자료·측정 로그.

| 모델/revision | Parameters | 저장 표현 | 파일 범위·bytes | 환경·설정 | 코딩 결과 | 출처 |
|---|---|---|---|---|---|---|
| 미확인 | 미확인 | 미확인 | 미확인 | 미확인 | 미측정 | 미제공 |

완료 기준: 출처와 측정 기준이 없는 값은 비교에서 보류하고, 모든 비교 행에 같은 평가 조건을 적용한다.

## 2. 노트북 실행 검증

- 준비: 모델 식별자와 라이선스, 장치 사양, 지원 런타임 확인.
- 절차: 파일 확보 → 로딩 → 응답 생성 → 목표 코딩 작업 평가.
- 산출물: 장치·설정·peak memory·지연·오류·성공 단계 기록.
- 완료 기준: 성공과 실패를 단계별로 재현할 수 있다. 로딩 성공만으로 업무 적합 판정을 내리지 않는다.

현재 자료만으로 특정 노트북의 실행 보장이나 권장 사양을 제시할 수 없다.

## 3. 회사 문서 처리 경로 검토

- 준비: 실제 회사 문서 대신 합성 문서로 흐름을 먼저 점검한다.
- 절차: 입력·전처리·추론·로그·결과 저장 위치와 외부 호출을 표시한다.
- 비교: 로컬 구성과 클라우드 구성의 품질, 비용, 보관 정책, 운영 조건.
- 산출물: 데이터 흐름도와 단계별 확인 근거.
- 완료 기준: “로컬”이라는 명칭이 아니라 실제 구성과 조직의 사용 조건으로 적용 여부를 판단한다.
