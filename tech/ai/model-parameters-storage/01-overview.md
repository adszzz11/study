# Overview: Parameters와 저장 용량

## What

Parameters는 모델 내부에서 사용하는 값이며, 파라미터 수는 그 값의 개수다. 파일 크기는 그 값을 어떤 형식으로 저장하고 어떤 파일들을 포함했는지에 따라 달라진다. 둘은 같은 단위가 아니다.

| 항목 | 확인할 질문 | dossier의 상태 |
|---|---|---|
| Parameters | 몇 개의 값을 갖는가? | 수 미제공 |
| 저장 표현 | 값당 표현과 부가 정보는 무엇인가? | 세 가지 값 사용 설명만 있음 |
| 배포 크기 | 가중치만인가, 전체 파일인가? | 범위 미확인 |
| 실행 메모리 | 어떤 설정에서 얼마나 사용하는가? | 측정 없음 |
| 코딩 품질 | 어떤 문제를 어떤 기준으로 풀었는가? | 평가 조건·결과 확인 어려움 |

## Why

작은 파일은 저장·전송 부담을 줄일 가능성이 있지만, 코딩 성능이나 특정 장치 실행을 보장하지 않는다. 용량 차이를 파라미터 수 차이로 바꾸어 읽으면 모델 선택의 근거가 틀어질 수 있다.

## 특징과 해석 경계

1. **용량 감소의 원인은 미확인이다.** 파라미터 수 감소, 표현 방식 변화, 비교 파일 범위 차이를 구분해야 한다. Quantization이나 Pruning 적용을 지목할 수 없다.
2. **세 가지 값과 저장 규격은 다르다.** 실제 값 집합, 적용 대상, packing 및 부가 정보가 없다. 특정 ternary 구현이나 bit-width를 확정하지 않는다.
3. **수치의 관계를 보류한다.** 약 54GB와 3.6GB는 같은 기준일 때만 15배다. 5.9GB는 독립적인 미확인 표기다.
4. **품질과 실행을 따로 검증한다.** 코딩 평가에는 모델·문제·환경·지표가, 실행 검증에는 장치·런타임·설정·측정이 필요하다.
5. **가중치 공개와 실행은 별개다.** Apache 2.0 언급만으로 모델 정체나 모든 배포물의 적용 범위를 확정할 수 없다.

## 일반 개념: 정적 크기와 실행 자원

일반적으로 가중치 외에도 런타임 버퍼, activations, KV cache 등이 실행 메모리에 영향을 준다. 따라서 디스크 파일 크기를 RAM/VRAM 요구량으로 그대로 대입할 수 없다. 이는 보충 개념이며 해당 영상 모델의 메모리 측정 결과가 아니다.
