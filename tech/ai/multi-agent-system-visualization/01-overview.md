# Overview: 화면이 보여주는 것과 증명하지 못하는 것

## What

여러 Agent의 이름·배치·상태를 하나의 화면에 모으는 구성 시각화다. 제공 요약에서는 중앙 JEV 노드 주변의 Agent와 지표가 변화한다. 이름이 붙은 Node는 시각 요소이며, 그 자체로 실행 가능한 Agent의 존재를 보장하지 않는다.

## Why

구성 요소를 빠르게 파악하고 관심 대상을 선택하는 출발점으로 유용하다. 그러나 활동하는 듯한 화면만으로 작업 수행, 메시지 교환, 결과 품질을 구분하기 어렵다. 운영 판단에는 화면 상태를 계산한 근거가 필요하다.

## 특징과 확인 한계

| 요소 | 요약에서 관찰·언급된 내용 | 확인되지 않는 내용 |
|---|---|---|
| 중앙 JEV | 화면 중앙 배치 | Orchestrator인지, UI 중심인지, 실제 기능 |
| 주변 Agent | 이름이 붙은 여러 노드 | 역할, 입력·출력, 권한, 독립 실행 여부 |
| Claude | 홍보 문구에 등장 | 호출 방식, 모델 구성, Agent별 사용 범위 |
| 37개 팀 | 홍보 문구에 명시 | 전체 목록, 실제 인스턴스 수, 동시 실행 수 |
| 지표 패널 | 수치·진행 막대 증가 | 단위, 계산식, 데이터 출처, 실행 연동 |
| 노드 재배치 | 이후 화면에서 위치 변화 | Layout 변경인지, 역할·관계 변경인지 |
| 업무 환경 | 사람이 브라우저·코드 화면을 봄 | 해당 화면과 Agent 실행 사이의 관계 |

중앙 집중형 구성처럼 **보이지만**, 제어 흐름이 중앙을 통과하는지는 알 수 없다. Hub-and-spoke는 실행 관계가 확인된 뒤 붙일 아키텍처 명칭이다.

## 세 층의 증거

| 층 | 답할 질문 | 필요한 근거 | 현재 자료 |
|---|---|---|---|
| 구성 표현 | 무엇이 어디에 표시되는가? | 화면·범례 | 영상 요약으로 확인 |
| 실행 증거 | 어떤 작업·메시지가 오갔는가? | Task 기록, 호출·메시지 Trace | 미제공 |
| 성과 증거 | 요구사항을 충족했는가? | 산출물, 검증 기준·결과, 업무 사용 기록 | 미제공 |

“37개 Agent가 회사 전체를 운영한다”는 주장은 두 번째·세 번째 층의 증거가 필요하다. 자료의 부재는 실패의 증거도 아니며, 현재 판단은 **미확인**이다.
