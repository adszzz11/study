# Projects: 검증 가능한 시각화 만들기

아래는 설계·학습 과제다. 제공 영상에 이미 구현된 기능이나 검증된 성과가 아니다.

## 1. 근거가 연결된 Agent Dashboard

- 범위: 3개 Agent와 제한 Task 하나로 시작한다.
- 구현: Agent 선택 → 담당 Task → 최근 실행 기록 → 산출물 버전 → 검증 결과를 연결한다.
- 데이터: 먼저 합성 데이터를 사용하고, 실제 실행을 붙일 때 데이터 종류를 구분한다.
- 미확인 처리: 기록이 없는 값은 “미확인”, 실행 실패와 검증 실패는 별도 상태로 표시한다.
- 산출물: 화면, 이벤트 표, 지표 정의서, 검증 보고.
- 완료 기준: 모든 표시 상태에서 원천 기록과 계산 규칙을 찾을 수 있고, 기록이 없는 항목은 성공으로 표시되지 않는다.

## 2. Layout 변경과 실행 변경의 비교 도구

- 범위: 같은 실행에 원형·격자 Layout을 적용하고, 별도 실행에서 Task 의존 관계를 변경한다.
- 구현: 좌표 변경과 의존 관계 변경을 별도 조작으로 제공한다.
- 평가: 참여자에게 어떤 변경이 실행 구조를 바꿨는지 설명하도록 한다.
- 산출물: 두 Layout, 두 실행의 dependency 표·Trace, 참여자의 판정과 오판 이유.
- 완료 기준: Layout 변경은 Task·Trace·Metric을 바꾸지 않고, 실행 변경은 별도 Run과 근거로 구별된다. 사용자 판별 결과와 혼동 원인도 보고한다.

## 3. ‘회사 운영’ 주장 검증용 제한 업무 사례

- 범위: 회사 전체 대신 “내부 문서 한 개의 검토용 요약”처럼 작은 업무를 고른다.
- 사전 정의: 입력 버전, 단계별 책임·권한, 승인 지점, 최종 산출물, 성공 조건을 기록한다.
- 성공 조건 예시: 필수 항목을 모두 포함하고, 사실 문장마다 근거가 있으며, 사람이 최종 승인한다.
- 실행: 성공뿐 아니라 실패, 재시도, 수정, 사람의 개입 시간도 남긴다.
- 산출물: Task 기록, 입력·출력 버전, 검증 보고, 승인 기록, 실패 분석.
- 완료 기준: 지정된 업무의 성공 여부를 사전 기준으로 판정할 수 있다. 실패도 유효한 실험 결과다.
