# 시작하기: 작은 그래프와 근거 추적

## 목표와 준비

파일 2개, 출력물 1개, 엔터티 3개로 관계 의미를 정의하고 원문으로 되돌아간다. 종이·표·로컬 노트로 수행할 수 있는 설계 연습이며 Orbit Agents 설치나 기능 재현 절차가 아니다. 공개 가능한 가상 자료를 사용한다.

## 1. 여섯 노드 정의

| ID | 종류 | 내용 |
|---|---|---|
| F1 | File | 가상 제품 A의 요구사항 |
| F2 | File | 가상 팀 B의 검토 기록 |
| O1 | Output | 두 자료를 요약한 분석 |
| E1 | Entity | 제품 A |
| E2 | Entity | 팀 B |
| E3 | Entity | 일정 C |

## 2. 관계를 명시

```text
O1 --근거로 사용--> F1
O1 --근거로 사용--> F2
F1 --언급--> E1
F1 --언급--> E3
F2 --언급--> E2
F2 --언급--> E3
```

`언급`은 인과관계나 사실 검증을 의미하지 않는다. `근거로 사용`도 출력물 전체의 정확성을 보증하지 않는다. 각 연결에 근거 위치와 검토 상태를 추가한다.

## 3. 엔터티에서 원문까지 탐색

1. E3를 언급한 F1·F2를 찾는다.
2. 두 파일을 근거로 사용한 O1을 찾는다.
3. O1에서 일정에 관한 주장 하나를 선택한다.
4. F1·F2의 문단과 대조하고, 불일치가 있으면 기록한다.

관계 방향의 역방향 탐색은 가능하지만 관계의 의미 자체를 뒤집지는 않는다. `F1이 O1을 근거로 사용`한다고 해석하면 안 된다.

## 4. 시각화와 검색 구분

| 검증 대상 | 수행할 작업 |
|---|---|
| 사람의 탐색 | 그래프에서 O1의 근거 파일과 위치 찾기 |
| 에이전트 검색 | 일정 질문에 어떤 자료·버전을 검색했는지 기록 |

두 번째 작업은 실제 검색 인터페이스가 있어야 검증 가능하다. 없으면 실험 계획으로 남긴다.

## 완료 기준

- [ ] 6개 노드의 종류와 관계 유형을 설명할 수 있다.
- [ ] O1의 주장과 연결된 원문 위치를 제시할 수 있다.
- [ ] 근거가 없는 주장은 미확인으로 표시했다.
- [ ] 화면 탐색 성공과 검색 품질을 별도로 기록했다.
