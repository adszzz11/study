# Overview: What / Why / 특징

## What

지식 그래프는 파일·출력물·엔터티를 노드와 관계로 표현하는 관점이다. Orbit Agents 영상 요약에서는 이 그래프 화면과 에이전트 운영 화면을 함께 강조한다. **그래프 화면의 존재는 내부 graph database 사용의 증거가 아니다.**

## Why

- **정보의 분산:** 여러 클라이언트가 사용하는 자료와 생성한 출력물의 연결을 파악하려는 필요.
- **업무 맥락의 분리:** 정보뿐 아니라 담당 에이전트, 부서, 업무·성과도 함께 이해하려는 필요.

두 문제는 영상 구성에 대한 해석이며 사용자 조사나 도입 효과 측정 결과가 아니다.

## 핵심 특징과 근거 수준

| 요소 | 요약에서 확인되는 내용 | 미확인 사항 |
|---|---|---|
| 노드 | 파일·출력물·엔터티 표현 | ID, schema, 중복 병합 |
| 관계 | 연결선 시각화 | 유형, 방향, 생성·검증 기준 |
| 탐색 | 지식 그래프 화면 강조 | 검색·필터·확장·편집 동작 |
| 메모리 | 여러 AI 클라이언트를 연결하는 구상 | 저장 엔진, 읽기·쓰기, 동기화 |
| 운영 | Lead Finder, Email Outreach Agent, CRM, 대시보드, 조직도 | 실제 실행, 지표 정의, 그래프 연결 |

## 논리적 구조

```text
Claude / Codex 등 AI 클라이언트
              │
    하나의 메모리에 연결하는 구상
              │
    파일 · 출력물 · 엔터티의 관계
              │
        지식 그래프 화면
```

이 구조는 구상의 요약이며 구현 아키텍처나 API 명세가 아니다. **공유 저장과 공유 이해는 별개**다. 같은 저장소에 접근해도 검색 결과, 전달되는 맥락, 최신 버전 반영은 따로 검증해야 한다.

## 운영 화면의 역할

Content·Marketing·Research 부서 아래 에이전트를 배치한 조직도는 업무 배치의 표현이다. 실제 권한, 위임, 실행 순서를 제어하는지는 알 수 없다. CRM·성과 지표와 메모리 그래프의 데이터 연결도 미확인이다.

## 평가 기준

| 기준 | 확인 질문 | 의미 |
|---|---|---|
| 관계 의미 | 연결선은 무엇을 뜻하는가? | 인접성과 근거 관계 구분 |
| 출처 추적 | 원문과 해당 위치로 이동 가능한가? | 주장 검토 |
| 시간·변경 | 갱신·삭제·충돌을 어떻게 표시하는가? | 공유 메모리 일관성 |
| 작업 연결 | 생성 에이전트·실행 기록이 있는가? | 업무 검토 |
| 규모 대응 | 노드가 늘어도 필요한 관계를 찾는가? | 탐색 유용성 |

이 기준들은 확인된 제품 기능이 아니라 검증을 위한 질문이다.
