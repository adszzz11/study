# Projects: 적용과 검증

아래 프로젝트는 dossier에서 확장한 설계 제안이다. 제품에 이미 구현된 기능이나 검증된 효과로 읽지 않는다.

## 프로젝트 1: 근거를 추적하는 Research 메모리

- **목표:** 자료 파일·엔터티·분석 출력물의 연결을 검토한다.
- **구현 범위:** 출력물에서 근거 파일·문단으로 이동하고 엔터티별 자료를 탐색한다.
- **산출물:** 노드 목록, 관계 표, 주장별 근거 대장, 미확인 주장 목록.
- **검증:** 선택한 주장 3개를 관계를 따라 원문까지 추적하고 실제 내용과 대조한다.
- **주의:** 동시 등장과 인과관계, 근거 연결과 사실 검증을 구분한다.

## 프로젝트 2: Lead Finder와 Outreach 검토 화면

- **목표:** 영상의 Lead Finder·Email Outreach Agent·CRM을 참고해 업무 기록의 출처를 검토한다.
- **구현 범위:** 가상 리드, 관련 자료, 메시지 초안, 담당 에이전트, 실행 기록을 연결한다.
- **산출물:** 리드별 초안·근거·담당자 매핑과 검토 상태.
- **검증:** 초안마다 대응하는 리드, 근거 자료, 작성 에이전트를 식별한다. 근거 없는 문구는 표시한다.
- **주의:** 자동 발송은 범위에 포함하지 않는다. 영상만으로 발송 성공이나 성과 개선을 전제할 수 없다.

## 프로젝트 3: 여러 클라이언트의 공유 메모리 검증

- **목표:** Claude·Codex가 하나의 메모리를 사용한다는 구상을 검증 가능한 작업으로 나눈다.
- **선행 조건:** 실제 연동 인터페이스, 접근 권한, 읽기·쓰기 조건을 확인한다. 불명확하면 계획만 작성한다.
- **구현 범위:** 동일 자료 조회 → 한쪽 갱신 → 다른 쪽 재조회 → 상충 정보 처리.
- **산출물:** 클라이언트별 자료 ID·버전·조회 시각·검색 결과를 담은 실험 기록.
- **검증:** 같은 자료·버전을 참조했는지, 변경이 반영되었는지, 충돌이 드러나는지 비교한다.
- **주의:** 동일 저장소 접근을 동일한 이해나 답변 정확도로 간주하지 않는다.

## 공통 결과 기록 양식

```text
질문 / 기대한 근거:
클라이언트 / 실행 ID:
자료 ID / 버전 / 원문 위치:
관찰한 결과:
성공·실패 판단 근거:
미확인 사항 / 다음 검증:
```
