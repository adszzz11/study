# Overview: 세 값 표현의 What / Why

## What

모델을 구성하는 수치를 세 가지 값으로 표현하여 용량 축소를 시도하는 개념이다. `ternary`라는 이름만으로 구체적인 알고리즘을 식별할 수 없다. 제공 자료에는 실제 세 값, 적용 파라미터, 저장 형식, 구현이 없다.

## Why

파일이 작아지는 것보다 필요한 작업 품질을 유지하면서 사용자의 컴퓨터에서 실행할 수 있는지가 중요하다. 영상은 파라미터와 파일 용량을 설명하고 코딩 성능, 노트북 실행 가능성, 회사 문서의 로컬·클라우드 처리를 논의한다.

## 특징과 확인 경계

| 항목 | 확인된 내용 | 확인되지 않은 내용 |
|---|---|---|
| 표현 | 세 값 기반 접근 소개 | 실제 값, 전체/일부 파라미터 적용 여부 |
| 생성 과정 | 설명 없음 | 학습 시 적용인지 기존 모델 변환인지 |
| 크기 | 약 54GB·3.6GB, 별도 5.9GB 표기 | 모델·파일 구성·설정 대응 |
| 품질 | 코딩 능력 저하 여부와 수치 논의 | 지표, 조건, 비교 대상, 구체적 결과 |
| 실행 | 노트북 실행 가능성을 질문 | 성공 여부, 하드웨어, 실행 도구 |
| 공개 | Apache 2.0 가중치 공개 언급 | 모델 식별 정보와 배포물 구성 |

## 파라미터 수와 파일 크기

“모델을 줄였다”는 말은 파라미터 수 감소, 같은 파라미터의 표현 변경, 또는 두 변화 모두를 뜻할 수 있다. 자료만으로 이를 판별할 수 없다. 화면의 용량 차이를 구조 축소나 동일 모델의 표현 변경 효과로 단정하지 않는다.

## 실행 아키텍처의 범위

확인되는 배치 선택지는 로컬 처리와 클라우드 처리다. 구체적 추론 구성은 없다. 파일 크기는 실행 중 메모리, 처리 속도, 문서의 실제 전송 경로를 대신 설명하지 않는다.
