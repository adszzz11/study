# Projects: 주장 검증에서 실험으로

모든 항목은 학습 제안이며 완료된 실험이나 검증 결과가 아니다.

## 1. 용량·성능 주장 검증표

현재 자료로 바로 시작할 수 있는 프로젝트다.

| 주장 | 현재 근거 | 부족한 자료 | 상태 |
|---|---|---|---|
| 용량이 줄어든다 | 54GB·3.6GB 비교 표기 | 모델·파일·설정 대응 | 미확인 |
| 5.9GB가 다른 수치와 연결된다 | 별도 표기만 있음 | 각 수치의 문맥 | 미확인 |
| 코딩 능력이 유지된다 | 관련 논의가 있음 | 지표·조건·결과 | 미확인 |
| 노트북에서 실행된다 | 가능성을 질문함 | 실행 로그·사양 | 미확인 |
| Apache 2.0 가중치 공개 | 공개 언급 | 모델 식별·배포 LICENSE | 미확인 |

완료 기준: 모든 주장에 관찰, 근거 위치, 추가 확인 항목을 대응시킨다. 미확인 상태도 유효한 산출물이다.

## 2. 코딩 작업 비교 기록

- 선행 조건: 비교 모델·버전·표현 방식과 실행 절차 식별.
- 과제: 동일한 코딩 문제를 풀고 생성 코드를 실행한다.
- 산출물: 요구사항 충족률, 테스트 결과, 실패 유형, 응답 시간, 파일 용량 기록표.
- 완료 기준: 성공·실패와 평가 조건을 함께 보고한다. 목표는 “작아도 좋다”의 입증이 아니라 어떤 작업에서 어느 품질을 얻는지 확인하는 것이다.

## 3. 회사 문서 로컬 처리 시범 적용

- 선행 조건: 실행 환경과 문서 처리 흐름 식별.
- 과제: 공개·합성 문서 하나와 동일 질문을 로컬·클라우드 조건에서 비교한다.
- 산출물: 답변 정확성, 처리 시간, 문서 전달 경로, 환경·설정 기록.
- 완료 기준: 로컬 실행 여부와 문서 처리 품질을 따로 평가한다. 전처리나 외부 호출이 있다면 해당 경로도 명시한다.
