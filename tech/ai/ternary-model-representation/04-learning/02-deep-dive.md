# Deep Dive: 품질과 로컬 실행 검증

## 1. 표현 변경 효과 분리

동일 모델인지, 파라미터 수가 같은지, 파일 구성과 표현 외 조건이 같은지 확인한다. 조건이 다르면 결과는 배포물 간 비교이며 표현 방식 하나의 효과로 해석할 수 없다. 실제 세 값이나 혼합 표현 여부도 자료 확보 후 기록한다.

## 2. 코딩 품질 평가

1. 요구사항과 정상·경계·오류 입력을 포함한 동일 과제를 준비한다.
2. prompt, context, output limit, 생성 설정을 기록한다. 차이가 있으면 명시한다.
3. 생성 코드를 실행하고 요구사항 충족 여부와 실패 유형을 기록한다.
4. 반복 횟수와 각 결과를 남겨 단일 성공 예시로 일반화하지 않는다.
5. 품질 결과와 용량·시간 측정을 별도 열로 보고한다.

## 3. 로컬 실행 측정

| 측정 항목 | 기록 이유 |
|---|---|
| 파일 크기와 구성 | 다운로드·저장 부담 식별 |
| 장치, OS, runtime 버전 | 실행 환경 재현 |
| context와 생성 설정 | 부하 조건 식별 |
| 로딩 시간, 응답 시간 | 대기 경험 평가 |
| peak RAM·GPU 메모리 | 실행 중 자원 요구량 확인 |
| 오류·실패와 반복 기록 | 성공 조건의 한계 확인 |

파일 크기와 실행 메모리는 같은 측정치가 아니다. 시작 가능한지, 과제를 끝내는지, 사용 가능한 시간 안에 응답하는지를 각각 확인한다.

## 4. 문서 데이터 흐름

문서 입력 → 전처리 → 추론 → 결과 저장의 각 단계에서 실행 위치와 외부 전송 여부를 기록한다. 로컬 모델이라는 설명만으로 전처리·로그·도구 호출까지 로컬이라고 판단하지 않는다. 시범 실험은 공개·합성 문서로 설계할 수 있다.

## 5. 재현 가능성

가중치 공개 언급만으로 재현을 보장할 수 없다. 모델 식별 정보, 배포 파일, 라이선스 범위, runtime과 설정, 입력·평가 절차가 함께 필요하다. 현재 dossier에는 이 정보가 없다.
