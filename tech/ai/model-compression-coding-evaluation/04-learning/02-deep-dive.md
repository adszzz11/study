# Deep Dive: 통제 실험과 결과 해석

## 비교 조건 통제

| 평가 축 | 기록할 조건 | 목적 |
|---|---|---|
| 대상 | 모델 ID·revision·변환 관계 | 압축 효과와 모델 차이 분리 |
| 입력 | 동일 prompt·문제 집합·템플릿 | 지시와 난이도 통제 |
| 생성 | sampling·출력 한도·시도 횟수 | 생성 편차 통제 |
| 판정 | 같은 테스트·언어 버전·timeout | 실제 동작 비교 |
| 비용 | 하드웨어·runtime·메모리·시간 | 해당 환경의 실용성 판단 |

동일 seed를 지원해도 runtime·연산 차이로 같은 출력을 보장하지 않는다. 지원하지 않는 설정과 불가피한 runtime 차이는 한계로 기록한다.

## 반복과 성공률

문제별 시도 수를 고정하고 모든 결과를 보존한다. 첫 시도 성공률과 여러 시도 중 한 번 이상 성공한 문제 비율을 별도 보고한다. 두 지표는 다르며 단순 관찰 비율을 공식 `pass@k` 추정치로 부르지 않는다.

```text
첫 시도 성공률 = 첫 생성에서 전체 테스트를 통과한 문제 수 / 전체 문제 수
k회 중 성공 비율 = k회 내 한 번 이상 전체 테스트를 통과한 문제 수 / 전체 문제 수
```

작은 문제 집합의 결과는 해당 문제와 설정에 한정한다. 문제별 결과와 반복 간 편차를 함께 제시하고 총점만으로 일반 코딩 능력을 단정하지 않는다.

## 실패 분류

- 문법 오류 / 실행 중 오류 / 요구사항 누락 / 경계값 실패 / 출력 중단.
- 로딩 실패·생성 실패·timeout은 별도 표시한다. 실패 항목을 조용히 분모에서 제외하지 않는다.
- 여러 원인이 겹치면 주 원인과 부 원인을 기록한다.

## 비용 측정

cold load 시간, 생성 시간, 테스트 시간을 분리한다. 입력·출력 길이, warm-up 여부와 반복 횟수를 남긴다. 메모리는 CPU RAM·GPU VRAM 또는 통합 메모리의 측정 범위를 명시한다. 여러 메모리 수치를 중복 합산하지 않는다.

| 문제 | 모델 | 시도 | 통과 | 실패 유형 | 생성 시간 | 최대 메모리 |
|---|---|---|---|---|---|---|
| 예시 ID | 미확인 | 1 | 미측정 | 미측정 | 미측정 | 미측정 |

## 결론 작성

- 변환 관계가 확인된 쌍: “이 장치·설정·문제 집합에서 압축 전후에 관찰된 차이”로 기술한다.
- 관계 미확인: “두 모델의 관찰된 차이”로 제한한다.
- 노트북 한 대에서 성공: 해당 장치·입출력 길이의 실행 결과다. 일반적인 노트북 지원 근거가 아니다.
- 코딩 테스트 성공: 문서 QA 성능이나 데이터의 로컬 잔류를 입증하지 않는다.
