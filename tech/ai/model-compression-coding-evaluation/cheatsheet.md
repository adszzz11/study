# Cheatsheet: 압축·코딩 평가·로컬 실행

## 핵심 구분

| 질문 | 측정 대상 | 피해야 할 추론 |
|---|---|---|
| 얼마나 작은가? | 파일 목록·bytes·표현 방식 | 작은 파일 = 작은 실행 메모리 |
| 코딩을 잘하는가? | 동일 테스트 통과·실패 유형 | 실행됨 = 요구사항 충족 |
| 노트북에서 가능한가? | 장치별 로딩·메모리·시간 | 한 번 성공 = 모든 노트북 지원 |
| 문서가 로컬에 남는가? | 실제 처리·통신·로그 경로 | 가중치 공개 = 외부 전송 없음 |

## 평가 전

- [ ] 모델 ID·revision·변환 관계·라이선스 적용 파일 확인.
- [ ] 54GB·3.6GB·5.9GB 대응은 확인 전까지 미확인 유지.
- [ ] 동일 문제·prompt·sampling·출력 한도·시도 수 설정.
- [ ] 테스트·성공 기준·분리 실행 환경·timeout 준비.
- [ ] 장치·runtime·입출력 길이·메모리 측정 범위 기록.

## 평가 후

- [ ] 첫 시도 성공과 여러 시도 내 성공을 구분.
- [ ] 문법 오류·요구사항 누락·경계값 실패·실행 오류·출력 중단 분류.
- [ ] 로딩·생성 실패와 timeout도 결과에 포함.
- [ ] 파일 크기·최대 메모리·생성 시간·테스트 성공률을 함께 보고.
- [ ] 변환 관계가 없으면 압축 효과라고 부르지 않음.

## 바로 쓸 결과 문장

```text
[모델 ID/revision]을 [장치/runtime]에서 [입력·출력 길이/생성 설정]으로 평가했다.
[문제 수/시도 수]에서 첫 시도 성공률은 [측정값]이었다.
파일 크기 [값/범위], 최대 메모리 [값/측정 범위], 생성 시간 [값]을 기록했다.
[비교 모델]과의 변환 관계는 [확인/미확인]이다.
결론은 이 문제 집합과 실행 환경에 한정한다.
```

세 값 표현만으로 특정 알고리즘·속도·품질을 확정하지 않는다. 원자료에 모델명·평가 조건이 없으므로 현재 성능 유지·압축률·실행 가능성은 미확정이다.
