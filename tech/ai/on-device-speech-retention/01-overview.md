# Overview: 온디바이스 음성과 데이터 수명

## What

온디바이스 음성 처리는 사용자 기기에서 음성 인식을 수행하는 방식이다. 보관(retention)은 데이터가 생성·저장·유지·삭제되는 수명주기이며 처리 위치와 독립적으로 확인해야 한다.

## Why

녹음이 끝나기를 기다리는 대신 인식이 확실한 부분부터 출력하면 사용자가 기다리는 시간을 줄일 수 있다. 다만 자료에 실제 latency 측정치는 없다. 서버 미전송 설명 역시 로컬 파일이나 전사 히스토리의 부재를 뜻하지 않는다.

## 특징: 영상에서 소개된 내용

| 구성 | 소개 내용 | 확인되지 않은 부분 |
|---|---|---|
| 입력 | 마이크·녹음 파일 | 원본 사본·입력 보존 방식 |
| 실행 위치 | Mac 내부, 녹음 서버 미전송 | 실제 실행 경로·통신 여부 |
| 출력 | 확실한 부분부터 점진적 출력 | 확정 기준·이미 출력한 텍스트 수정 |
| 언어 | 한국어·자동 언어 감지 | 정확도·언어 전환 품질 |
| 인식 보조 | 단어 경계 유지·후보 비교·무음 건너뛰기 | 내부 알고리즘 |
| 사용자 설정 | 용어 사전 | 적용 방식·저장 위치 |
| 모델 | tiny부터 large까지 선택 | 모델별 메모리·속도·정확도 |
| 가속 | M2 Neural Engine 강조 | 단계별 실행 경로·측정 조건 |

## 개념적 흐름

```text
마이크 또는 녹음 파일 → Mac 내부 음성 처리
→ 인식 후보 비교·단어 경계 처리 → 확실한 부분부터 텍스트 출력
```

구현을 검증한 아키텍처 도식이 아니다. 자동 언어 감지, 무음 건너뛰기, 용어 사전, 모델 선택의 정확한 실행 순서와 결합 방식은 알 수 없다. 먼저 나타나는 텍스트를 수정 불가능한 최종 전사로 해석하지 않는다.

## 성능 주장의 경계

영상에는 소리 분석 최대 18배, 텍스트 변환 최대 15배 가속 주장이 있다. 비교 대상, 모델 크기, 입력 길이, 측정 단위, 실행 조건과 실제 측정 과정이 없어 **영상의 주장**으로만 기록한다. 두 배수를 합산하거나 곱해 전체 속도를 추정할 수 없고, 다른 제품 대비 우위나 특정 Mac의 실시간 성능을 입증하지도 않는다.

## 보관 확인 범위

| 데이터 | 자료의 설명 | 추가로 확인할 사항 |
|---|---|---|
| 마이크 음성 | 로컬 처리 | 녹음 생성 여부·경로·기간 |
| 입력 파일 | 입력 지원 | 사본·변환 중간 파일 |
| 전사 텍스트 | 점진적 출력 | 자동 저장·히스토리·내보내기 |
| 임시 데이터·로그 | 언급 없음 | 생성 내용·삭제 시점 |
| 용어 사전 | 기능 소개 | 저장·보존·삭제 방법 |
| 삭제 후 잔존 | 언급 없음 | 종료·사용자 삭제 후 남는 데이터 |

확인 과제는 해당 저장 동작이 존재한다는 주장이 아니다. 현재 근거는 영상 요약이며 소스코드·통신·파일 관찰 결과는 포함되지 않았다.
