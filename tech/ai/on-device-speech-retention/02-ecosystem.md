# Ecosystem: 세 가지 비교 축

## 비교 범위

자료에는 경쟁 제품의 이름과 사양이 없다. 제품별 가격·성능 순위 대신 **어디서 처리하는가, 언제 결과가 나오는가, 무엇을 얼마나 보관하는가**를 비교한다.

| 방식 | 처리·출력 | 데이터 관점 | 근거의 범위 |
|---|---|---|---|
| Lightning-SimulWhisper | Mac 내부·확실한 부분부터 출력 | 녹음 서버 미전송 설명 | 소개만 존재, 성능·보관 정책 미검증 |
| 녹음 종료 후 일괄 변환 | 녹음 후 텍스트 변환 | 위치·보관 정책은 별도 | 영상에서 출력 시점의 대조로 등장 |
| 서버 처리 방식 | 서버에서 음성 처리 | 전송·서버 보관 확인 필요 | 특정 서비스의 동작·정책 자료 없음 |
| 보관 정책이 명시된 로컬 구성 | 로컬 처리와 저장·삭제 규칙 결합 | 위치와 수명을 함께 관리 | 특정 제품 기능이 아닌 설계 대안 |

## 선택 기준

- 대화 중 결과가 필요하면 첫 출력 지연과 수정 빈도를 확인한다.
- 저장 제한이 중요하면 음성뿐 아니라 전사·로그·사전의 수명을 확인한다.
- 네트워크가 제한되면 모델 준비·실행·업데이트를 분리해 오프라인 동작을 시험한다. 현재 자료는 완전한 오프라인 동작을 보장하지 않는다.
- 로컬이라는 한 축의 장점으로 속도·정확도·무보관을 추정하지 않는다.
