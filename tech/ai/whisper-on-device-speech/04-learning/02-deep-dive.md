# 심화 학습: 데이터 경계·저장·화자 정보

## 1. 실행·전송·저장 분리

| 질문 | 자료상 설명 | 추가 검증 |
|---|---|---|
| 모델은 어디서 실행되는가? | Sokki는 기기 내부 | 실행 구성·모델 파일·프로세스 확인 |
| 오디오는 어디로 이동하는가? | Sokki README는 Mac 외부 미전송 설명 | 권한 있는 환경의 네트워크 관찰 |
| 기록은 어디에 남는가? | 로컬 SQLite | DB·오디오·관련 파일의 실제 범위 확인 |

오프라인 동작 여부와 네트워크 관찰은 서로 보완하는 관찰이다. 특정 실행에서 전송을 보지 못한 사실이 모든 버전·기능의 미전송을 증명하지는 않는다. 텍스트·진단 로그·백업·동기화도 별도로 조사한다.

## 2. SQLite 저장 범위 조사

권한 있는 환경에서 앱을 종료하고 일관된 DB 사본을 준비한다. WAL 모드라면 관련 파일을 포함한 일관된 사본 또는 SQLite backup 기능이 필요할 수 있다. 경로는 자료에 없어 직접 확인해야 한다.

```sh
# 실제 경로로 교체. 사본을 읽기 전용으로 열어 구조 확인
sqlite3 -readonly /path/to/copied-history.db '.tables'
sqlite3 -readonly /path/to/copied-history.db '.schema'
```

- schema를 확인한 다음 필요한 최소 열만 조회한다. 전사 텍스트·시각·오디오 경로가 저장된다고 미리 가정하지 않는다.
- 데이터별 생성 위치·저장 위치·보존 기간·삭제 동작·근거를 표로 남긴다.
- 앱의 삭제 기능 실행 전후를 비교하고 원본 오디오·관련 파일·백업을 따로 확인한다.
- UI에서 사라짐, DB 행 삭제, 물리적 복구 불가능은 서로 다른 기준이다. 로컬 저장만으로 암호화나 완전 삭제를 보장하지 않는다.

## 3. 화자 분리와 누적 프로필

- **회의 내부:** 발화 구간 경계, 잘못 합쳐진 화자, 잘못 나뉜 화자를 기록한다.
- **회의 사이:** 동의한 참가자의 여러 회차를 비교해 같은 사람의 프로필 연결·중복·오연결을 기록한다.
- voice embedding·실명 식별·특정 diarization pipeline은 자료에 없다. Damso의 Whisper 사용과 온디바이스 처리도 미확인이다.

## 4. 녹음 시작 상태 전이

```text
자료에 제시된 순서: 회의 감지 → 사용자 확인 → 녹음
검증 대상으로 설계할 분기: 확인 대기 → 승인 / 거절 / 무응답
```

| 상태·이벤트 | 관찰할 항목 |
|---|---|
| 감지 | 감지 표시, 확인 전 처리 정보의 공개 여부 |
| 확인 대기 | 녹음 시작 여부, 응답 대기 동작 |
| 승인 | 실제 녹음 시작 시점 |
| 거절·무응답 | 녹음 여부, 재확인·종료 동작 |

거절·무응답 처리와 감지 신호는 자료에 없으므로 기대 동작과 관찰 결과를 나누어 적는다. 녹음 전 확인을 전체 데이터 수집 전 확인으로 확대하지 않는다.
