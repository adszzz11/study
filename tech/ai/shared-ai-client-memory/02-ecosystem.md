# Ecosystem: 역할과 설계 접근 비교

## 비교의 기준

Obsidian은 영상 속 비교 대상이고 Claude·Codex는 연결할 클라이언트다. 모두 같은 제품 범주의 경쟁자로 취급하지 않는다.

| 대상·접근 | 자료 속 역할 | 공유 메모리 관점 | 판단할 수 없는 부분 |
|---|---|---|---|
| Orbit Agents | 메모리와 에이전트 운영 통합 시스템으로 소개 | 공통 메모리와 운영 화면을 한곳에 배치 | 실제 연동·검색 품질·갱신·작업 성공률 |
| Obsidian | 비교 대상 | 소개를 이해하는 기준점 | 구체적인 기능 차이·우열 |
| Claude·Codex | 연결할 클라이언트 예시 | 서로 다른 클라이언트의 공통 지식 활용 | 지원 범위·연결 방식·읽기·쓰기 |
| 클라이언트별 개별 맥락 관리 | 분석용 대안 설계 | 필요한 맥락을 각각 전달 | 구현 사례·비용 비교 없음 |
| 공통 메모리와 운영 도구 분리 | 분석용 대안 설계 | 지식 관리와 실행 관리를 별도 구성 | 통합형과의 실증 비교 없음 |

마지막 두 행은 확인된 제품 기능이 아니라 설계 선택지다. 자료만으로 비용·성능·보안·호환성의 우열을 정할 수 없다.

## 도입 평가 질문

- **표현**: 한 화면에서 관계와 활동을 볼 수 있는가?
- **동작**: 다른 클라이언트가 같은 지식을 찾아 재사용하는가?
- **갱신**: 수정된 원본과 파생 결과물의 상태가 구분되는가?
- **운영**: 권한과 성공 지표를 실행 기록으로 재현할 수 있는가?

영상은 표현을 소개하지만 동작 검증 근거는 제공하지 않는다. 비교표의 미확인 항목을 구매·도입 전 검증 목록으로 사용한다.
