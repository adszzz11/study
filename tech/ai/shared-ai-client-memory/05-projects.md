# Projects: 검증에서 적용으로

## 적용 아이디어

아래는 소개된 구상에서 도출한 프로젝트이며 실제 구현 가능성은 별도 검증이 필요하다.

| 프로젝트 | 적용 흐름 | 최소 검증 기준 |
|---|---|---|
| Research 작업 인계 | A의 조사 정리를 B의 후속 분석에 활용 | 원본 재입력 없이 기록을 찾고 출처 제시 |
| 파일·출력물 계보 | 원본과 요약·보고서를 관계로 연결 | 원본 추적 및 원본 수정의 영향 대상 식별 |
| Lead Finder → Outreach | 잠재 고객 조사를 메시지 초안에 활용 | 동일 고객 중복 생성 없이 조사 근거 인계 |
| 부서별 메모리 운영 | 부서별 지식 공유 범위 설계 | 허용된 공유와 접근 제한이 실제로 작동 |
| 에이전트 성과 검증 | 대시보드와 실행 로그 대조 | 성공·실패 집계를 실제 결과에서 재현 |

## 추천 첫 프로젝트: Research 작업 인계

1. [[tech/ai/shared-ai-client-memory/04-learning/01-getting-started|작은 자료 집합 실험]]으로 공유 조회·출처·수정 반영을 확인한다.
2. [[tech/ai/shared-ai-client-memory/04-learning/02-deep-dive|신뢰성 검증]]으로 동명이인·모순·버전 충돌을 추가한다.
3. 기본 인계가 통과한 뒤 시험용 도구와 CRM으로 범위를 넓힌다.

단계를 나누면 메모리 문제와 외부 도구 문제를 구분하기 쉽다. 아직 실행하지 않은 기능은 미검증으로 남긴다.

## 결과물과 완료 기준

- 자료·버전·클라이언트·실행 시각이 포함된 실험 기록
- 답변에서 원본까지 이어지는 출처 경로
- 판정 기준별 통과·실패·미검증 표
- 실패 재현 입력과 해결되지 않은 제약 목록

기본 인계 프로젝트는 공유 조회·출처 추적·수정 반영의 증거가 모두 확보되어야 완료로 본다. 특정 제품의 성능 우위를 결론 내리려면 동일 조건의 별도 비교 실험이 필요하다.
