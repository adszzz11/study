# Overview: 공유 메모리와 운영 아키텍처

> **한 줄 정의**: 클라이언트와 분리된 공통 지식·작업 맥락을 여러 AI 클라이언트가 참조하도록 하는 구조다.

## What / Why

Claude·Codex에 각각 자료를 전달하면 맥락이 분산될 수 있다. 공유 메모리는 공통 지식에 접근하는 접점을 제공하려는 접근이다. 재입력 감소와 인계 품질 향상은 기대 효과이며, 이 자료에 실증 결과는 없다.

Orbit Agents는 Obsidian과 비교되지만, 개인 지식 보관을 넘어 여러 에이전트를 회사 형태로 배치하는 방향까지 소개한다.

## 자료에서 확인되는 특징

| 구성 | 소개된 내용 | 확인 한계 |
|---|---|---|
| 클라이언트 연결 | Claude·Codex가 공통 메모리를 활용하는 구상 | 연결 절차·동작 미검증 |
| 지식 그래프 | 파일·출력물·엔터티를 노드로 시각화 | 화면 표현만 확인 |
| 사전 구성 에이전트 | 도구가 연결된 Lead Finder·Email Outreach Agent | 도구 호출·작업 성공 미검증 |
| CRM | 고객 관리 화면 | 데이터 연동 방식 불명 |
| 성과 대시보드 | 에이전트 성과 집계 화면 | 지표 정의·산출 근거 불명 |
| 조직도 | Content·Marketing·Research 아래 에이전트 배치 | 권한·실행 정책과의 연결 불명 |

## 세 층의 개념 모델

```text
운영 층: CRM / 성과 대시보드 / 부서별 조직도
작업 층: AI 클라이언트 / 사전 구성 에이전트 / 도구
지식 층: 파일 / 출력물 / 엔터티 / 관계
```

소개된 기능을 분류한 모델이며, 내부 구현 설계도가 아니다. 층 사이 데이터 흐름, 갱신 주체와 시점은 확인되지 않았다. 통합이 실제로 동작한다면 작업 결과를 이후 맥락으로 재사용할 수 있다.

## 공유 메모리 ≠ 지식 그래프

공유 메모리는 **공동 읽기·쓰기와 상태 공유**, 지식 그래프는 **정보와 관계의 표현**에 관한 문제다. 연결선만으로 최신 상태 조회, 결과 기록, 엔터티 중복 제거, 수정 충돌 처리, 출처 추적을 입증할 수 없다.

그래프 UI가 Graph DB·vector search·GraphRAG의 사용을 의미하지 않는다. MCP·API·파일 동기화 중 어떤 방식으로 연결하는지도 자료에 없다. 조직도 역시 시스템이 강제하는 접근 권한의 증거는 아니다.
