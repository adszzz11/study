# Projects: 검증 가능한 도입 실험

## 회사 문서 로컬 처리 PoC

**목표:** 지정 장비에서 민감정보 없는 문서를 처리할 수 있는지 확인한다.

1. 모델·배포 파일·라이선스 적용 범위를 확인한다.
2. 샘플 문서와 성공 기준을 정한다.
3. 실행 여부·처리 시간·결과 품질·자원 사용량을 기록한다.
4. 입력부터 결과 저장까지 데이터 이동을 관찰한다.

**산출물:** 실행 가능한 데모, 환경 기록, 검증표, 통신 및 저장 위치의 근거. 실행 실패나 미확인 항목도 결과에 포함한다. 현재 자료로 특정 모델·하드웨어를 추천할 수 없다.

## 모델 크기와 코딩 성능 비교 보고서

**목표:** “얼마나 작아졌는가”와 “업무에 필요한 성능을 유지하는가”를 각각 판단한다.

- 비교 가능한 모델 계열·배포물·설정을 먼저 확인한다.
- 동일 과제와 장비에서 파일 크기, 테스트 결과, 응답 시간을 기록한다.
- 조건이 다른 기존 결과를 직접 비교하지 않는다.

**산출물:** 모델 식별자, 파일 구성, 설정, 과제, 장비, 실행 로그를 포함한 보고서. 변환 이외의 차이가 있으면 인과 해석의 한계로 적는다.

## 모델 도입 검토표

| 항목 | 현재 상태 | 근거/다음 확인 |
|---|---|---|
| 가중치 접근성 | 미확인 | 공개 언급만 있음; 공식 배포 위치 확인 |
| 라이선스 적용 범위 | 미확인 | Apache 2.0 이름만 있음; 파일별 원문 확인 |
| 장비 실행 가능성 | 추가 검증 필요 | 지정 장비에서 실행 기록 필요 |
| 코딩 품질 | 추가 검증 필요 | 동일 과제 평가 필요 |
| 문서 처리 위치 | 추가 검증 필요 | 단계별 데이터 흐름 확인 필요 |

상태는 **확인됨·미확인·추가 검증 필요**로 기록한다. 확인됨으로 바꿀 때는 근거와 검증 범위를 함께 적는다. 현재 공백을 드러내는 것이 이 표의 목적이다.
