# Projects: 실전 적용과 평가

## 1. 부서 간 업무 인계 실험

**목표:** 리서치 → 마케팅 초안 → 운영 검토에서 역할 분리의 효과를 확인한다.

- 각 단계의 입력·출력·완료 조건을 문서화한다.
- 최초에는 사람이 결과를 전달해 handoff 규칙부터 검증한다.
- 동일 자료로 단일 역할 처리와 역할 분리 처리를 비교한다.
- 누락 정보, 반복 수정, 전달 중 손실을 기록한다.

**완료 산출물:** 단계별 결과와 최종 문서, 추가 질문 횟수·재작업량 비교표. 최종 품질과 전달 비용을 함께 평가한다.

## 2. 역할별 모델 적합성 평가

**목표:** 동일 역할에서 모델 선택의 영향을 확인한다.

- 같은 자료·지시문·평가 기준으로 사용 가능한 모델을 비교한다.
- 근거 충실도, 형식 준수, 수정량을 기록하고 여러 번 반복한다.
- 비용·실행 시간은 실제 측정값이 있을 때만 포함한다.

**완료 산출물:** 모델·버전·실행별 결과표와 업무별 적합성 메모. 특정 역할의 결과를 모델 전체 순위로 일반화하지 않는다.

## 3. Workspace 통합 수준 점검

**목표:** 후보가 제공하는 통합 범위를 증거로 구체화한다.

| 점검 항목 | 상태 | 증거·확인 날짜 |
|---|---|---|
| Agent 목록·모델 선택 방식 | 미확인 | |
| Agent 간 결과 전달 | 미확인 | |
| 공유 context·부서별 접근 범위 | 미확인 | |
| 작업 상태·실패 처리·승인 | 미확인 | |
| 실행 기록·결과 추적 | 미확인 | |

상태는 `직접 확인`, `설명만 확인`, `미확인` 중 하나로 쓴다. Dossier 관찰을 직접 제품 테스트로 표시하지 않는다. 화면에 함께 등장한 것과 실제 업무 연결이 재현된 것을 구분한다.

**완료 산출물:** 증거를 첨부한 점검표와 도입 전 추가 검증 목록.
