# Deep Dive: 지연과 정확도 분리하기

## 측정 지표

| 지표 | 정의·기록 방법 | 해석 주의 |
|---|---|---|
| 최초 출력 지연 | 마이크 발화 시작부터 첫 표시까지 | 최종 정확도를 뜻하지 않음 |
| 확정 지연 | 해당 구간 발화 종료부터 결과 안정까지 | 구간과 관찰 기준을 명시 |
| 수정 빈도 | 이미 표시된 텍스트가 바뀐 횟수 | 발화 길이와 관찰 주기도 기록 |
| RTF | 파일 처리 경과 시간 / 음성 길이 | 실시간 마이크 대기 시간과 구분 |
| CER | (대치+삭제+삽입 문자 수) / 정답 문자 수 | 띄어쓰기·문장부호 정규화 규칙 고정 |
| 장시간 안정성 | 구간별 확정 지연·미처리량 추이 | 평균만으로 누적 지연을 숨기지 않음 |

RTF가 1보다 작으면 그 파일을 음성 길이보다 짧은 시간에 처리했다는 뜻이다. 이것만으로 마이크의 최초 출력이나 확정 지연이 작다고 단정하지 않는다.

## 모델과 출력 정책 실험

- 같은 Mac·입력·언어·사전 설정에서 모델만 변경한다. tiny~large 각각의 실제 지원 목록을 기록한다.
- 첫 실행은 모델 준비 비용이 섞일 수 있으므로 이후 실행과 구분한다. 반복 횟수와 분포를 함께 기록한다.
- 짧은 발화·긴 문장·중간에 멈춘 발화로 먼저 나온 텍스트의 수정과 단어 경계를 관찰한다.
- 한국어 지원 여부와 한국어 전문용어 정확도를 별도 평가한다. 사전이 인식 후보를 주는지 후처리인지 알 수 없으므로 결과만으로 내부 방식을 추정하지 않는다.

## 가속 주장의 재현 조건

```text
단계별 speedup = 동일 조건의 기준 단계 시간 / 가속 단계 시간
전체 시간 = 입력·대기 + 분석 + 변환 + 전달 + 출력 확정 대기
```

18배·15배는 두 단계에 대한 최대 주장이다. 기준 실행 방식과 모델·입력·정확도 조건이 같아야 배수를 해석할 수 있다. 각 단계 시간과 비가속 비중이 없으면 전체 가속을 계산할 수 없으며 두 값을 곱하거나 평균하지 않는다.

가속 비활성화 또는 단계별 계측을 지원하지 않으면 관찰 결과를 ‘해당 구성의 전체 처리 시간’으로 보고한다. Neural Engine 단독 효과라고 부르지 않는다. CPU/GPU fallback, 정밀도, 변환 형식과 실제 장치별 실행 비중은 소스·프로파일 등 별도 근거가 필요하다.

## 로컬 처리의 검증 범위

실행 조건과 관찰 구간을 명시해 네트워크 활동을 점검한다. 음성 업로드 미관찰과 앱 전체의 무통신 보장은 다르다. 모델 다운로드·업데이트 통신과 음성 전송을 구분하고, 로그·임시 파일·전사문 저장 위치와 보관·삭제 정책을 별도로 확인한다.
