# Deep Dive: 실행 상태와 역할 전달 검증

## 핵심개념 실험표

다음 항목은 검증 기준이며 제품의 확정 기능 목록이 아니다. 지원 여부를 확인할 수 없으면 미확인으로 기록한다.

| 개념 | 실험 | 관찰할 결과 |
|---|---|---|
| Background execution | 짧은 작업 요청 후 화면 이탈 | 이탈 중 진행을 입증하는 기록 |
| Service lifecycle | 요청 없는 대기와 요청 후 처리 비교 | 서비스 수명과 작업 수명의 차이 |
| Execution state | 여러 단계 업무의 중간 상태 확인 | 완료·진행·실패 단계 구분 |
| Memory | 다음 작업에서 이전 정보 참조 요청 | 기억한 정보와 재개한 단계의 차이 |
| Role handoff | 연구→작성→검토로 같은 과제 수행 | 전달물과 수정 책임 |
| Model configuration | 같은 입력에서 모델 설정 변경 | 결과 품질·형식 차이 |

## Memory와 checkpoint 분리

1. 무해한 선호 정보 하나를 전달하고 다음 작업에서 참조되는지 확인한다.
2. 별도 다단계 과제에서 각 단계의 산출물과 완료 지점을 기록한다.
3. 공식적으로 중단·재개가 지원될 때만 복구 실험을 수행한다.
4. 재개 시 이미 완료된 단계가 반복되는지, 미완료 단계부터 이어지는지 비교한다.

선호 정보가 기억되어도 checkpoint 저장을 입증하지 않는다. 다시 요청해서 처음부터 완성한 결과도 이전 실행의 복구와 구별해야 한다.

## 역할 간 전달물 설계

| 역할 | 입력 | 산출물 | 검토할 책임 |
|---|---|---|---|
| 연구자 | 문서와 질문 | 근거 목록·불확실성 | 인용 정확성 |
| 작성자 | 근거 목록 | 보고서 초안 | 근거 밖 주장 방지 |
| 검토자 | 원문·근거·초안 | 오류와 수정 제안 | 주장-근거 대조 |

수동 전달부터 실행하고, 자동 전달은 지원이 확인될 때 별도로 시험한다. 역할 이름만으로 자동 orchestration이 있다고 판단하지 않는다.

## 실패·권한 평가

- 실패 상태를 조회할 수 있는가? 재시도는 누가 언제 결정하는가?
- 재실행 시 같은 외부 행동이 중복되지 않는가?
- 진행 조회·중단·재개와 실행 제한이 문서화되어 있는가?
- 예약·쇼핑·양식 제출에서 실행 범위와 승인 지점은 어디인가?

이 질문의 답은 dossier에 없다. 외부 상태를 바꾸는 실험으로 확장하기 전에 별도로 확인한다.

## 실험 기록 양식

```text
가설 / 도구·버전 / 설정:
입력 / 예상 단계 / 관찰된 단계:

관찰 근거 / 미확인 사항 / 다음 실험:
```
