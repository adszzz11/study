# Ecosystem: 작업 방식과 활용 비교

이 표는 성능 순위가 아니다. 여섯 도구가 모두 같은 종류의 지속 실행 제품이라는 근거도 없다. 이름과 기능은 제공 dossier 기준이며 제품의 정확한 배포판·버전은 확인되지 않았다.

| 도구 | 관찰된 방식·영역 | 주제와의 연결 | 미확인 사항 |
|---|---|---|---|
| Dots | ChatGPT 안에서 사용자 부재 중 작업 지속 | 작업 연속성의 직접 사례 | 실행 제한, 세션 종료 영향, 중단·복구 |
| Muse | 예약·쇼핑·양식 작성·알림·장기 목표 | 일상 업무와 장기 목표 적용 | 상시 실행, trigger, 외부 행동 승인 |
| Grok Bot | 리서치·영업·마케팅·운영 AI 동료 | 직무별 업무 위임 | 백그라운드 실행, 역할 협업 |
| OpenClaw | 백그라운드 서비스, 채팅 요청 처리 | 서비스 기반 실행의 직접 사례 | 배포 위치, 가용성, 재시도·복구 |
| Hermes | 연구자·작성자·검토자, 모델·메모리 설정 | 역할과 실행 맥락 구성 | 상태 저장, 자동 전달, 지속 실행 보장 |
| SkillTree | 부서 agent와 Claude·GPT·Gemini 통합 | 조직·모델을 묶는 작업 공간 | 자동 orchestration, 병렬 처리, 전환 정책 |

## 목적별 비교 출발점

- 사용자 부재 중 작업 지속: Dots.
- 채팅과 서비스 연결: OpenClaw.
- 역할 분담: Grok Bot·Hermes.
- 여러 모델과 부서 통합: SkillTree.
- 일상 업무 적용: Muse.

이는 조사 순서를 정하기 위한 기준이지 구매 추천이나 검증된 기능 우열이 아니다.

## 대안과 선택 경계

| 필요한 방식 | 비교할 운영 대안 | 검증할 점 |
|---|---|---|
| 짧고 즉시 검토할 작업 | 대화형 단발 실행 | 백그라운드 운영이 실제 필요한가 |
| 정해진 시점의 반복 작업 | Scheduler와 명시적 workflow | trigger, 실행 기록, 실패 알림 |
| 중단 후 복구가 필수인 작업 | Durable execution을 명시한 시스템 | checkpoint, 복구 시험, 중복 방지 |

대안은 분석상 비교 축이다. 소개된 제품이 해당 구조를 구현했다는 뜻은 아니다.

영상 마지막에는 cloud·open-source, 가격·개인정보 보호·강점이 비교 항목으로 등장하지만 제품별 값은 제공되지 않았다. 무료 여부, self-hosting 가능 여부, 데이터 보관 위치와 보안 우위는 판단을 유보한다.
