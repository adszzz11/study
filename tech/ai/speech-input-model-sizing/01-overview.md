# Overview: 입력 경로와 모델 크기

## What

개념적 흐름은 **마이크 또는 녹음 파일 → Mac 내부 음성 처리 → 텍스트 출력**이다. 실시간 방식은 인식이 확실하다고 판단한 부분부터 먼저 보여준다는 설명이다. 확실함의 기준, 부분 출력의 수정 가능성, 최종 확정 조건은 알려지지 않았다.

## Why

최종 전사 품질만으로는 발화 중 읽고 사용하는 경험을 설명할 수 없다. 첫 텍스트가 빨리 나타나도 최종 결과까지 오래 걸리거나 문장이 자주 수정될 수 있다. **먼저 보이는 텍스트와 최종 확정 텍스트를 구분**해야 한다.

## 특징과 근거의 경계

| 소개 내용 | 의미 | 확인할 항목 |
|---|---|---|
| tiny~large 선택 화면 | 모델 변경 기능을 보여줌 | 모델별 한국어 품질·지연·자원 사용량 |
| Mac 내부 음성 처리 | 음성이 서버로 전송되지 않는다는 설명 | 다운로드·업데이트·진단 정보 등 전체 네트워크 동작 |
| M2 Neural Engine 가속 | 소리 분석 최대 18배, 텍스트 변환 최대 15배라는 영상 주장 | 비교 대상·모델·입력 길이·측정 조건 |
| 한국어·자동 언어 감지 | 한국어 입력 평가의 출발점 | 짧은 발화·혼합 언어의 감지 품질 |
| 단어 경계 유지·후보 비교 | 부분 출력의 읽기와 결과 선택에 관련 | 경계 판단 방식·후보 선택 규칙 |
| 무음 건너뛰기·용어 사전 | 무음과 전문용어에 대한 보조 기능 | 발화 보존 여부·등록 방법·개선 정도 |

로컬 음성 처리는 앱 전체의 완전한 offline 동작 보장이 아니다. 18배·15배를 전체 처리 시간 단축률로 환산하거나 특정 모델의 실시간 동작 보장으로 사용할 수 없다. 내부 decoding 알고리즘과 모델 구성 역시 자료만으로 단정할 수 없다.

## 평가할 지표

- 최초 출력 지연: 입력 시작 또는 발화 시작부터 첫 텍스트가 보일 때까지. 실험에서 기준 시점을 고정한다.
- 최종 결과 도달 시간: 입력 종료부터 전체 결과가 준비될 때까지. 확정 신호가 없으면 관찰 기준을 명시한다.
- 한국어 품질: 누락·대치·전문용어·띄어쓰기 오류.
- 출력 안정성: 먼저 나온 텍스트의 수정 여부와 빈도.
- 자원 사용량: 메모리·CPU·전력 등 관찰 가능한 항목. 측정값은 자료에 없다.
