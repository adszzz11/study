# Projects: 내 조건에 맞는 전사 절차

## 1. 개인 받아쓰기용 모델 선택표

- 입력: 일상 문장, 전문용어 문장, 긴 발화의 녹음과 정답 전사문.
- 절차: 허용 오류·대기 시간을 먼저 정하고 같은 파일에서 모델만 변경한다. 후보를 마이크 환경에서도 확인한다.
- 결과물: Mac·앱 버전·설정·반복 측정값과 선택 이유가 포함된 표.
- 완료 기준: 선택 모델이 사전 조건을 충족하며, 충족하지 못하면 보류 이유를 기록한다.

| 모델 | 오류·전문용어 | 첫 출력 지연 | 전체 처리 시간 | 자원 관찰 | 조건 충족 |
|---|---|---|---|---|---|
| 실제 선택지 기록 | 실험 후 입력 | 실험 후 입력 | 실험 후 입력 | 실험 후 입력 | 판정 |

## 2. 기존 녹음 파일 전사 절차

1. 지원 파일 형식과 긴 파일 처리 가능 여부를 도입 전에 확인한다.
2. 파일로 초안을 만들고 중요 구간·고유명사·전문용어를 원음과 대조한다.
3. 반복 용어는 사전 적용 전후로 비교하고 검수 시간이 줄었는지 기록한다.
4. 초안·검수본과 수정 근거를 구분해 보관한다.

결과물은 파일 접수부터 검수 완료까지의 절차와 누락·오류 점검표다. API·일괄 처리 기능은 자료에 없으므로 자동화는 별도 확인 과제로 남긴다.

## 3. 실시간 출력 활용 가능성 평가

발화 중 텍스트를 읽고 다음 문장을 이어가는 시나리오를 구성한다. 최초 출력 지연, 수정으로 인한 혼란, 단어 경계의 읽기 편의성, 긴 발화의 누락을 기록한다.

결과물은 실시간 출력이 작업에 도움이 되는 조건과 확정 전 사용의 한계다. 다른 도구로 즉시 전달하려면 확정 상태와 인터페이스를 먼저 확인한다. 자료에 외부 연동 API나 확정 이벤트가 없으므로 연동 구현을 지원 기능으로 전제하지 않는다.
