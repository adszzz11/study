# 심화: 동일 입력으로 모델 크기 비교

## 실험 설계

동일한 녹음 파일과 정답 전사문을 준비한다. 마이크로 매번 새로 읽으면 발음·속도·소음이 바뀌므로 모델 비교에는 같은 파일을 쓰고, 실제 사용감은 이후 마이크에서 확인한다.

- 고정: Mac, 앱 버전, 입력 파일, 언어·사전·무음 설정, 출력 정책, 다른 작업 부하.
- 변경: 모델 크기 하나. 선택 가능한 모델 이름과 버전을 실제 UI에서 기록한다.
- 구분: 다운로드·모델 로딩 시간과 인식 시간을 분리한다. 반복 측정 횟수와 순서를 기록한다.
- 사전 기준: 허용 오류, 전문용어 보존 조건, 허용 첫 출력 지연·결과 대기·자원 범위를 정한다.

## 기록 양식

```text
Mac / 메모리 / 앱 버전:
파일 ID / 길이 / 언어 / 정답 전사문:
모델 / 버전 / 설정 / 실행 순번:
시작 이벤트 / 첫 출력 / 입력 종료 / 결과 준비 이벤트:
최초 출력 지연 / 전체 처리 시간 / 종료 후 대기:
누락 / 오인식 / 전문용어 / 띄어쓰기 오류:
부분 출력 수정 횟수 / 수정 관찰 방법:
관찰한 메모리·CPU 등 / 측정 도구:
확정 여부 / 미확인 항목:
```

전체 처리 시간은 처리 시작부터 결과 준비까지이고, 종료 후 대기는 입력 종료부터 결과 준비까지다. 파일에서 실제 입력 종료를 알 수 없다면 해당 값은 미측정으로 남긴다. 확정 이벤트가 없으면 “결과 준비”의 관찰 기준과 한계를 적는다.

## 품질과 안정성 해석

- 정답 전사문과 대조하여 오류 유형을 분리한다. 한국어 띄어쓰기 정규화 여부도 기록한다.
- 선택적으로 WER = (대치 + 삭제 + 삽입) / 정답 단어 수를 계산할 수 있다. 한국어에서는 단어 분할 규칙에 따라 값이 달라지므로 규칙을 고정한다.
- 단어 수정 횟수와 문장 갱신 횟수를 혼용하지 않는다. 같은 관찰 규칙으로 비교한다.
- 반복 결과의 범위를 함께 적는다. 측정하지 않은 메모리·전력·지연은 추정값으로 채우지 않는다.

## 보조 기능은 하나씩

| 실험 | 고정할 입력 | 관찰할 결과 |
|---|---|---|
| 용어 사전 전후 | 동일 전문용어 녹음 | 용어 오류·검수 부담의 변화 |
| 무음 건너뛰기 전후 | 무음 앞뒤 짧은 발화 | 처리 변화와 발화 누락 |
| 자동 언어 감지 | 한국어 단독 / 한영 혼합을 별도 구성 | 감지 결과·짧은 발화 품질 |

## 선택 기준

가장 큰 모델 대신 **미리 정한 조건을 충족하는 모델**을 선택한다. 후보 사이 차이가 작으면 반복 측정하고 실제 마이크 시나리오에서 재확인한다. 자료의 최대 18배·15배를 실험 결과 칸에 넣지 않는다.
