# Projects: 업무 자동화 평가 프로젝트

아래는 dossier의 작업 방식에서 도출한 설계 제안이다. 제품별 구현이나 외부 연동을 보장하지 않는다.

## 1. 개인 업무 요청함

Muse의 업무 범위를 참고해 예약·알림·양식 작성 요청을 목록으로 관리한다.

- **입력:** 요청 내용, 필요한 정보, 기한, 사용자 확인 시점.
- **산출물:** 요청별 기대 결과·누락 정보·상태가 있는 표.
- **완료 조건:** 모든 요청에 완료 근거 또는 대기·실패 이유가 있다.
- **평가:** 누락 입력 수, 추가 질문 수, 기한 내 처리 여부.

실제 서비스 연동 가능 여부와 실행 승인 절차는 별도 확인한다.

## 2. 조사·작성·검토 파이프라인

Hermes의 역할 구성을 참고해 자료 추출 → 초안 → 근거 검토로 나눈다.

- **입력:** 같은 원문과 산출물 요구사항.
- **산출물:** 근거 목록, 초안, 원문에 없는 주장 표시, 최종본.
- **완료 조건:** 요구사항을 충족하고 모든 주요 주장을 원문으로 추적할 수 있다.
- **평가:** 근거 없는 주장 수, 수정 항목 수, 요구사항 충족도.

## 3. 채팅 기반 비동기 작업 관리

OpenClaw의 요청 방식을 참고해 요청마다 ID와 상태를 부여한다.

- **입력:** 채팅 요청과 완료 조건, 추가 입력 답변.
- **산출물:** 작업별 상태 이력, 결과 또는 실패 원인.
- **완료 조건:** 입력 대기와 실패를 완료에서 구별하고 요청 ID로 조회할 수 있다.
- **평가:** 상태 확인 가능성, 중복 요청 식별, 실패 원인 추적 가능성.

이 상태 관리 기능이 OpenClaw에 구현돼 있다는 의미는 아니다.

## 4. 부서별 agent·모델 평가표

Grok Bot의 업무 역할과 SkillTree의 작업 공간을 참고해 역할별 입력·산출물·평가 기준을 정의한다.

| 역할 | 입력 | 산출물 | 평가 기준 |
|---|---|---|---|
| 리서치 | 동일 자료·질문 | 근거 목록 | 근거 추적성·누락 |
| 마케팅 | 동일 제품 정보·대상 | 문안 초안 | 요구사항 충족·사실 일치 |
| 운영 | 동일 요청 목록 | 처리 계획 | 누락·기한·완료 조건 |

같은 자료와 완료 조건으로 여러 모델을 평가하고 품질과 일관성을 기록한다. 모델 이름만으로 우열을 정하지 않는다.
