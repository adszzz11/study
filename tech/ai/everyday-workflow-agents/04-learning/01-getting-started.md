# 시작하기: 하나의 업무를 명세하기

## 실습 범위

제품 설치 안내가 아닌 작업 설계 연습이다. 도구 없이 Markdown으로 시작할 수 있으며 실제 예약·쇼핑 실행은 실습에 필요하지 않다.

## 1. Task와 Goal 나누기

| 구분 | 예 | 작성할 내용 |
|---|---|---|
| Task | 이번 주 일정 후보 정리 | 입력·산출물·완료 조건 |
| Goal | 장기 목표 관리 | 중간 작업·진행 확인 시점 |

## 2. 요청 작성하기

```yaml
id: task-001
request: 이번 주 회의 일정 후보 정리
input: 사용자가 제공한 가능 시간과 참석 조건
output: 조건에 맞는 후보 3개와 제외 사유
completion: 모든 필수 조건 확인, 누락 정보 표시, 결과 검토 가능
check_in: 입력 누락 또는 조건 충돌 시 사용자에게 질문
```

이는 특정 제품의 API schema가 아닌 학습용 양식이다. 정보가 없으면 추정 대신 추가 질문을 기록한다.

## 3. 완료 판정하기

- [ ] 필수 조건을 빠짐없이 확인했다.
- [ ] 후보와 제외 사유를 사용자가 검토할 수 있다.
- [ ] 미해결 입력이 있으면 완료로 표시하지 않았다.
- [ ] 후보 정리와 실제 예약 실행을 구분했다.

## 4. 기록 남기기

누락 입력 수, 추가 질문 수, 기한 내 처리 여부를 기록한다. Goal은 이 Task 뒤에 이어질 작업과 다음 확인 시점을 추가한다. 목표 자동 분해 기능을 가정하지 않는다.
